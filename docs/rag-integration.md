**Role:** Member 2 – RAG Engineer

**Vector Store:** ChromaDB (`programming_knowledge` collection)

## 1. System Overview & Architecture

The RAG (Retrieval-Augmented Generation) subsystem provides curriculum-grounded educational retrieval for C, C++, Java, and Python. Rather than relying solely on parametric LLM knowledge, it retrieves exact pedagogical explanations, code snippets, memory layouts, debugging patterns, and common mistakes to ground explanations generated by Member 3's Gemini engine.

### End-to-End Pipeline

```
[ Educational Documents (32 docs across C, CPP, Java, Python) ]
                     │
                     ▼
          [ Document Loader ]  (Extracts COURSE, TOPIC, LEVEL, SOURCE)
                     │
                     ▼
       [ Code-Aware Semantic Chunker ] (900 chars target, 180 overlap)
                     │
                     ▼
      [ SentenceTransformer Singleton ] (all-MiniLM-L6-v2, 384-dim)
                     │
                     ▼
        [ ChromaDB Persistent Store ] (rag/chroma_db/, cosine metric)
                     │
       ┌─────────────┴─────────────┐
       │                           │
       ▼                           ▼
[ Semantic Query ]     [ Multi-Attribute Metadata Filter ]
(Dense Embedding)      (Course, Topic Slug, Level, Learner Level)
       │                           │
       └─────────────┬─────────────┘
                     │
                     ▼
         [ Top-K Document Chunks ]
                     │
                     ▼
         [ Context Formatter ] ──► Formatted Context Block
                     │
                     ▼
  [ Backend LLM Service / Gemini ] ──► Grounded Student Response
```

## 3. Retrieval API & Interfaces

### 3.1 Python API: `retrieve_context()`

The primary high-level interface exported by `rag.src.retriever` and `rag.src`:

```python
from rag.src.retriever import retrieve_context

result = retrieve_context(
    query="How does malloc and free work in C?",
    language="C",
    difficulty="beginner",
    top_k=3
)
```

FastAPI endpoints access the RAG system through `rag_service`:

```python

# Retrieve raw chunks
chunks = rag_service.retrieve(
    query=question,
```

## 4. FastAPI Endpoints & Downstream AI Integration

The following existing backend endpoints integrate RAG context:

### 1. `POST /api/ai/ask`
* **Route Handler:** `backend/routes/ai_routes.py` -> `ask_ai_assistant()`
* **Downstream Service:** `backend/services/llm_service.py` -> `generate_explanation()`
* **RAG Step:** 
  1. Detects language from payload (`course`, `language`, `topic_id`).
  2. Resolves curriculum topic ID (e.g. `top-py-fundamentals` -> `fundamentals`).
  3. Queries ChromaDB for the top-$k$ relevant chunks.
  4. Formats context with `format_context()`.
  5. Injects context and student's cognitive load level into Gemini prompt.

### 2. `POST /api/ai/hint`
* **Route Handler:** `backend/routes/ai_routes.py` -> `request_progressive_hint()`
* **Downstream Service:** `backend/services/llm_service.py` -> `generate_hint()`
* **RAG Step:** Retrieves concise syntactic and conceptual chunks matching the student's current code challenge to formulate scaffolded progressive hints.

### 3. `GET /health`
* Returns status of all platform subsystems:
  ```json
  {
    "status": "healthy",
    "modules": {
      "cognitive_engine": "active",
      "ml_classifier": "active",
      "rag_chromadb": "active",
      "gemini_llm": "active"
    }
  }
  ```

## 5. Error Handling & Fallback Strategy

The RAG retriever distinguishes four explicit execution states via `retrieve_with_status()`:

| Status Code | Cause | Fallback Behavior |
| :--- | :--- | :--- |
| `SUCCESS` | Normal query execution with matching chunks. | Returns top-$k$ chunks ranked by similarity. |
| `EMPTY_RESULT` | Query contains no semantic overlap or empty string. | Returns empty list gracefully; LLM falls back to standard adaptive tutor mode. |
| `EMBEDDING_UNAVAILABLE` | PyTorch or sentence-transformer model missing/offline. | Logs warning, returns `{success: False, error: ...}`; backend continues without RAG rather than crashing. |
| `QUERY_ERROR` | ChromaDB collection lock or corrupted query. | Returns error details and fallback message. |

Run all commands from the repository root:
