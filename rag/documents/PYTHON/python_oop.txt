TITLE: Deep Python Object-Oriented Programming, Metaclasses, Magic Methods, and Inheritance MRO

1. Introduction
Object-Oriented Programming (OOP) in Python provides an expressive, highly flexible paradigm for modeling complex software domains, structuring stateful abstractions, and managing inheritance relationships. Python's object model is fundamentally dynamic: classes are themselves first-class objects (instances of `type`), attributes are stored in dynamic dictionaries (`__dict__`), and method resolution across complex multi-inheritance graphs is resolved deterministically via C3 Linearization (Method Resolution Order, MRO). Understanding classes, instance vs class attributes, classmethods, staticmethods, properties (`@property`), magic methods (dunder methods), operator overloading, and composition is essential for advanced Python systems engineering.

4. Core Concepts
- Class as Object: In Python, classes are runtime objects created by the default metaclass `type`.
- Dunder (Double Underscore) Methods: Special hook methods defined by the Python data model that allow user classes to integrate with built-in language operators.
- C3 Linearization: The deterministic algorithm Python uses to compute the Method Resolution Order (MRO) for multiple inheritance hierarchies.
- Property Decorator (`@property`): Syntactic abstraction allowing methods to be accessed like attributes while executing validation logic behind the scenes.
- Duck Typing: "If it walks like a duck and quacks like a duck, it's a duck." Python inspects object capabilities at runtime rather than enforcing rigid nominal type hierarchies.

5. Detailed Theory
5.1 Instance vs Class Attributes and Namespaces
- Instance Attributes: Stored in the instance's unique `self.__dict__`. Unique to each object.
- Class Attributes: Stored in `Class.__dict__`. Shared by ALL instances of the class.
- Attribute Lookup Order: Python first searches the instance's `__dict__`; if not found, it searches the class's `__dict__`, then searches up the inheritance tree via MRO.

5.2 Methods: Instance, Class, and Static
1. Instance Method: Takes `self` as the first argument. Can access and mutate both instance and class state.
2. Class Method (`@classmethod`): Takes `cls` as the first argument. Can access and mutate class-level state. Commonly used for alternative constructor factories.
3. Static Method (`@staticmethod`): Does not receive `self` or `cls`. Pure utility function grouped logically inside the class namespace.

5.3 Multiple Inheritance and Method Resolution Order (MRO)
When resolving `super()` calls and inherited methods across multiple parent classes:
- Python uses C3 Linearization to produce a linear, monotonic inheritance chain without duplicate evaluations.
- `super()` does not simply call the parent class; it calls the *next class in the MRO chain* of the calling instance.
- Inspect MRO at runtime: `print(MyClass.__mro__)` or `MyClass.mro()`.

5.4 Magic Dunder Methods (The Python Data Model)
- Representation: `__repr__(self)` (unambiguous developer representation) vs `__str__(self)` (user-friendly string).
- Arithmetic Operators: `__add__`, `__sub__`, `__mul__`, `__truediv__`.
- Comparison Operators: `__eq__`, `__lt__`, `__le__`, `__gt__`, `__ge__`.
- Container Protocol: `__len__`, `__getitem__`, `__setitem__`, `__delitem__`, `__contains__`.
- Context Managers: `__enter__`, `__exit__`.

7. Basic Examples (Beginner Level)
```python
class BankAccount:
    bank_name = "Apex Financial" # Class attribute

    def __init__(self, account_holder: str, initial_deposit: float = 0.0):
        self.account_holder = account_holder # Instance attribute
        self._balance = max(0.0, initial_deposit)

    def deposit(self, amount: float):
        if amount > 0:
            self._balance += amount
            print(f"Deposited ${amount:.2f}. New Balance: ${self._balance:.2f}")

    def withdraw(self, amount: float) -> bool:
        if 0 < amount <= self._balance:
            self._balance -= amount
            print(f"Withdrew ${amount:.2f}. Remaining: ${self._balance:.2f}")
            return True
        print(f"Withdrawal of ${amount:.2f} failed: Insufficient funds.")
        return False

    def get_balance(self) -> float:
        return self._balance

# Instantiate objects
acc1 = BankAccount("Alice", 500.0)
acc2 = BankAccount("Bob", 100.0)

print(f"Account 1 ({acc1.account_holder}): ${acc1.get_balance():.2f}")
acc1.deposit(150.0)
acc1.withdraw(700.0)
print(f"Both accounts belong to bank: {BankAccount.bank_name}")
```
Expected Output:
```
Account 1 (Alice): $500.00
Deposited $150.00. New Balance: $650.00
Withdrawal of $700.00 failed: Insufficient funds.
Both accounts belong to bank: Apex Financial
```

8. Intermediate Examples (Properties, Classmethods, and Encapsulation)
```python
class Temperature:
    def __init__(self, celsius: float = 0.0):
        self._celsius = celsius

    # Property Getter
    @property
    def celsius(self) -> float:
        return self._celsius

    # Property Setter with Validation
    @celsius.setter
    def celsius(self, value: float):
        if value < -273.15:
            raise ValueError("Temperature cannot fall below absolute zero (-273.15°C)!")
        self._celsius = value

    @property
    def fahrenheit(self) -> float:
        return (self._celsius * 9 / 5) + 32

    # Alternative Constructor Factory
    @classmethod
    def from_fahrenheit(cls, f_value: float):
        c_value = (f_value - 32) * 5 / 9
        return cls(c_value)

    # Static Utility Method
    @staticmethod
    def is_freezing(c_value: float) -> bool:
        return c_value <= 0.0

temp1 = Temperature(25.0)
print(f"Temp: {temp1.celsius:.1f}°C -> {temp1.fahrenheit:.1f}°F")

temp2 = Temperature.from_fahrenheit(98.6)
print(f"Body Temp from Fahrenheit: {temp2.celsius:.1f}°C")
print(f"Is 0°C freezing? {Temperature.is_freezing(0.0)}")
```
Expected Output:
```
Temp: 25.0°C -> 77.0°F
Body Temp from Fahrenheit: 37.0°C
Is 0°C freezing? True
```

9. Advanced Examples (Magic Methods Operator Overloading and Multiple Inheritance MRO)
```python
class Vector2D:
    def __init__(self, x: float, y: float):
        self.x = float(x)
        self.y = float(y)

    def __repr__(self) -> str:
        return f"Vector2D({self.x}, {self.y})"

    def __str__(self) -> str:
        return f"({self.x}, {self.y})"

    def __add__(self, other: 'Vector2D') -> 'Vector2D':
        if not isinstance(other, Vector2D):
            return NotImplemented
        return Vector2D(self.x + other.x, self.y + other.y)

    def __mul__(self, scalar: float) -> 'Vector2D':
        return Vector2D(self.x * scalar, self.y * scalar)

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, Vector2D):
            return False
        return self.x == other.x and self.y == other.y

    def __abs__(self) -> float:
        return (self.x**2 + self.y**2) ** 0.5

# Multiple Inheritance Hierarchy (Diamond Pattern)
class BaseService:
    def execute(self):
        print("BaseService: core execution logic")

class LoggingService(BaseService):
    def execute(self):
        print("[LOG] Starting execution...")
        super().execute()
        print("[LOG] Execution completed.")

class AuthValidationService(BaseService):
    def execute(self):
        print("[AUTH] User authentication verified.")
        super().execute()

class ApplicationService(LoggingService, AuthValidationService):
    def execute(self):
        print("=== Application Gateway Invocation ===")
        super().execute()

print("--- Vector2D Operator Overloading ---")
v1 = Vector2D(3, 4)
v2 = Vector2D(1, 2)
v3 = v1 + v2
print(f"v1 + v2 = {v3}")
print(f"v1 * 3  = {v1 * 3}")
print(f"Magnitude |v1| = {abs(v1)}")

print("\n--- Multiple Inheritance MRO Inspection ---")
app = ApplicationService()
app.execute()
print(f"\nMRO Chain: {[cls.__name__ for cls in ApplicationService.mro()]}")
```
Expected Output:
```
--- Vector2D Operator Overloading ---
v1 + v2 = (4.0, 6.0)
v1 * 3  = (9.0, 12.0)
Magnitude |v1| = 5.0

--- Multiple Inheritance MRO Inspection ---
=== Application Gateway Invocation ===
[LOG] Starting execution...
[AUTH] User authentication verified.
BaseService: core execution logic
[LOG] Execution completed.

MRO Chain: ['ApplicationService', 'LoggingService', 'AuthValidationService', 'BaseService', 'object']
```

10. Line-by-Line Code Explanation
- `def __add__(self, other)`: Implements operator overloading for the `+` operator. If `other` is not a `Vector2D`, returning `NotImplemented` allows Python to try `other.__radd__(self)`.
- `super().execute()`: Traverses the next class in the C3 Linearization MRO chain. In `ApplicationService`, `super()` in `LoggingService` dispatches to `AuthValidationService`, ensuring cooperative multiple inheritance without duplicate execution.

11. Practical Programming Problems
Problem 1: Custom Collection Class with Sequence Protocol
Implement a custom `Polynomial` class supporting indexing, length, addition, and evaluation.
```python
class Polynomial:
    def __init__(self, *coefficients: float):
        # Stored in ascending order of degree: c0 + c1*x + c2*x^2
        self.coeffs = list(coefficients)

    def __repr__(self) -> str:
        terms = [f"{c}x^{i}" for i, c in enumerate(self.coeffs) if c != 0]
        return " + ".join(terms) if terms else "0"

    def __len__(self) -> int:
        return len(self.coeffs)

    def __getitem__(self, degree: int) -> float:
        return self.coeffs[degree] if degree < len(self.coeffs) else 0.0

    def evaluate(self, x: float) -> float:
        return sum(c * (x**i) for i, c in enumerate(self.coeffs))

p = Polynomial(3, 2, 5) # 3 + 2x + 5x^2
print(f"Polynomial: {p}")
print(f"Degree 2 coefficient: {p[2]}")
print(f"Evaluate at x=2: {p.evaluate(2)}")
```
Complexity: Time $O(N)$ evaluation, Space $O(N)$.

13. Common Mistakes
- Mutating Class Attributes via Instances: Writing `self.class_attr = 5` creates an instance attribute shadowing the class attribute rather than modifying the shared class variable.
- Calling `super().__init__()` with Mismatched Signatures in Multiple Inheritance: Breaks cooperative MRO chains.
- Missing `self` in Method Signatures: Raises `TypeError: method() takes 0 positional arguments but 1 was given`.

15. Debugging Techniques
- Inspect Instance Dictionaries: `print(obj.__dict__)` to inspect all currently bound instance attributes.
- Inspect Class Hierarchy: `print(Class.mro())` to diagnose method dispatch ordering issues.

16. Edge Cases
- Name Mangling: Attributes prefixed with double underscores (`__secret`) are renamed internally to `_ClassName__secret` to prevent accidental subclass shadowing.
- `__slots__` Optimization: Declaring `__slots__ = ('name', 'age')` suppresses the creation of `__dict__`, saving significant memory across millions of small instances.

17. Best Practices
- Use `@property` for getters and setters instead of writing Java-style `get_x()`/`set_x()` methods.
- Follow the Rule of Single Responsibility for classes.
- Prefer composition over inheritance when behavior can be delegated.

18. Performance Considerations
- Memory Savings with `__slots__`: Eliminates dynamic `__dict__` dictionary overhead, slashing memory consumption by 40% to 60% in large-scale object pools.

19. Security Considerations
- Arbitrary Attribute Injection: Python allows adding attributes dynamically at runtime. Use `__slots__` or `@dataclass(frozen=True)` to enforce strict schemas.

20. Memory Considerations
- Circular References in Objects: Instances referencing each other with backpointers require cyclic garbage collection for cleanup.

21. Comparison with Related Concepts
- `__repr__` vs `__str__`: `__repr__` is for developers (unambiguous, matches code syntax); `__str__` is for end users (readable format).
- `@classmethod` vs `@staticmethod`: `@classmethod` receives the class object `cls`; `@staticmethod` receives no implicit first argument.

22. Frequently Asked Questions
Q: What is the purpose of `__init__` vs `__new__`?
A: `__new__` is the actual constructor that allocates and returns the new object instance; `__init__` is the initializer that receives the newly created instance and sets up attributes.

Q: How does private encapsulation work in Python?
A: Python uses naming conventions. A single underscore `_var` indicates protected/internal use by convention. A double underscore `__var` triggers name mangling to prevent subclass collisions.

23. Interview Questions
Beginner:
Q: What is the purpose of the `self` parameter in Python class methods?
A: `self` represents the instance of the class on which the method is called, allowing explicit access to instance attributes and other methods.

Intermediate:
Q: Explain the difference between `@classmethod` and `@staticmethod`.
A: `@classmethod` receives the class object `cls` as its first parameter and can modify class-level state or serve as an alternative constructor. `@staticmethod` receives no implicit first parameter (`self` or `cls`) and acts as a plain function placed inside the class namespace.

Advanced:
Q: What is Method Resolution Order (MRO) and how does C3 Linearization resolve multiple inheritance?
A: MRO is the order in which Python searches parent classes for attributes and methods. C3 Linearization guarantees two properties: 1) Children precede their parents, and 2) The relative order of parent classes listed in class definitions is preserved across the entire hierarchy, avoiding duplicate lookups and resolving diamond patterns monotonically.
