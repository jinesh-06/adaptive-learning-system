1. Introduction
Data structures form the architectural core of algorithmic computing, determining how data is organized, accessed, manipulated, and stored in memory. Python provides a rich, expressive set of built-in data structures (`list`, `tuple`, `set`, `dict`) complemented by the high-performance `collections` module (`deque`, `Counter`, `defaultdict`, `namedtuple`, `OrderedDict`). In CPython, each data structure is implemented in optimized C code with distinct memory footprints, resizing heuristics, hash collision resolutions, and asymptotic time complexities. A thorough mastery of internal memory representations, mutability rules, indexing, slicing, comprehensions, shallow vs deep copying, and container selection is critical for writing high-performance, memory-efficient Python software.

3. Prerequisites
- Proficiency in Python fundamentals, control flow, functions, and object references.

4. Core Concepts
- Dynamic Array (`list`): Contiguous array of pointers to `PyObject` items with geometric over-allocation. $O(1)$ random indexing and append.
- Immutable Sequence (`tuple`): Fixed-size sequence of object references. Memory-compact and hashable if all elements are hashable.
- Hash Table (`set` and `dict`): Data structures mapping keys to buckets using `hash(key)`. Provides average $O(1)$ lookup, insertion, and deletion.
- Mutability vs Immutability: Mutable objects (`list`, `set`, `dict`) can be modified in-place; Immutable objects (`tuple`, `str`, `frozenset`) cannot be altered after instantiation.
- Hashability: An object is hashable if it has an immutable hash value across its lifetime (`__hash__`) and can be compared for equality (`__eq__`). Only hashable objects can be set elements or dictionary keys.

5. Detailed Theory
5.1 Deep Dive: Lists and Dynamic Array Memory Architecture
In CPython, a `list` is a `PyListObject` structure containing:
- `ob_refcnt`: Reference count.
- `ob_size`: Current number of items in the list.
- `ob_items`: A contiguous C array of pointers (`PyObject**`) allocated on the heap.
- `allocated`: Total memory capacity currently allocated.

Growth Factor & Over-Allocation:
When appending to a list that is full, CPython reallocates the pointer array with geometric headroom:
$$\text{New Allocated} = \text{new\_size} + (\text{new\_size} \gg 3) + (\text{new\_size} < 9 \ ? \ 3 : 6)$$
This over-allocation amortizes the cost of `list.append()`, achieving $O(1)$ amortized time complexity despite occasional $O(N)$ reallocations.

List Methods & Operations:
- Creation: `lst = [1, 2, 3]`, `list(iterable)`
- Indexing: Positive `lst[0]`, Negative `lst[-1]` (translates to `len(lst) - 1`).
- Slicing: `lst[start:stop:step]` returns a new list containing shallow copies of pointers.
- Appending & Extending: `lst.append(x)` (adds 1 element), `lst.extend(iterable)` (unpacks and adds all elements).
- Insertion & Removal: `lst.insert(idx, x)` ($O(N)$ shift), `lst.remove(x)` ($O(N)$ search and shift), `lst.pop(idx)` ($O(1)$ at end, $O(N)$ at start), `lst.clear()`.
- Sorting: `lst.sort()` (in-place Timsort algorithm, $O(N \log N)$), `sorted(lst)` (returns new sorted list).

5.2 Deep Dive: Tuples and Packing/Unpacking
A `tuple` (`PyTupleObject`) is an immutable sequence:
- Memory efficiency: Tuples avoid the `allocated` capacity field of lists and allocate exact memory size.
- Sequence Unpacking: `a, b, *rest = (1, 2, 3, 4, 5)` -> `a = 1`, `b = 2`, `rest = [3, 4, 5]`.
- Immutability Caveat: A tuple is immutable, but if it contains a mutable element (e.g., `t = ([1, 2], 3)`), the internal list CAN be mutated in-place (`t[0].append(99)`). However, `t` cannot be used as a dictionary key because it contains an unhashable element.

5.3 Deep Dive: Sets and Mathematical Set Theory
A `set` (`PySetObject`) is an open-addressing hash table storing only unique keys:
- Uniqueness: Duplicates are discarded automatically during insertion.
- Hash Collision Resolution: Uses open addressing with quadratic probing perturbation:
  $$j = ((5 \times j) + 1 + \text{perturb}) \pmod{\text{size}}$$
- Set Operations:
  - Union: `A | B` or `A.union(B)`
  - Intersection: `A & B` or `A.intersection(B)`
  - Difference: `A - B` or `A.difference(B)`
  - Symmetric Difference: `A ^ B` or `A.symmetric_difference(B)`
  - Subset / Superset: `A <= B`, `A >= B`
- `frozenset`: An immutable, hashable variant of `set` suitable for dictionary keys or nested set members.

5.4 Deep Dive: Dictionaries (Python 3.6+ Compact Hash Table)
Since Python 3.6+, CPython uses a compact, ordered dictionary architecture:
1. Indices Array (Sparse Table): An array storing hash table indices (e.g., `[-1, 0, -1, 1]`).
2. Entries Array (Dense Table): A contiguous array storing `[hash, key_ptr, value_ptr]` in insertion order.
Benefits:
- Consumes 20% to 25% less RAM than legacy hash tables.
- Guarantees deterministic iteration in insertion order.
Dict Operations: `dict.get(key, default)`, `dict.keys()`, `dict.values()`, `dict.items()`, `dict.update()`, `dict.pop(key)`.

5.5 Specialized Containers (`collections` Module)
1. `collections.deque`: Double-ended queue implemented as a doubly-linked list of 64-element array blocks. $O(1)$ push and pop from BOTH ends (`append`, `appendleft`, `pop`, `popleft`).
2. `collections.Counter`: Dictionary subclass designed for multiset frequency counting (`most_common(k)`).
3. `collections.defaultdict`: Dictionary returning a default factory value when querying missing keys without raising `KeyError`.
4. `collections.namedtuple`: Factory generating tuple subclasses with named fields accessible via attribute lookup (`point.x`).

5.6 Shallow Copy vs Deep Copy
- Shallow Copy (`copy.copy(x)` or `x[:]`): Creates a new container, but populates it with references to the exact same child objects.
- Deep Copy (`copy.deepcopy(x)`): Recursively duplicates the container AND all nested child objects, allocating completely independent memory structures.

6. Syntax
- List Comprehension: `[expr for item in iterable if condition]`
- Dict Comprehension: `{k_expr: v_expr for item in iterable if condition}`
- Set Comprehension: `{expr for item in iterable if condition}`
- Deque Creation: `dq = collections.deque(maxlen=10)`
- Defaultdict: `d = collections.defaultdict(list)`

9. Advanced Examples (Deque Sliding Window, Counter Frequency Analysis, and Deep Copy Analysis)
```python
import collections
import copy

# 1. collections.deque as Fast Sliding Window Buffer
sliding_window = collections.deque(maxlen=3) # Fixed maximum capacity
sensor_stream = [10.2, 10.5, 10.8, 11.2, 11.0, 10.9]

print("--- Deque Sliding Window ---")
for reading in sensor_stream:
    sliding_window.append(reading) # Automatically drops oldest item on overflow
    avg = sum(sliding_window) / len(sliding_window)
    print(f"Window: {list(sliding_window)} -> Moving Average: {avg:.2f}")

# 2. collections.Counter for NLP Term Frequency
paragraph = "python is fast python is expressive and python data structures are powerful"
word_counts = collections.Counter(paragraph.split())
print("\n--- Counter Frequency Analysis ---")
print(f"Top 2 most common words: {word_counts.most_common(2)}")
print(f"Frequency of 'python': {word_counts['python']}")

# 3. Shallow Copy vs Deep Copy Demonstration
original = [[1, 2, 3], ["A", "B"]]
shallow = copy.copy(original)
deep = copy.deepcopy(original)

original[0].append(999) # Mutate child list

print("\n--- Copy Verification ---")
print(f"Original: {original}")
print(f"Shallow (Mutated!): {shallow}")
print(f"Deep (Isolated!):   {deep}")
```
Expected Output:
```

Window: [10.2, 10.5] -> Moving Average: 10.35
```

10. Line-by-Line Code Explanation
- `sliding_window = collections.deque(maxlen=3)`: Allocates a ring-buffer deque. When items exceed `maxlen`, elements at the left end (`popleft`) are dropped in $O(1)$ time with zero memory movement.
- `word_counts = collections.Counter(paragraph.split())`: Efficiently counts token frequencies in $O(N)$ time and provides $O(K \log N)$ heap-based top element extraction via `most_common(k)`.
- `copy.deepcopy(original)`: Traverses the object graph, maintaining a memo dictionary of visited objects to clone nested child structures independently without sharing pointers.

11. Practical Programming Problems
Problem 1: Group Anagrams
Given a list of strings, group all anagrams together in $O(N \cdot K \log K)$ time using a dictionary.
```python
import collections

def group_anagrams(strs: list[str]) -> list[list[str]]:
    anagram_map = collections.defaultdict(list)
    for s in strs:
        # Sorted character tuple serves as canonical hashable key
        sorted_key = "".join(sorted(s))
        anagram_map[sorted_key].append(s)
    return list(anagram_map.values())

input_words = ["eat", "tea", "tan", "ate", "nat", "bat"]
print("Grouped Anagrams:")
for group in group_anagrams(input_words):
    print(f"  {group}")
```
Complexity: Time $O(N \cdot K \log K)$ where $N$ is word count and $K$ is max word length, Space $O(N \cdot K)$.

12. Real-World Applications
- In-Memory Caches (LRU Cache): Combining `collections.OrderedDict` or `dict` + doubly-linked list for $O(1)$ cache lookups and eviction.
- Search Engine Indexing: Inverted indices mapping search tokens to document sets using `defaultdict(set)`.
- Graph Algorithms: Adjacency list representations using `defaultdict(list)`.

13. Common Mistakes
- Using a List as a Queue: Calling `list.pop(0)` or `list.insert(0, val)` takes $O(N)$ time because all subsequent elements must be shifted in memory. Always use `collections.deque` ($O(1)$).
- Modifying a Dictionary While Iterating Over It: Raises `RuntimeError: dictionary changed size during iteration`. Iterate over `list(d.keys())` or use a dict comprehension.
- Unhashable Dictionary Keys: Attempting to use a `list` or `set` as a dictionary key raises `TypeError: unhashable type`. Use `tuple` or `frozenset`.

15. Debugging Techniques

16. Edge Cases
- Key Comparison in Sets/Dicts: Python checks both `hash(a) == hash(b)` AND `a == b`. E.g., `1` and `True` have the exact same hash ($1$) and compare equal (`1 == True`), so `{1, True}` stores only ONE element (`{1}`).
- Slicing Beyond Array Length: `lst[0:1000]` on a list of 5 elements does NOT raise an `IndexError`; it safely returns all 5 elements.

17. Best Practices
- Use `set` for membership testing (`x in my_set` runs in $O(1)$ time vs $O(N)$ for lists).
- Use `collections.deque` for FIFO queue operations.
- Use `dict.get(key, default)` to avoid `KeyError` exceptions when querying optional fields.

18. Performance Considerations
- Lookups in Sets/Dicts vs Lists:
  - Checking `item in my_list`: $O(N)$ linear scan.
  - Checking `item in my_set`: $O(1)$ average hash table lookup (up to $10,000\times$ faster on large collections).

19. Security Considerations
- Hash Collision Denial of Service: Python applies a randomized hash seed (SIPHASH-24) at startup to prevent attackers from crafting adversarial strings that collapse dictionary lookups into $O(N)$ linked list scans.

20. Memory Considerations
- Memory Pre-allocation: Lists over-allocate capacity. If memory is tight after constructing a large list, use `sys.intern` for strings or convert static collections to `tuple`.

21. Comparison with Related Concepts
- `list` vs `tuple`: Lists are mutable dynamic arrays ($O(1)$ append, higher memory overhead); Tuples are immutable, fixed-size ($O(1)$ creation, lower memory, hashable).
- `dict` vs `defaultdict`: `dict` raises `KeyError` on missing keys; `defaultdict` automatically invokes a factory function to insert a default value.

22. Frequently Asked Questions
Q: Why is `item in my_set` faster than `item in my_list`?
A: Sets compute the hash of `item` to inspect its hash bucket directly in $O(1)$ average time, whereas lists perform a linear scan comparing elements sequentially in $O(N)$ time.

Q: How does Python maintain dictionary insertion order?
A: Since Python 3.6+, CPython separates dictionary storage into a sparse indices table and a dense entries table. Elements are appended to the dense entries table sequentially, preserving insertion order naturally.

23. Interview Questions
Beginner:
Q: What is the difference between `list.sort()` and `sorted(list)`?
A: `list.sort()` mutates the list in-place and returns `None`; `sorted(list)` returns a brand-new sorted list while leaving the original input unchanged.

Intermediate:
Q: Why can a tuple containing a list NOT be used as a dictionary key?
A: A dictionary key must be hashable, meaning its hash value must never change over its lifetime. Because a nested list is mutable, its contents (and potential hash) could change, so Python declares any tuple containing a mutable object unhashable (`TypeError: unhashable type: 'list'`).

Advanced:
Q: Explain how CPython implements dynamic array resizing for lists.
A: CPython uses geometric over-allocation. When appending to a full list, CPython calculates a new capacity using the formula `new_allocated = new_size + (new_size >> 3) + (new_size < 9 ? 3 : 6)`. It reallocates the contiguous pointer array on the heap and copies existing pointers, ensuring amortized $O(1)$ append time.
