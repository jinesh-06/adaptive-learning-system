TITLE: C Functions: Declarations, Prototypes, Parameter Passing, Recursion, and Storage Classes

1. Introduction
Functions are self-contained modular blocks of code designed to perform specific computational tasks, promote code reusability, improve maintainability, and enforce structured procedural programming. In C, execution begins at `main()`, which coordinates program logic by calling standard library and user-defined functions. Understanding function call semantics, activation frames (stack frames), call-by-value mechanisms, pointer passing, recursion, variable scopes, and storage classes (`auto`, `register`, `static`, `extern`) is essential for building modular, memory-efficient C applications.

2. Learning Objectives
By studying this module, learners will:
- Formulate function definitions, declarations (prototypes), and invocations correctly.
- Understand the function call stack, activation records, and call overhead.
- Differentiate between call-by-value and simulated call-by-reference using pointers.
- Pass one-dimensional and multi-dimensional arrays to functions safely.
- Implement and analyze direct and indirect recursive functions with correct base cases.
- Master variable scope (block, file, function) and lifetime (automatic, static).
- Apply C storage class specifiers (`auto`, `register`, `static`, `extern`).
- Declare, initialize, and invoke function pointers for callback architectures.

3. Core Concepts
- Function Prototype: Informs compiler of function name, return type, and parameter types before its definition.
- Call Stack & Stack Frames: Memory region storing return addresses, parameters, and local variables during execution.
- Call by Value: C strictly passes arguments by value; the callee receives a distinct copy of each parameter.
- Pass by Address: Passing pointer values allows callee to dereference and modify caller variables in place.
- Storage Classes: Determine the scope, visibility, and lifetime of variables and functions.
- Function Pointers: Variables holding the memory address of executable function code.

4. Detailed Explanation
4.1 Function Declaration vs Definition
- Declaration (Prototype): `return_type function_name(type1 param1, type2 param2);` enables the compiler to perform argument type checking.
- Definition: Contains the actual implementation block.

4.2 Parameter Passing Mechanics
- Primitive values: Passed by value (copied onto stack). Modifications inside callee do not alter original variables in the caller.
- Pointers: Pointer address is passed by value. Dereferencing the pointer allows modification of the target memory location.
- Arrays: Arrays decay to pointers to their first element when passed into functions (`int arr[]` decays to `int *arr`). The array size must be passed as a separate parameter.

4.3 Recursion and Base Cases
A function is recursive when it calls itself directly or indirectly. Every recursive function requires:
1. One or more Base Cases: Non-recursive termination conditions that return directly.
2. Recursive Step: Reduces problem size toward the base case.
Failure to reach a base case results in unbounded stack growth, triggering a Stack Overflow.

4.4 Storage Classes in C
- `auto`: Default for local variables. Stored on stack; lifetime is limited to block scope.
- `register`: Requests CPU register storage for high-frequency access (cannot take address with `&`).
- `static`:
  - Inside function: Retains value across function calls; initialized once in data segment.
  - At file scope: Restricts visibility/linkage strictly to the current translation unit (.c file).
- `extern`: Declares a global variable or function defined in another source file or translation unit.

4.5 Function Pointers
Syntax: `return_type (*func_ptr_name)(param_types);`
Enables dynamic dispatch, table-driven methods, and customizable callback handlers.

5. Syntax
5.1 Function Declaration and Definition
/* Prototype */
int compute_sum(int a, int b);

/* Definition */
int compute_sum(int a, int b) {
    return a + b;
}

5.2 Function Pointer Syntax
int (*operation)(int, int) = compute_sum;
int result = operation(10, 20);

6. Basic Examples
Example 6.1: Basic Function with Call by Value
#include <stdio.h>

int multiply(int x, int y) {
    return x * y;
}

int main(void) {
    int a = 6, b = 7;
    int product = multiply(a, b);
    printf("Product of %d and %d is %d\n", a, b, product);
    return 0;
}

Example 6.2: Simulating Call by Reference using Pointers (Swap Function)
#include <stdio.h>

void swap(int *p1, int *p2) {
    int temp = *p1;
    *p1 = *p2;
    *p2 = temp;
}

int main(void) {
    int x = 100, y = 200;
    printf("Before swap: x = %d, y = %d\n", x, y);
    swap(&x, &y);
    printf("After swap:  x = %d, y = %d\n", x, y);
    return 0;
}

7. Intermediate Examples
Example 7.1: Static Local Variable Preserving State Across Calls
#include <stdio.h>

void generate_id(void) {
    static int counter = 1000; // Initialized only once
    counter++;
    printf("Assigned Transaction ID: %d\n", counter);
}

int main(void) {
    generate_id(); // 1001
    generate_id(); // 1002
    generate_id(); // 1003
    return 0;
}

Example 7.2: Array Passing and Linear Search
#include <stdio.h>

int linear_search(const int arr[], int size, int target) {
    for (int i = 0; i < size; i++) {
        if (arr[i] == target) {
            return i; // Target index found
        }
    }
    return -1; // Not found
}

int main(void) {
    int scores[] = {88, 92, 79, 95, 84};
    int n = sizeof(scores) / sizeof(scores[0]);
    int target = 95;
    int index = linear_search(scores, n, target);
    if (index != -1) {
        printf("Element %d found at index %d.\n", target, index);
    } else {
        printf("Element not found.\n");
    }
    return 0;
}

8. Advanced Examples
Example 8.1: Function Pointers for Strategy / Callback Pattern
#include <stdio.h>

int add(int a, int b) { return a + b; }
int subtract(int a, int b) { return a - b; }
int multiply_op(int a, int b) { return a * b; }

// Higher-order function accepting a function pointer
void execute_calculator(int (*calc)(int, int), int x, int y, const char *op_name) {
    int result = calc(x, y);
    printf("Operation [%s] on (%d, %d) = %d\n", op_name, x, y, result);
}

int main(void) {
    execute_calculator(add, 20, 10, "Addition");
    execute_calculator(subtract, 20, 10, "Subtraction");
    execute_calculator(multiply_op, 20, 10, "Multiplication");
    return 0;
}

Example 8.2: Tail Recursion and Factorial
#include <stdio.h>

// Tail recursive implementation allowing compiler optimization (TCO)
unsigned long long factorial_tail(int n, unsigned long long accumulator) {
    if (n <= 1) return accumulator;
    return factorial_tail(n - 1, n * accumulator);
}

int main(void) {
    int n = 15;
    unsigned long long fact = factorial_tail(n, 1);
    printf("Factorial of %d is %llu\n", n, fact);
    return 0;
}

9. Code Explanation
In Example 6.2:
- `swap(&x, &y)` passes the memory addresses of `x` and `y`.
- In `swap(int *p1, int *p2)`, dereferencing `*p1` reads and writes directly to the memory address of caller variable `x`.
In Example 8.1:
- `int (*calc)(int, int)` declares `calc` as a pointer to any function taking two integers and returning an integer.
- This decoupling allows callers to pass dynamic behaviors at runtime without modifying `execute_calculator`.

10. Practical Use Cases
- Standard library utilities like `qsort()` and `bsearch()` utilizing comparison function pointers.
- Event-driven graphical user interfaces and hardware interrupt service routines (ISRs).
- State-preserving ID counters and memoization caches using `static` local variables.

11. Common Mistakes
1. Attempting to return address of local automatic variable: Returning `&local_var` produces a dangling pointer because the stack frame is deallocated upon function return.
2. Missing function prototypes: Calling a function before declaration can lead to implicit int return assumptions and signature mismatch bugs.
3. Forgetting base case in recursion: Leads to infinite recursive calls and stack overflow crashes.
4. Modifying array size inside function: Using `sizeof(arr)` inside a function returns pointer size (4 or 8 bytes), not the full array byte size.

12. Edge Cases
- Deep recursion depth leading to stack overflow on systems with limited stack space (e.g., embedded targets).
- Passing NULL pointers to functions expecting valid memory references without defensive checking.

13. Best Practices
- Declare functions as `static` if they are only used within a single `.c` file to prevent global namespace pollution.
- Mark read-only array and pointer parameters with `const` (`const int *arr`).
- Always validate input parameters (check for `NULL` pointers) before dereferencing.
- Keep function lengths manageable and adhere to the Single Responsibility Principle.

14. Performance Considerations
- Use `inline` keyword for small, frequently called helper functions to eliminate call stack overhead.
- Pass large structures via `const` pointers (`const StructType *ptr`) rather than by value to prevent costly data copying on the stack.

15. Comparison with Related Concepts
- Macro (`#define`) vs Inline Function: Macros perform simple textual replacement without type safety or scope checking; inline functions provide full compiler type-checking and debugging support.
- Recursion vs Iteration: Recursion provides elegant solutions for divide-and-conquer and tree traversal, but consumes $O(N)$ stack memory; iteration uses $O(1)$ auxiliary stack space.

16. Debugging Tips
- Use GDB `backtrace` (or `bt`) command to inspect the call stack when a crash occurs inside nested function calls.
- Step into functions using `step` (or `s`) and step over using `next` (or `n`).

17. Interview Questions and Concept Checks
1. Why is returning a pointer to a local stack variable dangerous in C?
   - Local variables exist only for the lifetime of their stack frame. Once the function returns, that stack memory is reused, making the returned pointer invalid (dangling).
2. What does the `static` keyword mean when applied to a global function?
   - It restricts the function's linkage to internal linkage, making it invisible outside that specific translation unit (.c file).
3. How does `qsort()` from `<stdlib.h>` use function pointers?
   - It accepts a comparison function pointer `int (*compar)(const void *, const void *)` to dynamically compare elements.

18. Summary
Functions are fundamental building blocks in C programming. Deep comprehension of stack frame mechanics, call-by-value vs pointer passing, recursion, storage class lifetimes, and function pointers enables developers to write modular, high-performance, and maintainable systems code.
