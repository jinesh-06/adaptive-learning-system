TITLE: C Structures, Unions, Enumerations, and Memory Alignment

1. Introduction
While primitive data types represent individual scalars, complex software applications require grouping related heterogeneous data into composite entities. C provides user-defined composite data types through structures (`struct`), unions (`union`), enumerations (`enum`), and type aliasing (`typedef`). A structure aggregates multiple variables of different types under a single contiguous block, whereas a union allows multiple members to share the exact same memory space. Understanding structure declarations, initialization syntax, member access operators (`.` and `->`), pointer-to-structure mechanics, nested composites, bit-fields, memory alignment, and structure padding is essential for writing efficient systems code, network protocol parsers, and hardware drivers.

2. Learning Objectives
By studying this module, learners will:
- Define, declare, initialize, and manipulate C structures.
- Use member access operators: direct access (`.`) and pointer dereference access (`->`).
- Implement arrays of structures and nested structures.
- Pass structures to functions by value and by pointer reference efficiently.
- Apply `typedef` to define clean, readable type aliases.
- Understand unions, shared memory layouts, and type-punning mechanics.
- Compare memory models of structures versus unions.
- Define and utilize enumerations (`enum`) for state machines and categorical types.
- Understand struct memory padding, byte alignment, and compiler packing pragmas.

3. Core Concepts
- Structure (`struct`): A contiguous record holding multiple distinct member variables simultaneously.
- Union (`union`): A memory entity whose size equals its largest member; only one member is stored at any given time.
- Arrow Operator (`->`): Syntactic shorthand `ptr->member` for `(*ptr).member`.
- Type Aliasing (`typedef`): Assigns descriptive custom type names to existing primitive or composite types.
- Enumeration (`enum`): A distinct user type consisting of named integer constants.
- Memory Alignment & Padding: Hardware-driven alignment constraints causing compilers to insert unused padding bytes between struct members.

4. Detailed Explanation
4.1 Structures
- Declaration:
  struct Student {
      int id;
      char name[50];
      float gpa;
  };
- Initialization: Can use positional initializers `struct Student s1 = {101, "Alice", 3.9};` or designated initializers `struct Student s1 = {.name = "Alice", .id = 101, .gpa = 3.9};`.
- Pointer Access:
  struct Student *s_ptr = &s1;
  printf("%s", s_ptr->name);

4.2 Memory Alignment and Padding
CPUs access memory more efficiently in multiples of word boundaries (typically 4 or 8 bytes).
Given:
struct Data {
    char a;    // 1 byte + 3 bytes padding
    int b;     // 4 bytes
    char c;    // 1 byte + 3 bytes padding
};
Total size is 12 bytes instead of 6 bytes.
Reordering members by descending size:
struct OptimizedData {
    int b;     // 4 bytes
    char a;    // 1 byte
    char c;    // 1 byte + 2 bytes padding
};
Total size is reduced to 8 bytes (33% memory saving).

4.3 Unions and Shared Memory
- All union members share the exact same starting memory address.
- Useful for variant data types (discriminated unions) and hardware register bit-level representations.

4.4 Enumerations
- Default assigns integer values starting from 0: `enum Color { RED, GREEN, BLUE };` (RED=0, GREEN=1, BLUE=2).
- Explicit integer assignments are supported.

6. Basic Examples
Example 6.1: Basic Struct Declaration, Initialization, and Printing
#include <stdio.h>
#include <string.h>

typedef struct {
    int employee_id;
    char name[32];
    double salary;
} Employee;

void print_employee(const Employee *emp) {
    printf("ID: %d | Name: %s | Salary: $%.2f\n", emp->employee_id, emp->name, emp->salary);
}

int main(void) {
    Employee emp1 = {1001, "Marcus Vance", 85000.00};
    Employee emp2;
    emp2.employee_id = 1002;
    strncpy(emp2.name, "Elena Rostova", sizeof(emp2.name) - 1);
    emp2.salary = 92500.50;

    print_employee(&emp1);
    print_employee(&emp2);
    return 0;
}

Example 6.2: Enumeration for Day and State
#include <stdio.h>

typedef enum {
    LOG_DEBUG = 10,
    LOG_INFO  = 20,
    LOG_WARN  = 30,
    LOG_ERROR = 40
} LogLevel;

void log_message(LogLevel level, const char *msg) {
    switch (level) {
        case LOG_DEBUG: printf("[DEBUG] %s\n", msg); break;
        case LOG_INFO:  printf("[INFO]  %s\n", msg); break;
        case LOG_WARN:  printf("[WARN]  %s\n", msg); break;
        case LOG_ERROR: printf("[ERROR] %s\n", msg); break;
    }
}

int main(void) {
    log_message(LOG_INFO, "System service initialized.");
    log_message(LOG_ERROR, "Failed to connect to database host.");
    return 0;
}

7. Intermediate Examples
Example 7.1: Array of Structs and Search
#include <stdio.h>
#include <string.h>

typedef struct {
    char code[8];
    char title[64];
    int credits;
} Course;

int find_course(const Course catalog[], int count, const char *target_code) {
    for (int i = 0; i < count; i++) {
        if (strcmp(catalog[i].code, target_code) == 0) {
            return i;
        }
    }
    return -1;
}

int main(void) {
    Course catalog[] = {
        {"CS101", "Introduction to C", 4},
        {"CS102", "Data Structures in C++", 4},
        {"CS201", "Systems Programming in C", 3}
    };
    int total = sizeof(catalog) / sizeof(catalog[0]);

    int idx = find_course(catalog, total, "CS201");
    if (idx != -1) {
        printf("Found: %s - %s (%d Credits)\n", catalog[idx].code, catalog[idx].title, catalog[idx].credits);
    }
    return 0;
}

8. Advanced Examples
Example 8.1: Tagged / Discriminated Union (Variant Type)
#include <stdio.h>

typedef enum {
    TYPE_INT,
    TYPE_FLOAT,
    TYPE_STRING
} ValueType;

typedef struct {
    ValueType type;
    union {
        int i_val;
        float f_val;
        char *s_val;
    } data;
} DynamicValue;

void print_dynamic_value(const DynamicValue *val) {
    switch (val->type) {
        case TYPE_INT:
            printf("Integer: %d\n", val->data.i_val);
            break;
        case TYPE_FLOAT:
            printf("Float: %.4f\n", val->data.f_val);
            break;
        case TYPE_STRING:
            printf("String: %s\n", val->data.s_val);
            break;
    }
}

int main(void) {
    DynamicValue v1 = {.type = TYPE_INT, .data.i_val = 1024};
    DynamicValue v2 = {.type = TYPE_FLOAT, .data.f_val = 3.14159f};
    DynamicValue v3 = {.type = TYPE_STRING, .data.s_val = "Adaptive Learning Engine"};

    print_dynamic_value(&v1);
    print_dynamic_value(&v2);
    print_dynamic_value(&v3);
    return 0;
}

9. Code Explanation
In Example 6.1:
- Passing `&emp1` (a pointer) to `print_employee` avoids copying the entire 44-byte structure onto the stack, executing in $O(1)$ time and memory.
In Example 8.1:
- The tagged union pattern pairs an `enum` discriminator (`type`) with a `union` payload (`data`). This ensures type safety when accessing union members in C.

10. Practical Use Cases
- Network packet headers (IP, TCP, UDP protocol structures).
- Abstract Syntax Trees (AST) and expression parsers in compilers.
- Embedded microcontroller peripheral register mappings.
- Relational database record modeling and serialization layers.

11. Common Mistakes
1. Using dot operator on a pointer: `emp_ptr.name` instead of `emp_ptr->name` or `(*emp_ptr).name`.
2. Assuming `sizeof(struct)` is simply the sum of its member sizes, ignoring compiler padding.
3. Accessing inactive union members without checking the active tag.
4. Returning local struct pointers: Returning `&local_struct` produces a dangling pointer.

12. Edge Cases
- Self-referential structures: A struct cannot contain an instance of itself directly (`struct Node next;` fails), but it can contain a pointer to itself (`struct Node *next;`).
- Zero-length arrays at end of struct: Used as flexible array members in C99 for variable-length packet buffers (`char payload[];`).

13. Best Practices
- Order struct members from largest type to smallest type to minimize alignment padding.
- Pass structures larger than 16 bytes via `const` pointers (`const MyStruct *ptr`).
- Always use tagged unions when handling polymorphic data in pure C.

14. Performance Considerations
- Pass-by-reference eliminates CPU cache thrashing caused by copying large struct instances across stack frames.
- Be cautious with compiler packing pragmas (`#pragma pack(1)`); packing reduces byte size but may cause CPU bus unaligned access penalties on ARM architectures.

15. Comparison with Related Concepts
- Struct vs Union: In a struct, each member has its own distinct memory offset; in a union, all members overlap at byte offset 0.
- C Structs vs C++ Classes: In C, structs contain only data fields and have no access modifiers (all public) or member functions.

16. Debugging Tips
- Inspect memory layout and padding offsets using the standard `offsetof(struct_type, member)` macro from `<stddef.h>`.
- Use GDB `print *emp_ptr` to display all members of a struct instance simultaneously.

17. Interview Questions and Concept Checks
1. What is structure padding and why does the compiler introduce it?
   - Compilers insert padding bytes between struct members to align data types to native word boundaries (e.g., 4-byte or 8-byte boundaries) for faster CPU memory access.
2. How does a union determine its total memory footprint?
   - The size of a union is equal to the size of its largest member, rounded up to the alignment requirement of its most strictly aligned member.
3. What is a flexible array member in C99?
   - An unsized array declared as the last member of a struct (`type arr[]`) used to allocate contiguous variable-length payload buffers.

18. Summary
Structures, unions, and enumerations provide C with rich data abstraction capabilities. Understanding memory alignment, pointer access syntax, and tagged union patterns allows programmers to design compact, high-performance data models for real-world software.
