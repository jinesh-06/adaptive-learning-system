TITLE: Deep C Arrays, Multidimensional Storage, Pointer Decay, and Safe String Manipulation

1. Introduction
Arrays and strings are fundamental data storage structures in C. An array is a contiguous, fixed-size sequence of elements of homogeneous data type allocated in memory. In C, strings are not a distinct built-in primitive type, but rather character arrays terminated by a null byte (`'\0'`). Because C does not perform automatic runtime bounds checking and passes arrays by decaying them into raw memory pointers, a deep understanding of memory layouts, pointer arithmetic equivalence, `<string.h>` library mechanics, buffer overflow vulnerabilities, and safe input parsing is critical for systems programming.

- Implement secure string handling patterns to prevent stack buffer overflows and off-by-one null terminator bugs.

4. Core Concepts
- Contiguous Memory Allocation: Array elements are stored in adjacent memory addresses with zero padding between primitive elements.
- Array Decay: In most expressions (except when operand of `sizeof` or `&`), an array name evaluates to a pointer to its first element (`&arr[0]`).
- Null-Terminated Strings: Strings are sequences of characters ending with ASCII byte 0 (`'\0'`). All string algorithms iterate until encountering this null sentinel byte.
- Row-Major Order: 2D arrays are flattened in memory row by row. `matrix[row][col]` maps to linear offset `row * NUM_COLS + col`.

5. Detailed Theory
5.1 Array Memory Layout and Pointer Equivalence
For an array declared as `int arr[5] = {10, 20, 30, 40, 50};`:
- The memory address of element `arr[i]` is computed by:
  $$	ext{Address}(arr[i]) = 	ext{Base Address}(arr) + (i 	imes 	ext{sizeof}(	ext{int}))$$
- Pointer Arithmetic Equivalence:
  The indexing expression `arr[i]` is strictly syntactic sugar for `*(arr + i)`.
  Because addition is commutative, `*(arr + i) == *(i + arr) == i[arr]`.

5.2 Array-to-Pointer Decay in Functions
When an array is passed to a function:
```c
void print_array(int arr[], size_t size); // Equivalent to: void print_array(int *arr, size_t size);
```
The compiler decays the array into a pointer to its first element. Inside `print_array`, `sizeof(arr)` evaluates to `sizeof(int*)` (8 bytes on 64-bit systems), NOT the total byte size of the array. Hence, the array size MUST be passed as an explicit parameter.

5.3 Multidimensional Arrays
A 2D array `int matrix[3][4]` is stored as 3 contiguous rows of 4 integers:
- `sizeof(matrix)` = $3 	imes 4 	imes 4 = 48$ bytes.
- When passing a 2D array to a function, the column dimension MUST be specified so the compiler can compute row offsets:
  `void process_matrix(int matrix[][4], int rows);`

5.4 C Strings and Null-Termination Mechanics
A string literal `"Hello"` has type `const char[6]` (5 letters + 1 null byte `'\0'`).
- Array Initialization (Mutable on Stack):
  `char str[] = "Hello";` -> Allocates 6 bytes on the stack, copies "Hello\0" into it. Can be modified: `str[0] = 'h';`.
- Pointer to String Literal (Immutable in `.rodata`):
  `char *str = "Hello";` -> Points to read-only text memory. Modifying `str[0] = 'h';` causes a segmentation fault (`SIGSEGV`).

5.5 String Library Functions (`<string.h>`)
- `size_t strlen(const char *s)`: Counts characters until `'\0'` (excluding the null byte). $O(N)$ time.
- `char *strcpy(char *dest, const char *src)`: Copies characters including `'\0'`. UNSAFE if `dest` buffer is smaller than `src`.
- `char *strncpy(char *dest, const char *src, size_t n)`: Copies at most `n` bytes. If `src` has length $\ge n$, `dest` is NOT null-terminated!
- `int strcmp(const char *s1, const char *s2)`: Lexicographically compares two strings. Returns $<0$ if $s1 < s2$, $0$ if equal, $>0$ if $s1 > s2$.
- `char *strchr(const char *s, int c)`: Finds first occurrence of character `c`.
- `char *strstr(const char *haystack, const char *needle)`: Finds substring.
- `char *strtok(char *str, const char *delim)`: Tokenizes string by replacing delimiters with `'\0'`. Modifies input in-place.

6. Syntax
- 1D Array: `type name[SIZE];`
- 2D Array: `type name[ROWS][COLS];`
- String Declaration: `char name[BUFFER_SIZE] = "initial_text";`
- Safe Input: `fgets(buffer, sizeof(buffer), stdin);`

7. Basic Examples (Beginner Level)
```c
#include <stdio.h>

int main(void) {
    // Array declaration and initialization
    int scores[5] = { 88, 92, 79, 95, 84 };
    int total_score = 0;

    printf("Array elements: ");
    for (int i = 0; i < 5; i++) {

        total_score += scores[i];

    return 0;
}
```
Expected Output:
```
Array elements: 88 92 79 95 84 
Average score: 87.60
Greeting string: Hello, World! (Length: 13 chars)
```

```c
#include <stdio.h>
#include <string.h>

#define ROWS 2
#define COLS 3

void print_matrix(const int mat[ROWS][COLS]) {
    for (int r = 0; r < ROWS; r++) {
        printf("[ ");
        for (int c = 0; c < COLS; c++) {
            printf("%3d ", mat[r][c]);
        }
        printf("]\n");
    }
}

void parse_csv_line(char *csv_line) {
    printf("Parsing CSV line: \"%s\"\n", csv_line);
    const char *delimiters = ",\n";
    char *token = strtok(csv_line, delimiters);
    int column_idx = 1;

    while (token != NULL) {
        printf("  Column %d: %s\n", column_idx++, token);
        token = strtok(NULL, delimiters);
    }
}

int main(void) {
    int matrix[ROWS][COLS] = {
        { 10, 20, 30 },
        { 40, 50, 60 }
    };

    printf("2D Matrix Contents:\n");
    print_matrix(matrix);

    char log_entry[] = "2026-09-12,INFO,AuthService,User login successful";
    parse_csv_line(log_entry);

    return 0;
}
```

9. Advanced Examples (Safe String Copy and Bounds-Checked Buffer Manipulation)
```c
#include <stdio.h>
#include <stdbool.h>
#include <stddef.h>

// Safe string copy guaranteed to null-terminate and prevent overflow
bool safe_str_copy(char *dest, size_t dest_capacity, const char *src) {
    if (dest == NULL || src == NULL || dest_capacity == 0) {
        return false;
    }

    size_t i = 0;
    while (i < dest_capacity - 1 && src[i] != '\0') {
        dest[i] = src[i];
        i++;
    }
    dest[i] = '\0'; // Always guarantee null termination

    // Return true if entire src was copied; false if truncation occurred
    return (src[i] == '\0');
}

int main(void) {
    char small_buffer[8];
    const char *long_text = "Supercalifragilistic";

    bool fully_copied = safe_str_copy(small_buffer, sizeof(small_buffer), long_text);
    printf("Copied into 8-byte buffer: \"%s\" (Truncated: %s)\n", 
           small_buffer, fully_copied ? "No" : "Yes");

    char adequate_buffer[32];
    const char *short_text = "Safe C Code";
    fully_copied = safe_str_copy(adequate_buffer, sizeof(adequate_buffer), short_text);
    printf("Copied into 32-byte buffer: \"%s\" (Truncated: %s)\n", 
           adequate_buffer, fully_copied ? "No" : "Yes");

    return 0;
}
```
Expected Output:
```
Copied into 8-byte buffer: "Superca" (Truncated: Yes)
Copied into 32-byte buffer: "Safe C Code" (Truncated: No)
```

10. Line-by-Line Code Explanation
- `bool safe_str_copy(...)`: Accepts target buffer, total buffer capacity (including null byte), and source string.
- `while (i < dest_capacity - 1 && src[i] != '\0')`: Copies at most `dest_capacity - 1` characters, reserving the final slot for `'\0'`.
- `dest[i] = '\0';`: Guarantees null-termination even if the source string was longer than the target capacity.
- `return (src[i] == '\0');`: Informs the caller whether string truncation occurred.

11. Practical Programming Problems
Problem 1: In-Place String Reversal
Write an efficient function to reverse a null-terminated string in-place using two-pointer swapping.
```c
#include <stdio.h>
#include <string.h>

void reverse_string(char *str) {
    if (str == NULL) return;
    int left = 0;
    int right = (int)strlen(str) - 1;
    while (left < right) {
        char temp = str[left];
        str[left] = str[right];
        str[right] = temp;
        left++;
        right--;
    }
}

int main(void) {
    char message[] = "Adaptive Learning Engine";
    printf("Original: \"%s\"\n", message);
    reverse_string(message);
    printf("Reversed: \"%s\"\n", message);
    return 0;
}
```
Complexity: Time $O(N)$, Space $O(1)$.

13. Common Mistakes
- Using `gets()`: `gets()` provides no buffer bounds limit and is so dangerous it was completely removed from the C11 standard. Always use `fgets()`.
- Forgetting the Null Terminator in Buffer Size: Allocating `char str[5]` for `"hello"` (5 characters) leaves no room for `'\0'`, leading to out-of-bounds reads during `printf("%s")`.
- Calling `strtok()` on Read-Only String Literals: `strtok` mutates the input string by writing `\0` over delimiters. Calling it on a string literal causes a `SIGSEGV`.

14. Common Errors and Error Messages
INCORRECT EXAMPLE:
```c
// Bug: Buffer overflow with strcpy
char buffer[5];
strcpy(buffer, "Extremely Long Text"); // STACK SMASHING / BUFFER OVERFLOW
```
CORRECT VERSION:
```c
char buffer[32];
strncpy(buffer, "Extremely Long Text", sizeof(buffer) - 1);
buffer[sizeof(buffer) - 1] = '\0';
```

15. Debugging Techniques
- AddressSanitizer: Compile with `gcc -fsanitize=address -g main.c` to catch stack and global buffer overflows instantly with line numbers.
- Valgrind: Run `valgrind ./program` to detect uninitialized string reads.

16. Edge Cases
- Empty String `""`: Contains 1 byte: the null terminator (`str[0] == '\0'`). `strlen("") == 0`.
- Missing Null Terminator: Passing an un-terminated `char` array to `strlen()` causes the function to scan through adjacent stack memory until it encounters an arbitrary 0 byte or crashes with `SIGSEGV`.

17. Best Practices
- Always use `fgets(buffer, sizeof(buffer), stdin)` instead of `scanf("%s", buffer)` for string input.
- Always explicitly allocate $N + 1$ bytes for a string of length $N$ to store the null terminator.
- Use `snprintf(buffer, sizeof(buffer), "format %s", val)` for safe formatted string composition.

18. Performance Considerations
- Cache Line Locality: Accessing 2D arrays row-by-row (`matrix[r][c]`) follows memory layout and achieves near 100% cache hits. Accessing column-by-column (`matrix[c][r]`) causes cache thrashing and runs up to 10x slower on large matrices.

19. Security Considerations
- Stack Smashing: Buffer overflows allow overwriting function return addresses, enabling arbitrary code execution (CWE-120). Always use bounds-checking functions.

20. Memory Considerations
- Array Decay Loses Size Info: A function receiving an array cannot determine its length via `sizeof`. Size must be tracked and passed separately.

21. Comparison with Related Concepts
- C Strings vs C++ `std::string`: C strings are raw memory buffers with manual memory and termination management; `std::string` is an automatic RAII object that manages capacity and stores length in $O(1)$.
- 1D Flattened Array vs Array of Pointers (`char**`): A 1D flattened array has zero pointer overhead and perfect cache locality; an array of pointers involves extra memory allocation and pointer indirection overhead.

22. Frequently Asked Questions
Q: Why does `sizeof("hello")` return 6?
A: String literals include the hidden trailing null terminator byte `'\0'`, giving 5 characters + 1 null byte = 6 bytes.

Q: Is `strtok()` thread-safe?
A: No. `strtok()` maintains internal static state to track position across calls. Use the POSIX thread-safe reentrant variant `strtok_r()` for multi-threaded programs.

23. Interview Questions
Beginner:
Q: What is the difference between `char str[] = "text";` and `char *str = "text";`?
A: `char str[]` allocates an array on the stack and copies the characters into it, allowing in-place modification. `char *str` points directly to a read-only string literal in the `.rodata` segment, and attempting to modify it causes undefined behavior (segmentation fault).

Intermediate:
Q: Explain how array-to-pointer decay works in C.
A: When an array is used in an expression (other than `sizeof` or `&`), its name evaluates to a pointer to its first element (`&arr[0]`). When passed to a function, only this pointer is copied, losing original array size metadata.

Advanced:
Q: How does `snprintf` guarantee null termination, and how should its return value be checked for truncation?
A: `snprintf(buf, size, fmt, ...)` writes at most `size - 1` characters and always appends `'\0'`. It returns the total number of characters that *would* have been written if `size` were unlimited. If `return_val >= size`, truncation occurred.

26. Summary
Arrays provide fast contiguous memory storage, while C strings rely on null-terminated character arrays. Understanding pointer decay, 2D row-major layouts, safe string manipulation functions, and buffer overflow prevention is essential for robust C programming.

27. Key Takeaways
- Arrays decay to pointers when passed to functions; always pass array size explicitly.
- Strings require $N + 1$ bytes for $N$ characters to store the terminating `'\0'`.
- Never use `gets()` or unbounded `strcpy()`; use `fgets()` and `snprintf()`.
- Access 2D arrays in row-major order for optimal CPU cache utilization.
