1. INTRODUCTION

Pointers and dynamic memory management are fundamental features of C programming. A pointer is an object whose value represents the address of another object or function according to the rules of the C language.

Pointers allow programs to:

* Access objects indirectly.
* Modify objects through their addresses.
* Efficiently pass large objects to functions.
* Traverse arrays and data structures.
* Dynamically allocate storage.
* Construct linked lists, trees, graphs, queues, stacks, and hash tables.
* Interface with operating-system and embedded-system APIs.
* Implement custom memory-management techniques.

However, pointer-based programming requires careful attention to object lifetime, bounds, alignment, ownership, and validity.

Incorrect pointer operations can result in:

* Undefined behavior.
* Buffer overflows.
* Use-after-free.
* Double-free errors.
* Dangling pointers.
* Memory leaks.
* Invalid pointer arithmetic.
* Alignment violations.
* Segmentation faults on systems where invalid access is detected.

The ISO/IEC JTC 1/SC 22/WG14 committee is responsible for standardizing the C programming language. C23 is the current C standard.

4. POINTER FUNDAMENTALS

A pointer is an object that stores a value representing the address of another object or function according to the rules of C.

Example:

#include <stdio.h>

int main(void)
{
int x = 10;
int *p = &x;

```
printf("Value: %d\n", *p);

return 0;
```

}

Here:

x  -> integer object containing 10
p  -> pointer containing the address of x
*p -> accesses the integer object x

5. ADDRESS-OF OPERATOR

The address-of operator (&) obtains the address of an object.

Example:

int x = 25;
int *p = &x;

Conceptually:

x
+------+
|  25  |
+------+
^
|
p

The pointer p contains the address of x.

6. DEREFERENCE OPERATOR

The unary * operator can access the object referred to by a valid pointer.

Example:

int x = 25;
int *p = &x;

printf("%d\n", *p);

Output:

25

A pointer can also be used to modify the pointed-to object:

*p = 50;

Now:

x = 50

7. NULL POINTERS

A null pointer is a pointer value that does not point to an object or function.

Example:

int *p = NULL;

A null pointer must not be dereferenced.

Incorrect:

int *p = NULL;
printf("%d\n", *p);

The behavior is undefined.

NULL is commonly used to represent that a pointer currently has no valid target.

8. POINTER INITIALIZATION

An uninitialized pointer:

int *p;

does not automatically point to a valid object.

Using it before assigning a valid value can result in undefined behavior.

Safer:

int *p = NULL;

Then assign a valid address:

int value = 100;
p = &value;

9. POINTER ARITHMETIC

Pointer arithmetic depends on the type of the pointed-to object.

Example:

int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;

Then:

p + 0 -> arr[0]
p + 1 -> arr[1]
p + 2 -> arr[2]
p + 3 -> arr[3]
p + 4 -> arr[4]

Pointer arithmetic advances according to the size of the pointed-to type.

For example, if sizeof(int) is 4 bytes, moving from p to p + 1 advances by 4 bytes in the corresponding address representation.

Pointer arithmetic should be performed only within the same array object or at its one-past-the-end position, according to the rules of C.

10. VALID POINTER ARITHMETIC

For:

int arr[5];
int *p = arr;

Operations such as the following can be valid:

p + 1
p + 2
p++
p--

provided that the resulting pointer remains within the permitted array range or one-past-the-end position.

The one-past-the-end pointer may be formed but must not be dereferenced.

Example:

int *end = arr + 5;

Valid:

while (p != end) {
printf("%d\n", *p);
p++;
}

Invalid:

printf("%d\n", *end);

11. POINTER SUBTRACTION

Two pointers referring to elements of the same array can be subtracted.

Example:

#include <stdio.h>
#include <stddef.h>

int main(void)
{
int arr[10];

```
int *p1 = &arr[2];
int *p2 = &arr[7];

ptrdiff_t difference = p2 - p1;

printf("%td\n", difference);

return 0;
```

}

Output:

5

The result represents the number of array elements between the pointers.

12. ARRAY AND POINTER RELATIONSHIP

Consider:

int arr[3] = {10, 20, 30};

In many expressions, arr is converted to a pointer to its first element.

Therefore:

arr

commonly behaves like:

&arr[0]

and:

arr[2]

is equivalent to:

*(arr + 2)

However, an array and a pointer are not the same type.

This difference is important when using sizeof.

For example:

int arr[10];
int *p = arr;

sizeof(arr)

returns the size of the complete array.

sizeof(p)

returns the size of the pointer itself.

13. POINTER SIZE

The size of a pointer is implementation-dependent.

Many modern 64-bit systems commonly use 8-byte object pointers, but the C language does not require every system to use 8-byte pointers.

Therefore, portable C code must not assume:

sizeof(pointer) == 8

The size of a pointer should be obtained using:

sizeof(pointer)

14. VOID POINTERS

A void pointer is a generic object pointer.

Example:

int x = 10;

void *p = &x;

In C, an object pointer can be converted to void * and back to an appropriate object pointer without an explicit cast.

Example:

int *q = p;

Before dereferencing a void pointer, the programmer must use the appropriate object-pointer type.

Example:

printf("%d\n", *(int *)p);

void * is commonly used in generic C interfaces such as dynamic memory allocation and generic library functions.

15. CONST AND POINTERS

There are three important forms.

15.1 POINTER TO CONSTANT DATA

const int *p;

The integer cannot be modified through p.

Example:

int x = 10;
const int *p = &x;

printf("%d\n", *p);

The pointer itself can be changed:

p = NULL;

15.2 CONSTANT POINTER

int *const p = &x;

The pointer cannot be redirected after initialization.

However, the pointed-to integer can be modified:

*p = 20;

15.3 CONSTANT POINTER TO CONSTANT DATA

const int *const p = &x;

Neither the pointer nor the pointed-to data can be modified through p.

16. POINTER-TO-POINTER

A pointer-to-pointer stores the address of another pointer.

Example:

int x = 10;
int *p = &x;
int **pp = &p;

Conceptually:

pp
|
v
p
|
v
x
|
10

Then:

*pp

produces p.

And:

**pp

produces x's value, 10.

17. USES OF DOUBLE POINTERS

Double pointers are useful when a function must modify a pointer owned by the caller.

Example:

#include <stdio.h>
#include <stdlib.h>

void allocate_buffer(int **ptr, size_t count)
{
*ptr = malloc(count * sizeof **ptr);

```
if (*ptr == NULL)
    return;
```

}

int main(void)
{
int *buffer = NULL;

```
allocate_buffer(&buffer, 5);

if (buffer != NULL) {
    for (int i = 0; i < 5; i++)
        buffer[i] = i + 1;

    free(buffer);
    buffer = NULL;
}

return 0;
```

}

18. DYNAMIC MEMORY MANAGEMENT

C provides dynamic memory-management functions through <stdlib.h>.

Important functions include:

malloc()
calloc()
realloc()
free()

C23 also provides:

free_sized()
free_aligned_sized()

Dynamic allocation is useful when the required amount of storage is not known at compile time or when an object's lifetime must extend beyond a particular block scope.

19. MALLOC()

Syntax:

void *malloc(size_t size);

malloc() allocates the requested number of bytes of uninitialized storage.

Example:

int *p = malloc(5 * sizeof *p);

if (p == NULL) {
return 1;
}

The cast is not required in C.

Preferred:

int *p = malloc(5 * sizeof *p);

Instead of:

int *p = (int *)malloc(5 * sizeof *p);

The returned pointer must be checked before use.

20. CALLOC()

Syntax:

void *calloc(size_t count, size_t size);

Example:

int *p = calloc(5, sizeof *p);

calloc() allocates storage for an array of objects and initializes the allocated storage to all bits zero.

Important:

All-bits-zero is not universally guaranteed by the C language to represent every possible zero value, such as a null pointer representation or every floating-point representation of 0.0.

Therefore, calloc() should be understood as zeroing the allocated bytes, not as a universal semantic initialization of every C type.

21. REALLOC()

Syntax:

void *realloc(void *ptr, size_t new_size);

realloc() changes the size of an existing dynamic allocation.

The allocation may:

1. Expand in place.
2. Move to another memory location.

Existing contents are preserved up to the lesser of the old and new sizes.

Example:

int *tmp = realloc(p, new_size);

if (tmp != NULL) {
p = tmp;
}

22. SAFE REALLOC PATTERN

Avoid:

p = realloc(p, new_size);

because if realloc() fails, it returns NULL and the original allocation remains allocated. Overwriting p would lose the original pointer.

Preferred:

void *tmp = realloc(p, new_size);

if (tmp != NULL) {
p = tmp;
} else {
/* Original allocation is still valid */
}

This pattern prevents accidental loss of the original allocation.

23. FREE()

Syntax:

free(ptr);

free() releases dynamically allocated storage.

Example:

int *p = malloc(10 * sizeof *p);

if (p != NULL) {
/* use p */

```
free(p);
p = NULL;
```

}

free(NULL) is guaranteed to be safe and performs no action.

After free(p), the lifetime of the allocation has ended and the old pointer must not be dereferenced.

24. MEMORY LIFECYCLE

A dynamic object's lifecycle can be represented as:

Allocation
|
v
Allocated object
|
| use
v
Resize or normal use
|
v
Deallocation
|
v
Object lifetime ends

A dynamically allocated object remains valid until its allocated storage is released by the appropriate deallocation operation or otherwise reaches the end of its specified lifetime.

25. OWNERSHIP

Every dynamically allocated object should have a clearly defined owner.

The owner is responsible for ensuring that the allocation is eventually released.

Example:

char *name = malloc(100);

If the current function owns the allocation, it should arrange for:

free(name);

on all appropriate cleanup paths.

Good ownership design prevents memory leaks and makes APIs easier to understand.

26. MEMORY LEAK

A memory leak occurs when dynamically allocated storage remains allocated but the program can no longer correctly access it for deallocation.

Example:

int *p = malloc(100 * sizeof *p);

p = NULL;

The allocated block can no longer be released through p.

Correct:

int *p = malloc(100 * sizeof *p);

if (p != NULL) {
/* use p */

```
free(p);
p = NULL;
```

}

27. DANGLING POINTER

A dangling pointer is a pointer that refers to an object whose lifetime has ended.

Example:

int *p = malloc(sizeof *p);

free(p);

After free(p), p is no longer a valid pointer for accessing the released object.

Defensive practice:

free(p);
p = NULL;

28. WILD POINTER

A wild pointer is a common term for an uninitialized pointer.

Example:

int *p;

The pointer has not been initialized to a valid object or null pointer.

Incorrect:

*p = 10;

Safer:

int *p = NULL;

29. USE-AFTER-FREE

Example:

int *p = malloc(sizeof *p);

if (p != NULL) {
*p = 100;

```
free(p);

/* Invalid */
*p = 200;
```

}

The final access is a use-after-free and has undefined behavior.

Correct:

free(p);
p = NULL;

30. DOUBLE FREE

Incorrect:

int *p = malloc(sizeof *p);

free(p);
free(p);

The second free() attempts to release an allocation whose lifetime has already ended.

Safer:

free(p);
p = NULL;

Calling free(p) again is then safe because p is NULL.

31. BUFFER OVERFLOW

Example:

int *p = malloc(5 * sizeof *p);

if (p != NULL) {
p[5] = 100;
}

Valid indexes are:

0
1
2
3
4

p[5] is outside the allocated array and results in undefined behavior.

32. OUT-OF-BOUNDS ACCESS

For:

int arr[5];

Valid element access:

arr[0]
arr[1]
arr[2]
arr[3]
arr[4]

Invalid:

arr[5]
arr[-1]

C does not automatically perform bounds checking for ordinary arrays.

33. INTEGER OVERFLOW IN ALLOCATION

A dangerous allocation expression can be:

p = malloc(count * sizeof *p);

if count is extremely large, the multiplication may overflow before malloc() receives the size.

For robust software, validate allocation-size calculations before performing multiplication.

A size calculation should ensure that:

count * sizeof *p

does not exceed the representable range of size_t.

Where supported, functions such as reallocarray() can express array-size calculations more safely.

34. INVALID FREE

free() should only be used with:

* A null pointer.
* A pointer returned by an appropriate allocation function.
* A pointer to an allocation that has not already been released.

Incorrect:

int x = 10;
free(&x);

This is invalid because x was not dynamically allocated.

35. STRUCTURE PADDING AND ALIGNMENT

Consider:

struct Example {
char c;
int x;
};

The structure may contain padding between members or at the end.

Therefore:

sizeof(struct Example)

may be larger than:

sizeof(char) + sizeof(int)

The implementation may insert padding to satisfy alignment requirements.

Never assume a structure has no padding.

36. STRUCTURE ALLOCATION

Preferred:

struct Example *p = malloc(sizeof *p);

This is preferable to repeating the structure type because sizeof *p automatically follows the pointer's type.

Example:

struct Node *node = malloc(sizeof *node);

if (node == NULL) {
return NULL;
}

37. FLEXIBLE ARRAY MEMBERS

C supports flexible array members.

Example:

struct Packet {
size_t length;
unsigned char data[];
};

A dynamically allocated object can reserve additional storage after the fixed portion for the flexible array member.

This technique is useful for variable-sized structures and network or binary data representations.

38. CONTIGUOUS DYNAMIC ARRAYS

Example:

int *data = malloc(n * sizeof *data);

A successful allocation for n int objects provides storage suitable for those objects in contiguous array order.

Contiguous storage is often beneficial for:

* Sequential access.
* Cache locality.
* Simple indexing.
* Bulk processing.

39. DYNAMIC 2D ARRAYS

There are several ways to implement dynamic two-dimensional data.

Method 1:

int **matrix;

Each row can be allocated independently.

Advantages:

* Rows can have different lengths.
* Rows can be independently allocated.

Disadvantages:

* Multiple allocations.
* Additional pointer indirection.
* Rows may not be contiguous.

40. FLATTENED 2D ARRAY

A 2D matrix can be represented as one contiguous allocation.

For:

rows = 3
cols = 4

the element at row r and column c can be stored at:

data[r * cols + c]

Example:

int *data = malloc(rows * cols * sizeof *data);

if (data != NULL) {
data[r * cols + c] = value;
}

This representation provides contiguous storage for all matrix elements.

41. DYNAMIC MATRIX EXAMPLE

#include <stdio.h>
#include <stdlib.h>

typedef struct {
int *data;
size_t rows;
size_t cols;
} Matrix;

Matrix *matrix_create(size_t rows, size_t cols)
{
Matrix *m = malloc(sizeof *m);

```
if (m == NULL)
    return NULL;

m->data = malloc(rows * cols * sizeof *m->data);

if (m->data == NULL) {
    free(m);
    return NULL;
}

m->rows = rows;
m->cols = cols;

return m;
```

}

void matrix_set(Matrix *m, size_t row, size_t col, int value)
{
m->data[row * m->cols + col] = value;
}

int matrix_get(const Matrix *m, size_t row, size_t col)
{
return m->data[row * m->cols + col];
}

void matrix_destroy(Matrix **m)
{
if (m == NULL || *m == NULL)
return;

```
free((*m)->data);
free(*m);

*m = NULL;
```

}

int main(void)
{
Matrix *m = matrix_create(3, 4);

```
if (m == NULL)
    return EXIT_FAILURE;

int value = 1;

for (size_t r = 0; r < m->rows; r++) {
    for (size_t c = 0; c < m->cols; c++) {
        matrix_set(m, r, c, value++);
    }
}

for (size_t r = 0; r < m->rows; r++) {
    for (size_t c = 0; c < m->cols; c++) {
        printf("%3d ", matrix_get(m, r, c));
    }
    printf("\n");
}

matrix_destroy(&m);

return EXIT_SUCCESS;
```

}

5   6   7   8
9  10  11  12

42. PROCESS MEMORY MODEL

A simplified process-memory model is often represented as:

High Address
+----------------------+
| Stack                |
| Function frames      |
+----------------------+
| Mapped regions       |
| Shared libraries     |
+----------------------+
| Heap                 |
| Dynamic allocations  |
+----------------------+
| BSS                  |
| Zero-initialized     |
| static storage       |
+----------------------+
| Data                 |
| Initialized static   |
+----------------------+
| Text / Code          |
+----------------------+
Low Address

This is a conceptual model.

The exact virtual-address-space organization is implementation- and operating-system-dependent.

The C language itself does not require every implementation to use this exact layout.

43. STORAGE DURATION

C describes different storage durations, including:

* Automatic storage duration.
* Static storage duration.
* Thread storage duration.
* Allocated storage duration.

Dynamic allocation is associated with allocated storage duration.

The exact physical location of an object should not be inferred solely from its storage duration.

44. VIRTUAL MEMORY

Modern operating systems commonly provide processes with virtual address spaces.

A virtual address may be translated through hardware and operating-system mechanisms to physical memory or another mapped resource.

If a program accesses an address that is not valid for the process, the operating system may generate a memory-access fault.

On many Unix-like systems, such an invalid access commonly results in SIGSEGV.

Important:

SIGSEGV is an operating-system-level manifestation. The C language generally describes the underlying invalid access as undefined behavior.

45. HEAP ALLOCATOR

The C standard specifies allocation functions but does not require a particular heap implementation.

A particular implementation such as GNU libc may use sophisticated allocation structures including:

* Free chunks.
* Allocation metadata.
* Arenas.
* Internal bins.
* Memory mappings.

The exact implementation is platform-specific.

Therefore, portable C programs should depend on the C allocation interface rather than assumptions about a specific heap implementation.

46. WHAT HAPPENS DURING FREE()

Calling:

free(p);

releases the allocated storage for reuse by the memory allocator.

It does not necessarily mean that the memory is immediately returned to the operating system.

An allocator may retain memory for future allocations by the same process.

Therefore:

free()

should be understood as ending the lifetime of the allocated object and making the storage available to the allocator.

47. MEMORY ALIGNMENT

Objects may have alignment requirements.

For example:

char
int
double
struct

may require different alignments on a particular implementation.

Memory returned by malloc() is suitably aligned for objects requiring fundamental alignment.

Special alignment requirements can be handled using facilities such as aligned_alloc() where supported and appropriate.

48. SIZEOF BEST PRACTICE

Preferred:

int *p = malloc(n * sizeof *p);

For structures:

struct Node *node = malloc(sizeof *node);

Using sizeof *pointer avoids repeating the type name and reduces maintenance errors.

49. SAFE DYNAMIC ARRAY EXAMPLE

#include <stdio.h>
#include <stdlib.h>

typedef struct {
int *data;
size_t size;
size_t capacity;
} DynamicArray;

DynamicArray *create_array(size_t capacity)
{
DynamicArray *arr = malloc(sizeof *arr);

```
if (arr == NULL)
    return NULL;

if (capacity == 0) {
    arr->data = NULL;
    arr->size = 0;
    arr->capacity = 0;
    return arr;
}

arr->data = malloc(capacity * sizeof *arr->data);

if (arr->data == NULL) {
    free(arr);
    return NULL;
}

arr->size = 0;
arr->capacity = capacity;

return arr;
```

}

int push_back(DynamicArray *arr, int value)
{
if (arr == NULL)
return -1;

```
if (arr->size == arr->capacity) {

    size_t new_capacity;

    if (arr->capacity == 0)
        new_capacity = 1;
    else
        new_capacity = arr->capacity * 2;

    int *tmp = realloc(
        arr->data,
        new_capacity * sizeof *arr->data
    );

    if (tmp == NULL)
        return -1;

    arr->data = tmp;
    arr->capacity = new_capacity;
}

arr->data[arr->size++] = value;

return 0;
```

}

void destroy_array(DynamicArray **arr)
{
if (arr == NULL || *arr == NULL)
return;

```
free((*arr)->data);
free(*arr);

*arr = NULL;
```

}

int main(void)
{
DynamicArray *arr = create_array(2);

```
if (arr == NULL)
    return EXIT_FAILURE;

for (int i = 1; i <= 5; i++) {

    if (push_back(arr, i * 10) != 0) {
        destroy_array(&arr);
        return EXIT_FAILURE;
    }

    printf(
        "Added %d | Size: %zu | Capacity: %zu\n",
        i * 10,
        arr->size,
        arr->capacity
    );
}

printf("Array elements: ");

for (size_t i = 0; i < arr->size; i++)
    printf("%d ", arr->data[i]);

printf("\n");

destroy_array(&arr);

return EXIT_SUCCESS;
```

}

Added 20 | Size: 2 | Capacity: 2
Added 30 | Size: 3 | Capacity: 4
Added 40 | Size: 4 | Capacity: 4
Added 50 | Size: 5 | Capacity: 8
Array elements: 10 20 30 40 50

Node *node = malloc(sizeof *node);

```
    return NULL;
```

}

void free_list(Node **head)
{
while (head != NULL && *head != NULL) {

```
    Node *next = (*head)->next;

}
```

52. POINTER QUALIFIERS

Important pointer-related qualifiers include:

const
volatile
restrict

const controls modification through a particular access path.

volatile tells the implementation that accesses to an object may have observable effects beyond ordinary program execution and therefore should not be optimized away in the same manner as ordinary accesses.

volatile is commonly relevant to memory-mapped hardware and certain low-level interfaces.

restrict provides an optimization-related promise about pointer-based access to objects.

These qualifiers have precise language-level rules and should be used only when their semantics are appropriate.

53. MEMORY-MAPPED I/O

Embedded systems may expose hardware registers through memory addresses.

Conceptual example:

volatile unsigned int *reg =
(volatile unsigned int *)0x40001000;

Then:

*reg = 1;

may access a hardware register on an appropriate target platform.

This is implementation-specific and is not portable ordinary application code.

The actual address and register semantics are defined by the hardware platform.

54. UNDEFINED BEHAVIOR

Pointer errors frequently result in undefined behavior.

Examples:

int *p = NULL;
*p = 10;

Another example:

int *p = malloc(sizeof *p);

free(p);

*p = 10;

Another example:

int arr[5];

arr[10] = 20;

C does not guarantee a predictable result after undefined behavior occurs.

55. COMMON MEMORY ERRORS

Null dereference:
Accessing an object through a null pointer.

Wild pointer:
Using an uninitialized pointer.

Dangling pointer:
A pointer associated with an object whose lifetime has ended.

Use-after-free:
Accessing storage after it has been released.

Double-free:
Releasing the same allocation more than once.

Buffer overflow:
Accessing outside an object's permitted bounds.

Memory leak:
Allocated storage is no longer properly reachable for release.

Invalid free:
Passing an inappropriate pointer to free().

Alignment violation:
Accessing an object through an improperly aligned pointer.

Allocation-size overflow:
A size calculation wraps before memory allocation.

AddressSanitizer, commonly called ASan, is a compiler-based memory error detector.

It can detect many errors including:

57. VALGRIND

It can help identify:

* Invalid writes.
* Invalid frees.
* Memory leaks.

Availability and behavior depend on the operating system and architecture.

60. C23 MEMORY MANAGEMENT

C23 introduces additional memory-management facilities including:

These functions allow deallocation interfaces to receive size and alignment information where required by their contracts.

Example concept:

Programs should use these functions only when the compiler and standard library implementation support the relevant C23 functionality.

61. MALLOC VS CALLOC

malloc():

* Takes a number of bytes.
* Allocates uninitialized storage.
* Returns a pointer or NULL.

calloc():

* Takes an element count and element size.
* Allocates storage for an array.
* Initializes allocated bytes to all bits zero.
* Returns a pointer or NULL.

Example:

int *a = malloc(5 * sizeof *a);

int *b = calloc(5, sizeof *b);

62. MALLOC VS REALLOC

malloc() creates a new allocation.

Example:

int *p = malloc(size);

realloc() changes the size of an existing allocation.

Example:

int *tmp = realloc(p, new_size);

if (tmp != NULL)
p = tmp;

63. STACK VS DYNAMIC STORAGE

Automatic storage:

* Lifetime is generally associated with entering and leaving a block.
* Management is automatic.
* Commonly implemented using a stack-like mechanism.

Dynamic allocated storage:

* Obtained through allocation functions.
* Lifetime is controlled explicitly.
* Released using an appropriate deallocation function.

The C standard defines storage duration and object lifetime; it does not require that every implementation physically implement automatic storage as a stack or allocated storage as a conventional heap.

64. CACHE LOCALITY

Contiguous arrays often provide good spatial locality.

Example:

int *data = malloc(n * sizeof *data);

Sequential access:

for (size_t i = 0; i < n; i++)
process(data[i]);

may allow hardware caches to efficiently fetch nearby elements.

Pointer-based structures may involve additional indirection and less predictable memory locations.

Actual performance depends on the workload, compiler, processor, and memory-access pattern.

65. HEAP FRAGMENTATION

Frequent allocation and deallocation of differently sized blocks can create fragmentation.

Example:

Allocate A
Allocate B
Allocate C

Free B

Allocate D

The allocator must manage free regions and may need to split or combine blocks.

For allocation-intensive applications, possible techniques include:

* Object pools.
* Memory arenas.
* Slab allocation.
* Buffer reuse.
* Batch allocation.

66. ZERO-BYTE ALLOCATION

The behavior of zero-size allocation requests is implementation- and standard-version-dependent in important details.

Portable programs should avoid relying on the returned pointer from:

malloc(0)

as usable storage.

Never dereference storage obtained from a zero-size allocation request.

If an application requires an empty dynamic array, explicitly represent the empty state using a NULL pointer and a size of zero where appropriate.

67. POINTER COMPARISON

Pointers can be compared under specific rules.

Equality comparison can be used to determine whether two pointers represent the same pointer value or whether a pointer is null.

Relational comparisons such as:

p < q

are meaningful for pointers into the same array object, subject to the C language rules.

Do not assume that arbitrary pointer addresses can be numerically ordered in a portable way.

68. POINTER CASTING

Pointer casts should be used carefully.

Example:

void *generic = &value;

int *p = generic;

No explicit cast is required for this conversion in C.

Unnecessary casts can hide errors.

Casting an arbitrary address to a pointer type does not automatically make the address valid, correctly aligned, or safe to dereference.

69. STRICT ALIASING AND OBJECT ACCESS

C has rules governing how an object may be accessed through different types.

Incorrect type-punning can result in undefined behavior.

For low-level byte inspection, character types such as unsigned char can be used to inspect the object representation of an object according to the language rules.

Example:

int value = 0x12345678;
unsigned char *bytes = (unsigned char *)&value;

The byte representation is implementation-dependent, including byte order.

70. END-OF-LIFETIME RULE

A pointer does not keep an object alive merely by storing its address.

For example:

int *p = malloc(sizeof *p);

free(p);

The pointer value may still exist as a variable, but the object that p previously referred to no longer exists.

Therefore:

*p

is invalid after the object's lifetime ends.

71. ERROR-PATH CLEANUP

Good C programs clean up partially allocated resources when an operation fails.

Example:

int *a = malloc(...);

if (a == NULL)
return 1;

int *b = malloc(...);

if (b == NULL) {
free(a);
return 1;
}

If a later operation fails, previously acquired resources should also be released.

This pattern becomes especially important in large systems programs.

72. RESOURCE OWNERSHIP MODEL

A function interface should clearly define whether it:

* Borrows a pointer.
* Takes ownership of a pointer.
* Returns newly allocated memory.
* Requires the caller to free returned memory.

Example documentation:

char *create_name(void);

Ownership rule:

"The caller owns the returned allocation and must release it using free()."

Clear ownership rules reduce memory leaks and double-free errors.

84. COMMON MISTAKES

85. INTERVIEW QUESTIONS

BEGINNER:

Q: What is a pointer?

A:
A pointer is an object that stores a value representing the address of another object or function according to the rules of C.

Q: What does & do?

A:
The & operator obtains the address of an object.

Q: What does * do?

A:
The unary * operator can access the object referred to by a valid pointer.

INTERMEDIATE:

Q: What is a void pointer?

A:
A void pointer is a generic object pointer that can hold the address of an object of any object type. It must be converted to an appropriate object-pointer type before dereferencing.

Q: What is a dangling pointer?

A:
A dangling pointer is a pointer associated with an object whose lifetime has ended, such as after dynamic storage has been released.

Q: What is the difference between malloc() and calloc()?

A:
malloc() allocates a specified number of bytes without initializing the allocated storage. calloc() allocates storage for a specified number of objects and initializes all allocated bytes to zero.

ADVANCED:

Q: Why should realloc() use a temporary pointer?

A:
If realloc() fails, it returns NULL while the original allocation remains valid. A temporary pointer prevents the original pointer from being overwritten and lost.

Q: Does free() always return memory to the operating system?

A:
No. The allocator may retain the released memory for future allocations. Returning memory to the operating system is implementation-dependent.

Q: Is casting malloc() required in C?

A:
No. malloc() returns void *, which is implicitly convertible to an object pointer in C.

Q: Why is sizeof *p useful?

A:
It obtains the size of the object pointed to by p without repeating its type name, making allocation expressions easier to maintain.

Q: What is use-after-free?

A:
Use-after-free occurs when a program accesses an object after its allocated lifetime has ended.

95. FAQ

Q: Why can sizeof(int *) and sizeof(double *) be the same?

A:
Pointer size is determined by the implementation. Different pointer types can have the same size even though they point to objects of different sizes.

Q: Is sizeof(pointer) always 8 on a 64-bit computer?

A:
No. It is common on modern 64-bit systems, but portable C code must not assume a specific pointer size.

Q: Is casting malloc() required?

A:
No. C automatically converts void * to an appropriate object pointer type.

Q: What happens if malloc() fails?

A:
malloc() returns a null pointer. The program must detect this before dereferencing the result.

Q: What happens if realloc() fails?

A:
The requested resizing does not succeed, and the original allocation remains valid.

Q: Can a pointer be used after free()?

A:
The pointer variable can still exist, but it must not be used to access the released object.

Q: Does free(NULL) cause an error?

A:
No. free(NULL) is defined to do nothing.

Q: Does free() always return memory to the operating system?

A:
No. The allocator may retain the memory for later allocations.

Q: Can a one-past-the-end pointer be dereferenced?

A:
No. It may be used for pointer comparison and iteration termination, but it does not refer to an accessible array element.

Q: Is an array the same as a pointer?

A:
No. Arrays and pointers are different types, although an array expression is converted to a pointer to its first element in many expressions.
