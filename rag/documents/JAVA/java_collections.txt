TITLE: Deep Java Collections Framework: Lists, Sets, Maps, Generics, and Internal Hash Architectures

1. Introduction
The Java Collections Framework (JCF), located in the `java.util` package, provides a unified, highly optimized architecture for representing and manipulating object collections. Built around core interfaces (`Collection`, `List`, `Set`, `Queue`, `Deque`, `Map`) and generic type parameters (`<T>`), the JCF cleanly separates abstract data contracts from concrete algorithmic implementations (`ArrayList`, `LinkedList`, `HashSet`, `TreeSet`, `HashMap`, `TreeMap`, `PriorityQueue`). Understanding internal memory representations (e.g., HashMap bucket arrays transitioning to Red-Black Trees), time complexities, fail-fast vs fail-safe iterators, custom comparators, and concurrency trade-offs is essential for high-performance enterprise Java engineering.

2. Learning Objectives
- Master the Java Collections Framework hierarchy: `Collection`, `List`, `Set`, `Queue`, `Deque`, and `Map`.
- Understand dynamic array mechanics in `ArrayList` (capacity growth factor 1.5x) vs doubly-linked `LinkedList`.
- Master `HashSet` (backed by `HashMap`), `LinkedHashSet` (insertion order), and `TreeSet` (Red-Black Tree, $O(\log N)$).
- Deeply understand `HashMap` internals: hash function spreading, bucket arrays, collision chaining, and treeification (TreeNode Red-Black trees).
- Master `TreeMap` and `PriorityQueue` (Min-Heap) mechanics.
- Implement sorting using `Comparable<T>` (natural order) and `Comparator<T>` (custom order with lambda combinators).
- Master Java Generics: Type parameters, Type Erasure, and Wildcards (`? extends T`, `? super T` / PECS principle).

3. Prerequisites
- Proficiency in Java OOP, inheritance, interfaces, and the `equals`/`hashCode` contract.

4. Core Concepts
- Collection Interface: Root interface for sequences, sets, and queues (`add`, `remove`, `contains`, `size`, `iterator`).
- Map Interface: Key-Value mapping data structure (not a subtype of `Collection`).
- Generics & Type Erasure: Compile-time type safety; the Java compiler strips generic type parameters at compile time, inserting casts and bridge methods in bytecode.
- Treeification in HashMap (Java 8+): When a hash bucket chain reaches $\ge 8$ elements and table capacity $\ge 64$, the linked list converts to a balanced Red-Black Tree, improving worst-case search from $O(N)$ to $O(\log N)$.
- Fail-Fast Iterators: Iterators that detect concurrent structural modification via `modCount` and immediately throw `ConcurrentModificationException`.

5. Detailed Theory
5.1 Deep Dive: `List` Implementations (`ArrayList` vs `LinkedList`)
1. `ArrayList<E>`:
   - Backed by an internal `Object[] elementData` array on the heap.
   - Initial capacity: 10 (when first element is added).
   - Growth Policy: `newCapacity = oldCapacity + (oldCapacity >> 1)` (1.5x growth factor).
   - Performance: $O(1)$ random access (`get(i)`), amortized $O(1)$ append (`add`), $O(N)$ middle insert/remove due to `System.arraycopy` element shifting.
2. `LinkedList<E>`:
   - Doubly-linked list composed of `Node<E>` objects (`{ E item; Node next; Node prev; }`).
   - Performance: $O(1)$ add/remove at head/tail, $O(N)$ search and index lookup. High memory overhead (24 bytes per node on 64-bit JVM) and poor cache locality.

5.2 Deep Dive: `Set` Implementations
1. `HashSet<E>`: Backed entirely by an internal `HashMap<E, Object>` where elements are keys and values are a dummy constant `PRESENT`. $O(1)$ average add/contains.
2. `LinkedHashSet<E>`: Subclass of `HashSet` maintaining a doubly-linked list across all entries to preserve insertion order.
3. `TreeSet<E>`: NavigableSet backed by a `TreeMap` (Red-Black Tree). Elements stored in sorted order. $O(\log N)$ add/remove/contains.

5.3 Deep Dive: `HashMap` Internal Architecture (Java 8+)
A `HashMap` consists of:
- `Node<K, V>[] table`: Array of bucket nodes. Default capacity: 16, default load factor: 0.75.
- Hash Function Spreading: Computes index via bitwise XOR shift:
  $$\text{hash} = (h = key.\text{hashCode}()) \oplus (h \gg 16)$$
  $$\text{index} = \text{hash} \ \& \ (\text{capacity} - 1)$$
- Collision Resolution & Treeification:
  - Collisions are initially stored as a singly-linked list in the bucket.
  - Treeify Threshold (8): If a bucket length reaches 8 and total table capacity $\ge 64$, the bucket converts to a `TreeNode` Red-Black tree.
  - Untreeify Threshold (6): If bucket elements drop to 6 during resizing, the tree converts back to a linked list.
  - Worst-case lookup time: $O(\log N)$ instead of $O(N)$.

5.4 Generics and the PECS Principle
- Producer Extends, Consumer Super (PECS):
  - `<? extends T>`: Use when you only READ (produce) data from the collection.
  - `<? super T>`: Use when you only WRITE (consume) data into the collection.
  - Invariance: `List<Dog>` is NOT a subtype of `List<Animal>`, preventing accidental runtime type corruption.

6. Syntax
- List: `List<String> list = new ArrayList<>();`
- Map: `Map<String, Integer> map = new HashMap<>();`
- Sorting: `list.sort(Comparator.comparing(Student::getGpa).reversed());`
- PriorityQueue: `Queue<Integer> pq = new PriorityQueue<>(Collections.reverseOrder());`

7. Basic Examples (Beginner Level)
```java
import java.util.List;
import java.util.ArrayList;
import java.util.Set;
import java.util.HashSet;
import java.util.Map;
import java.util.HashMap;

public class CollectionBasics {
    public static void main(String[] args) {
        // 1. List Operations
        List<String> fruits = new ArrayList<>();
        fruits.add("Apple");
        fruits.add("Banana");
        fruits.add("Cherry");
        fruits.add(1, "Blueberry");
        System.out.println("ArrayList: " + fruits);

        // 2. Set Operations (Duplicates automatically rejected)
        Set<Integer> uniqueNumbers = new HashSet<>();
        uniqueNumbers.add(10);
        uniqueNumbers.add(20);
        uniqueNumbers.add(10); // Duplicate!
        System.out.println("HashSet (Unique): " + uniqueNumbers);

        // 3. Map Operations
        Map<String, Double> prices = new HashMap<>();
        prices.put("Laptop", 1200.00);
        prices.put("Mouse", 25.50);
        prices.put("Keyboard", 75.00);

        System.out.println("Price of Laptop: $" + prices.get("Laptop"));
        System.out.println("Contains 'Monitor': " + prices.containsKey("Monitor"));
    }
}
```
Expected Output:
```
ArrayList: [Apple, Blueberry, Banana, Cherry]
HashSet (Unique): [20, 10]
Price of Laptop: $1200.0
Contains 'Monitor': false
```

8. Intermediate Examples (Custom Sorting with Comparable & Comparator and PriorityQueue)
```java
import java.util.List;
import java.util.ArrayList;
import java.util.Collections;
import java.util.Comparator;
import java.util.PriorityQueue;

class Student implements Comparable<Student> {
    private final String name;
    private final double gpa;

    public Student(String name, double gpa) {
        this.name = name;
        this.gpa = gpa;
    }

    public String getName() { return name; }
    public double getGpa() { return gpa; }

    // Natural ordering: Ascending by name
    @Override
    public int compareTo(Student other) {
        return this.name.compareTo(other.name);
    }

    @Override
    public String toString() {
        return name + " (" + gpa + ")";
    }
}

public class CollectionsSortingDemo {
    public static void main(String[] args) {
        List<Student> students = new ArrayList<>();
        students.add(new Student("Charlie", 3.75));
        students.add(new Student("Alice", 3.95));
        students.add(new Student("Bob", 3.82));

        // Natural sort by name
        Collections.sort(students);
        System.out.println("Sorted by Name (Natural): " + students);

        // Custom sort by GPA descending using Comparator Combinator (Java 8+)
        students.sort(Comparator.comparingDouble(Student::getGpa).reversed());
        System.out.println("Sorted by GPA (Descending): " + students);

        // Min-Heap Priority Queue
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();
        minHeap.offer(50);
        minHeap.offer(10);
        minHeap.offer(30);

        System.out.print("PriorityQueue Extraction: ");
        while (!minHeap.isEmpty()) {
            System.out.print(minHeap.poll() + " ");
        }
        System.out.println();
    }
}
```
Expected Output:
```
Sorted by Name (Natural): [Alice (3.95), Bob (3.82), Charlie (3.75)]
Sorted by GPA (Descending): [Alice (3.95), Bob (3.82), Charlie (3.75)]
PriorityQueue Extraction: 10 30 50 
```

9. Advanced Examples (ConcurrentModificationException and Generics PECS Wildcards)
```java
import java.util.List;
import java.util.ArrayList;
import java.util.Iterator;

public class AdvancedCollectionsDemo {
    // PECS: Producer Extends (Reading from list of any Number subtype)
    public static double sumOfNumbers(List<? extends Number> list) {
        double total = 0.0;
        for (Number n : list) {
            total += n.doubleValue(); // Reading is safe
        }
        // list.add(10); // COMPILE ERROR: cannot write to ? extends Number
        return total;
    }

    // PECS: Consumer Super (Writing integers into list of Integer supertype)
    public static void addIntegers(List<? super Integer> list) {
        list.add(100);
        list.add(200);
    }

    public static void main(String[] args) {
        List<Double> doubleList = List.of(1.5, 2.5, 3.5);
        System.out.println("Sum of doubles via <? extends Number>: " + sumOfNumbers(doubleList));

        List<Number> numList = new ArrayList<>();
        addIntegers(numList);
        System.out.println("Modified list via <? super Integer>:   " + numList);

        // Safe Element Removal using Iterator
        List<String> items = new ArrayList<>(List.of("A", "B", "REMOVE", "C"));
        Iterator<String> it = items.iterator();
        while (it.hasNext()) {
            if ("REMOVE".equals(it.next())) {
                it.remove(); // Safe removal without ConcurrentModificationException!
            }
        }
        System.out.println("List after safe iterator removal: " + items);
    }
}
```
Expected Output:
```
Sum of doubles via <? extends Number>: 7.5
Modified list via <? super Integer>:   [100, 200]
List after safe iterator removal: [A, B, C]
```

10. Line-by-Line Code Explanation
- `List<? extends Number>`: Covariant generic wildcard. Accepts `List<Integer>`, `List<Double>`, etc. Guarantees every element can be safely read as a `Number`.
- `it.remove()`: Safely removes the current element during iteration by updating both the underlying list and the iterator's internal `expectedModCount` state, avoiding `ConcurrentModificationException`.

11. Practical Programming Problems
Problem 1: Top K Elements using PriorityQueue
Find the $K$ largest elements in an unsorted array in $O(N \log K)$ time.
```java
import java.util.PriorityQueue;
import java.util.List;
import java.util.ArrayList;

public class TopKElements {
    public static List<Integer> findTopK(int[] nums, int k) {
        PriorityQueue<Integer> minHeap = new PriorityQueue<>(k);
        for (int num : nums) {
            minHeap.offer(num);
            if (minHeap.size() > k) {
                minHeap.poll();
            }
        }
        return new ArrayList<>(minHeap);
    }

    public static void main(String[] args) {
        int[] data = { 10, 5, 20, 8, 30, 2, 25 };
        System.out.println("Top 3 Largest Elements: " + findTopK(data, 3));
    }
}
```
Complexity: Time $O(N \log K)$, Space $O(K)$.

12. Real-World Applications
- In-Memory Caches: `LinkedHashMap` configured as an LRU Cache with `removeEldestEntry()`.
- Job Schedulers: `PriorityQueue` scheduling tasks by expiration timestamp.
- User Session Registries: `ConcurrentHashMap` handling millions of concurrent user lookups in enterprise web servers.

13. Common Mistakes
- Modifying Collections During For-Each Loop: Writing `for (String s : list) list.remove(s);` throws `ConcurrentModificationException`. Always use `Iterator.remove()` or `list.removeIf()`.
- Mutable Objects as HashMap Keys: Mutating fields of a key object alters its `hashCode()`, making it impossible to retrieve from the map.
- Using `LinkedList` Assuming Faster Performance: `LinkedList` has huge pointer overhead and cache-miss penalties; `ArrayList` almost always outperforms it.

14. Common Errors and Error Messages
INCORRECT EXAMPLE:
```java
// Bug: ConcurrentModificationException in for-each
List<String> list = new ArrayList<>(List.of("one", "two"));
for (String s : list) {
    if ("one".equals(s)) list.remove(s); // THROWS ConcurrentModificationException!
}
```
CORRECT VERSION:
```java
list.removeIf("one"::equals); // Safe modern Java 8+ idiom
```

15. Debugging Techniques
- Inspect Map Bucket Collisions: In debuggers, inspect `HashMap.table` array to observe bucket list/tree structures.
- Unmodifiable Wrappers: Use `Collections.unmodifiableList(list)` or `List.copyOf(list)` to catch accidental mutations immediately.

16. Edge Cases
- Null Keys in Collections: `HashMap` allows exactly 1 `null` key (stored at bucket index 0); `TreeMap` and `ConcurrentHashMap` do NOT allow null keys (throw `NullPointerException`).
- Type Erasure Bridge Methods: The compiler inserts bridge methods to preserve polymorphic overriding when generic types are erased to `Object`.

17. Best Practices
- Program to interfaces: `List<String> list = new ArrayList<>();`, not `ArrayList<String> list = new ArrayList<>();`.
- Pre-size `ArrayList` and `HashMap` when expected element counts are known (`new ArrayList<>(1000)`).
- Use immutable factory methods (`List.of()`, `Set.of()`, `Map.of()`) for static collections.

18. Performance Considerations
- Cache Locality: `ArrayList` stores contiguous references, optimizing CPU L1 cache prefetching compared to node-based collections.

19. Security Considerations
- Denial of Service via Hash Collisions: Java 8's treeification in `HashMap` guarantees $O(\log N)$ worst-case lookup, mitigating hash flooding attacks.

20. Memory Considerations
- Memory Overhead: `ArrayList` overhead is minimal ($4$ bytes per slot); `LinkedList` consumes $24$ bytes per node; `HashMap` consumes $32$ bytes per node.

21. Comparison with Related Concepts
- `HashMap` vs `TreeMap`: `HashMap` is $O(1)$ unordered hash table; `TreeMap` is $O(\log N)$ sorted Red-Black tree.
- `Comparable` vs `Comparator`: `Comparable` defines single natural ordering on the class itself (`compareTo`); `Comparator` defines external custom sorting logic (`compare`).

22. Frequently Asked Questions
Q: What is the load factor in `HashMap`?
A: The load factor (default 0.75) is the threshold ratio of elements to capacity at which the `HashMap` doubles its bucket array size to maintain $O(1)$ performance.

Q: Why does `ArrayList` grow by 1.5x instead of 2x?
A: 1.5x growth allows the memory allocator to potentially reuse previously deallocated contiguous blocks in subsequent reallocations, reducing heap fragmentation.

23. Interview Questions
Beginner:
Q: What is the difference between `ArrayList` and `LinkedList`?
A: `ArrayList` is a dynamic array providing $O(1)$ random access and cache efficiency, but $O(N)$ middle insertions. `LinkedList` is a doubly-linked list with $O(1)$ node insertion given a pointer, but $O(N)$ sequential traversal and high memory pointer overhead.

Intermediate:
Q: Explain how `HashMap.put()` works internally in Java 8+.
A: `put(K, V)` computes the key's hash spread, finds the bucket index `hash & (n - 1)`. If the bucket is empty, it creates a new Node. If populated, it traverses the bucket: if matching key is found, it updates the value; if not, it appends a new node. If bucket length reaches 8 and table capacity $\ge 64$, it converts the linked list to a Red-Black tree (`TreeNode`). If total size exceeds `capacity * loadFactor`, it rehashes the table.

Advanced:
Q: Explain the PECS principle (Producer Extends, Consumer Super) in Java Generics.
A: PECS dictates wildcard bounds: Use `? extends T` when reading data from a collection (it produces `T` items); Use `? super T` when writing data into a collection (it consumes `T` items). This allows maximum API flexibility while maintaining strict compile-time type safety.
