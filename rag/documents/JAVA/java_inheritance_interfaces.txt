TITLE: Deep Java Inheritance, Interfaces, Dynamic Method Dispatch, and Object Contracts

1. Introduction
Inheritance and interfaces provide the architectural scaffolding for polymorphism, subtyping, API contracts, and code reuse in the Java programming language. Java strictly enforces Single Class Inheritance (`extends`) to eliminate the complexities of multiple inheritance, while allowing a class to implement multiple Interfaces (`implements`) for behavioral abstraction. Dynamic Method Dispatch is resolved at runtime through virtual method tables (vtables) in the JVM. Understanding abstract classes, interface evolution (default and static interface methods), `@Override` semantics, the `super` reference, and foundational `java.lang.Object` contracts (`equals`, `hashCode`, `toString`) is vital for building extensible enterprise frameworks.

2. Learning Objectives
- Master single class inheritance with `extends`, `super()`, and superclass method invocation.
- Understand Dynamic Method Dispatch (runtime polymorphism) and `@Override` annotation semantics.
- Differentiate Abstract Classes (`abstract class`) from Interfaces (`interface`).
- Master Modern Java Interface features: Default methods (`default`), static methods, and private helper methods.
- Implement Multiple Interface inheritance and resolve interface default method naming conflicts.
- Master the `java.lang.Object` contract: proper symmetric/transitive `equals()` and consistent `hashCode()`.

3. Prerequisites
- Proficiency in Java fundamentals, methods, and OOP class design.

4. Core Concepts
- Subtyping ("is-a"): A subclass inherits member variables and methods from its superclass, establishing a subtype hierarchy.
- Dynamic Method Dispatch: The mechanism where a call to an overridden method is resolved at runtime based on the actual object instance on the heap, not the reference type.
- Abstract Class: A class that cannot be instantiated directly and may contain both abstract methods (without bodies) and concrete implemented methods with state.
- Interface: A pure behavioral contract. Since Java 8/9, interfaces can also contain default methods (`default`), static methods, and private helper methods.
- Object Contract: Overriding `equals()` requires consistently overriding `hashCode()` so that equal objects always produce identical hashcodes for hash collections (`HashMap`, `HashSet`).

5. Detailed Theory
5.1 Dynamic Method Dispatch and the JVM `invokevirtual` Opcode
In Java, all non-static, non-final, non-private methods are virtual by default:
- Calling `parentRef.display()` emits the `invokevirtual` bytecode instruction.
- At runtime, the JVM inspects the object's class metadata in the Metaspace (via its class vtable pointer) and executes the most specific subclass implementation.

5.2 Abstract Classes vs Interfaces
| Feature | Abstract Class | Interface |
| :--- | :--- | :--- |
| Inheritance | Single inheritance (`extends`) | Multiple inheritance (`implements`) |
| State / Fields | Can have instance variables (`private int x;`) | Public static final constants only |
| Constructors | Has constructors (called via `super()`) | No constructors |
| Default Logic | Concrete methods with full state access | Default methods (`default`) without state |
| Speed | Slightly faster direct vtable offset | Interface table lookup (`invokeinterface`) |

5.3 Modern Interface Evolution (Java 8, 9+)
- Default Methods (`default void log() { ... }`): Allows adding new methods to interfaces without breaking existing implementing classes.
- Static Interface Methods (`static void helper() { ... }`): Utility methods bound to the interface namespace.
- Private Interface Methods (Java 9+): Shared helper routines encapsulated inside the interface file.

5.4 The `equals()` and `hashCode()` Contract
From `java.lang.Object`:
1. `equals()` must be:
   - Reflexive: `x.equals(x)` is true.
   - Symmetric: `x.equals(y) == y.equals(x)`.
   - Transitive: If `x.equals(y)` and `y.equals(z)`, then `x.equals(z)`.
   - Consistent: Multiple calls return the same result if fields are unchanged.
   - Null-safe: `x.equals(null)` is false.
2. `hashCode()` Contract:
   - If `x.equals(y)` is true, `x.hashCode() == y.hashCode()` MUST be true.
   - If `x.equals(y)` is false, hashcodes do not have to be distinct (though distinct hashcodes improve HashMap performance).

6. Syntax
- Class Inheritance: `public class Dog extends Animal { ... }`
- Interface Implementation: `public class Circle implements Shape, Drawable { ... }`
- Interface Default Method: `default void print() { System.out.println("Default"); }`
- Calling Super: `super.makeSound();`

7. Basic Examples (Beginner Level)
```java
// Base Class
class Animal {
    protected String name;

    public Animal(String name) {
        this.name = name;
    }

    public void makeSound() {
        System.out.println(name + " makes an unspecified sound.");
    }
}

// Subclasses with Method Overriding
class Dog extends Animal {
    public Dog(String name) {
        super(name); // Invoke superclass constructor
    }

    @Override
    public void makeSound() {
        System.out.println(name + " barks: Woof! Woof!");
    }
}

class Cat extends Animal {
    public Cat(String name) {
        super(name);
    }

    @Override
    public void makeSound() {
        System.out.println(name + " meows: Meow!");
    }
}

public class InheritanceBasics {
    public static void main(String[] args) {
        // Polymorphic reference assignment
        Animal a1 = new Dog("Buddy");
        Animal a2 = new Cat("Luna");

        a1.makeSound(); // Dispatches dynamically to Dog::makeSound
        a2.makeSound(); // Dispatches dynamically to Cat::makeSound
    }
}
```
Expected Output:
```
Buddy barks: Woof! Woof!
Luna meows: Meow!
```

8. Intermediate Examples (Interfaces, Default Methods, and Conflict Resolution)
```java
interface Audible {
    void playAudio();

    // Default Method (Java 8+)
    default void checkAudioDriver() {
        System.out.println("[AUDIBLE] Audio driver is operational.");
    }
}

interface Visual {
    void renderGraphics();

    default void checkAudioDriver() {
        System.out.println("[VISUAL] Audio-visual sync driver check.");
    }
}

// Resolving Multiple Interface Default Method Conflicts
class MediaPlayer implements Audible, Visual {
    @Override
    public void playAudio() {
        System.out.println("Streaming high-fidelity audio...");
    }

    @Override
    public void renderGraphics() {
        System.out.println("Rendering 1080p 60fps video frames...");
    }

    // Must explicitly resolve conflicting default method!
    @Override
    public void checkAudioDriver() {
        System.out.println("Resolving driver conflict in MediaPlayer:");
        Audible.super.checkAudioDriver(); // Explicitly invoke Audible default implementation
    }
}

public class InterfaceDeepDive {
    public static void main(String[] args) {
        MediaPlayer player = new MediaPlayer();
        player.playAudio();
        player.renderGraphics();
        player.checkAudioDriver();
    }
}
```
Expected Output:
```
Streaming high-fidelity audio...
Rendering 1080p 60fps video frames...
Resolving driver conflict in MediaPlayer:
[AUDIBLE] Audio driver is operational.
```

9. Advanced Examples (Complete Object Contract: equals, hashCode, and toString)
```java
import java.util.Objects;
import java.util.HashSet;
import java.util.Set;

public class StudentProfile {
    private final int studentId;
    private final String fullName;
    private final String major;

    public StudentProfile(int id, String name, String major) {
        this.studentId = id;
        this.fullName = name;
        this.major = major;
    }

    @Override
    public boolean equals(Object o) {
        // 1. Check reference identity
        if (this == o) return true;
        // 2. Check null and exact class type
        if (o == null || getClass() != o.getClass()) return false;
        // 3. Cast and compare significant fields
        StudentProfile that = (StudentProfile) o;
        return studentId == that.studentId &&
               Objects.equals(fullName, that.fullName) &&
               Objects.equals(major, that.major);
    }

    @Override
    public int hashCode() {
        // Use java.util.Objects.hash for composite hashing
        return Objects.hash(studentId, fullName, major);
    }

    @Override
    public String toString() {
        return "StudentProfile[ID=" + studentId + ", Name='" + fullName + "', Major='" + major + "']";
    }

    public static void main(String[] args) {
        StudentProfile s1 = new StudentProfile(101, "Alice", "Computer Science");
        StudentProfile s2 = new StudentProfile(101, "Alice", "Computer Science");
        StudentProfile s3 = new StudentProfile(102, "Bob", "Data Science");

        System.out.println("s1.equals(s2): " + s1.equals(s2)); // true
        System.out.println("s1.hashCode() == s2.hashCode(): " + (s1.hashCode() == s2.hashCode())); // true

        // Testing HashSet duplicate elimination
        Set<StudentProfile> studentSet = new HashSet<>();
        studentSet.add(s1);
        studentSet.add(s2); // Duplicate! Rejected by HashSet!
        studentSet.add(s3);

        System.out.println("\nHashSet Contents (Size: " + studentSet.size() + "):");
        for (StudentProfile s : studentSet) {
            System.out.println("  " + s);
        }
    }
}
```
Expected Output:
```
s1.equals(s2): true
s1.hashCode() == s2.hashCode(): true

HashSet Contents (Size: 2):
  StudentProfile[ID=101, Name='Alice', Major='Computer Science']
  StudentProfile[ID=102, Name='Bob', Major='Data Science']
```

10. Line-by-Line Code Explanation
- `Audible.super.checkAudioDriver();`: Disambiguation syntax. When two implemented interfaces declare the exact same default method signature, the implementing class MUST override the method and explicitly choose which interface implementation to call using `InterfaceName.super.method()`.
- `Objects.hash(...)`: Combines individual field hash codes using prime multiplier $31$, guaranteeing consistent hash code distribution for hash table collections.

11. Practical Programming Problems
Problem 1: Payment Gateway Strategy Pattern using Interfaces
Implement a polymorphic payment processing pipeline supporting CreditCard, PayPal, and Crypto.
```java
interface PaymentStrategy {
    boolean pay(double amount);
}

class CreditCardPayment implements PaymentStrategy {
    private String cardNumber;
    public CreditCardPayment(String card) { this.cardNumber = card; }
    public boolean pay(double amount) {
        System.out.printf("Paid $%.2f via Credit Card (%s)\n", amount, cardNumber.substring(cardNumber.length()-4));
        return true;
    }
}

class CryptoPayment implements PaymentStrategy {
    private String walletAddress;
    public CryptoPayment(String wallet) { this.walletAddress = wallet; }
    public boolean pay(double amount) {
        System.out.printf("Paid $%.2f via Crypto Wallet (%s...)\n", amount, walletAddress.substring(0, 6));
        return true;
    }
}

class ShoppingCart {
    public void checkout(PaymentStrategy strategy, double total) {
        strategy.pay(total);
    }
}

public class StrategyDemo {
    public static void main(String[] args) {
        ShoppingCart cart = new ShoppingCart();
        cart.checkout(new CreditCardPayment("1234567890123456"), 120.50);
        cart.checkout(new CryptoPayment("0x71C...89A"), 450.00);
    }
}
```
Complexity: Time $O(1)$, Space $O(1)$.

13. Common Mistakes
- Overriding `equals()` without `hashCode()`: Causes objects to be lost inside `HashMap` or `HashSet` because equal objects end up in different hash buckets.
- Missing `@Override` Annotation: Renaming a base method or having slightly mismatched parameters creates an accidental overload rather than an override.
- Overusing Inheritance over Composition: Creating rigid, deeply nested inheritance hierarchies (Fragile Base Class problem).

14. Common Errors and Error Messages
INCORRECT EXAMPLE:
```java
// Bug: Overriding equals with wrong signature
public class Item {
    int id;
    public boolean equals(Item other) { // BAD: Overloads equals instead of overriding Object.equals(Object)!
        return this.id == other.id;
    }
}
```
CORRECT VERSION:
```java
public class Item {
    int id;
    @Override
    public boolean equals(Object other) { // Correct: overrides Object.equals
        if (other instanceof Item item) return this.id == item.id;
        return false;
    }
}
```

15. Debugging Techniques
- IDE Equals/HashCode Generators: Use IntelliJ/Eclipse/VSCode generators or Lombok (`@EqualsAndHashCode`) to generate bug-free object contracts.
- Bytecode Verification: Use `javap -c ClassName` to inspect `invokevirtual` vs `invokeinterface` opcodes.

16. Edge Cases
- Dynamic Dispatch in Constructors: Calling an overridable method inside a superclass constructor invokes the derived class method *before* derived fields are initialized (yielding null or zero values).
- Pattern Matching for `instanceof` (Java 16+): `if (obj instanceof Student s)` automatically tests type and casts in a single statement.

17. Best Practices
- Always use the `@Override` annotation on overriding methods.
- Always implement both `equals()` and `hashCode()` together.
- Favor composition over inheritance.
- Design interfaces with single responsibilities (SOLID Interface Segregation Principle).

18. Performance Considerations
- Monomorphic vs Polymorphic Inlining: If the JIT compiler observes that an interface call is only ever invoked on a single concrete class (Monomorphic), it de-virtualizes and inlines the call completely.

19. Security Considerations
- Malicious Method Overriding: Prevent subclasses from overriding critical security checks by marking methods as `final`.

20. Memory Considerations
- VTable Memory: Every class loaded into the JVM Metaspace maintains a virtual method table pointer array for fast method lookup.

21. Comparison with Related Concepts
- Abstract Class vs Interface: Abstract class allows stateful fields and constructor chaining; Interface allows multiple inheritance and clean API decoupling.
- Overloading vs Overriding: Overloading is compile-time in the same class; Overriding is runtime in a subclass.

22. Frequently Asked Questions
Q: Can an interface implement another interface?
A: No, an interface cannot implement another interface, but it can EXTEND one or more interfaces (`interface C extends A, B`).

Q: Why does Java not support multiple class inheritance?
A: To prevent the Diamond Problem (ambiguity regarding which parent method implementation or member variable to inherit).

23. Interview Questions
Beginner:
Q: What is the purpose of the `@Override` annotation?
A: `@Override` informs the compiler that the annotated method is intended to override a method declared in a superclass or interface. If the signature does not match, compilation fails with an error.

Intermediate:
Q: What happens if you override `equals()` but do not override `hashCode()`?
A: Equal objects may produce different hash codes. When stored in a hash-based collection (`HashMap`, `HashSet`), they will map to different hash buckets, causing `map.get(key)` to fail and duplicates to be inserted into sets.

Advanced:
Q: How does Dynamic Method Dispatch work under the hood in the JVM?
A: The JVM uses Virtual Method Tables (vtables) located in the Metaspace. Each class has a vtable pointing to its method implementations. When `invokevirtual` is executed, the JVM loads the object's vtable and performs an indirect jump via the method offset index in constant $O(1)$ time.
