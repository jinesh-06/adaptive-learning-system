TITLE: Mastering Advanced Java: Stream API, Lambdas, Concurrency, JVM Memory Model, and Garbage Collection

1. Introduction
Advanced Java systems development requires mastering functional programming paradigms introduced in Java 8+ (Lambdas, Functional Interfaces, Stream API, `Optional`), high-throughput multithreaded concurrency utilities (`java.util.concurrent`), the Java Memory Model (JMM, happens-before consistency), and JVM garbage collection internals. Through declarative stream pipelines, thread pools (`ExecutorService`), atomic variables (`AtomicInteger`), thread synchronization, and GC tuning (G1GC, ZGC), Java engineers can construct highly concurrent, low-latency, scalable enterprise architectures.

2. Learning Objectives
- Master Lambda Expressions and core Functional Interfaces (`Predicate`, `Function`, `Consumer`, `Supplier`, `UnaryOperator`).
- Implement declarative data pipelines using the Java Stream API (intermediate operations: `filter`, `map`, `flatMap`, `sorted`; terminal operations: `collect`, `reduce`, `count`).
- Master `java.util.Optional` for eliminating `NullPointerException` antipatterns.
- Implement multithreaded concurrency using `Thread`, `Runnable`, `Callable`, `Future`, and `ExecutorService` thread pools.
- Master synchronization primitives: `synchronized` blocks/methods, `volatile` memory visibility, and `ReentrantLock`.
- Understand the JVM Memory Model (Heap, Metaspace, GC Roots, Garbage First Collector / G1GC).

3. Prerequisites
- Mastery of Java fundamentals, OOP, collections, interfaces, and exception handling.

4. Core Concepts
- Functional Interface: An interface with exactly one abstract method (`@FunctionalInterface`), eligible for lambda expression binding.
- Stream API: A lazy, declarative sequence of elements supporting parallel aggregate computations.
- `Optional<T>`: A container object representing the presence or absence of a non-null value.
- Java Memory Model (JMM): The formal specification governing how threads interact through shared memory and establishing "happens-before" visibility guarantees.
- `volatile`: Guarantees that reads and writes to a variable are visible to all threads immediately by bypassing CPU register caches and preventing instruction reordering.

5. Detailed Theory
5.1 Core Functional Interfaces (`java.util.function`)
1. `Predicate<T>`: `boolean test(T t)` -> Filters conditions.
2. `Function<T, R>`: `R apply(T t)` -> Transforms type `T` to `R`.
3. `Consumer<T>`: `void accept(T t)` -> Consumes data (side effects).
4. `Supplier<T>`: `T get()` -> Factory generating values on demand.

5.2 Stream API Lifecycle & Laziness
A Stream pipeline consists of three phases:
1. Source: Collection, array, or generator (`list.stream()`).
2. Intermediate Operations (Lazy): `filter()`, `map()`, `sorted()`, `distinct()`, `limit()`. Intermediate operations are NOT executed until a terminal operation is invoked.
3. Terminal Operation (Eager): `collect(Collectors.toList())`, `forEach()`, `reduce()`, `count()`. Triggers the computation pipeline and consumes the stream.
*Rule: Streams cannot be reused after a terminal operation has executed.*

5.3 Concurrency & Thread Pools (`java.util.concurrent`)
- `ExecutorService`: High-level thread management abstraction.
  - `Executors.newFixedThreadPool(n)`: Pool of $N$ worker threads sharing an unbounded blocking queue.
  - `Executors.newCachedThreadPool()`: Dynamically spawns threads as needed.
- `Callable<V>` vs `Runnable`: `Runnable` cannot return a value or throw checked exceptions; `Callable<V>` returns a result `V` wrapped in a `Future<V>` and can throw exceptions.

5.4 JVM Memory Architecture & Garbage Collection
- Young Generation: Eden Space + Survivor Spaces (S0, S1). New objects allocated here. Minor GC cleans short-lived objects rapidly.
- Old Generation (Tenured): Objects that survive multiple Minor GCs are promoted here. Major/Full GC cleans this space.
- Metaspace: Native OS memory storing class metadata and bytecode.
- Modern Garbage Collectors:
  - G1GC (Garbage-First): Default in Java 9+. Divides heap into equal-sized regions and collects regions with the most garbage first to meet latency targets.
  - ZGC: Ultra-low latency collector with pause times $< 1$ millisecond on terabyte heaps.

6. Syntax
- Lambda: `(a, b) -> a + b`
- Stream Pipeline: `list.stream().filter(x -> x > 10).map(String::valueOf).toList();`
- Optional: `Optional.ofNullable(val).orElse("Default");`
- Thread Pool: `ExecutorService executor = Executors.newFixedThreadPool(4);`

7. Basic Examples (Beginner Level)
```java
import java.util.List;
import java.util.Optional;

public class LambdaStreamBasics {
    public static void main(String[] args) {
        List<String> names = List.of("Alice", "Bob", "Alexander", "Charlotte", "Ben");

        // Stream Pipeline: Filter names longer than 3 chars, uppercase, and collect
        List<String> longNames = names.stream()
            .filter(name -> name.length() > 3)
            .map(String::toUpperCase)
            .sorted()
            .toList();

        System.out.println("Transformed Names: " + longNames);

        // Optional demonstration
        Optional<String> optionalName = Optional.of("Sophia");
        Optional<String> emptyName = Optional.empty();

        System.out.println("Optional Value:  " + optionalName.orElse("Anonymous"));
        System.out.println("Fallback Value:  " + emptyName.orElse("Anonymous"));
    }
}
```
Expected Output:
```
Transformed Names: [ALEXANDER, ALICE, CHARLOTTE]
Optional Value:  Sophia
Fallback Value:  Anonymous
```

8. Intermediate Examples (Grouping Collectors, Reductions, and Thread Pools)
```java
import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;
import java.util.concurrent.Callable;

class Product {
    private final String category;
    private final String name;
    private final double price;

    public Product(String category, String name, double price) {
        this.category = category;
        this.name = name;
        this.price = price;
    }

    public String getCategory() { return category; }
    public String getName() { return name; }
    public double getPrice() { return price; }
}

public class StreamsAndConcurrencyDemo {
    public static void main(String[] args) throws Exception {
        List<Product> catalog = List.of(
            new Product("Electronics", "Laptop", 1200.0),
            new Product("Electronics", "Phone", 800.0),
            new Product("Books", "Java Guide", 45.0),
            new Product("Books", "Algorithms", 60.0),
            new Product("Apparel", "Shirt", 25.0)
        );

        // 1. Grouping By Category using Collectors.groupingBy
        Map<String, List<Product>> groupedByCategory = catalog.stream()
            .collect(Collectors.groupingBy(Product::getCategory));

        System.out.println("=== Products Grouped by Category ===");
        groupedByCategory.forEach((category, prods) -> {
            System.out.println("  Category: " + category + " (" + prods.size() + " items)");
        });

        // 2. Average Price Calculation using Collectors.averagingDouble
        double avgPrice = catalog.stream()
            .collect(Collectors.averagingDouble(Product::getPrice));
        System.out.printf("Average Catalog Price: $%.2f\n\n", avgPrice);

        // 3. ExecutorService Concurrency
        ExecutorService pool = Executors.newFixedThreadPool(2);
        Callable<String> task = () -> {
            Thread.sleep(20);
            return "Async Task Completed by " + Thread.currentThread().getName();
        };

        Future<String> future = pool.submit(task);
        System.out.println("Future Result: " + future.get());
        pool.shutdown();
    }
}
```
Expected Output:
```
=== Products Grouped by Category ===
  Category: Electronics (2 items)
  Category: Books (2 items)
  Category: Apparel (1 items)
Average Catalog Price: $426.00

Future Result: Async Task Completed by pool-1-thread-1
```

9. Advanced Examples (Thread Synchronization, ReentrantLock, and Atomic Variables)
```java
import java.util.concurrent.atomic.AtomicInteger;
import java.util.concurrent.locks.ReentrantLock;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.TimeUnit;

public class AdvancedConcurrencyDemo {
    private static final AtomicInteger atomicCounter = new AtomicInteger(0);
    private static int lockedCounter = 0;
    private static final ReentrantLock lock = new ReentrantLock();

    public static void incrementWithLock() {
        lock.lock(); // Explicit Lock Acquisition
        try {
            lockedCounter++;
        } finally {
            lock.unlock(); // Always unlock in finally!
        }
    }

    public static void main(String[] args) throws InterruptedException {
        ExecutorService executor = Executors.newFixedThreadPool(4);

        for (int i = 0; i < 1000; i++) {
            executor.submit(() -> {
                atomicCounter.incrementAndGet(); // Lock-free atomic hardware increment
                incrementWithLock();
            });
        }

        executor.shutdown();
        executor.awaitTermination(5, TimeUnit.SECONDS);

        System.out.println("AtomicCounter (Expected 1000): " + atomicCounter.get());
        System.out.println("LockedCounter (Expected 1000): " + lockedCounter);
    }
}
```
Expected Output:
```
AtomicCounter (Expected 1000): 1000
LockedCounter (Expected 1000): 1000
```

10. Line-by-Line Code Explanation
- `atomicCounter.incrementAndGet()`: Executes a hardware-level Compare-And-Swap (CAS) atomic CPU instruction (`LOCK XADD`), incrementing the integer without acquiring operating system thread locks.
- `lock.lock(); try { ... } finally { lock.unlock(); }`: Explicit `ReentrantLock` idiom. The `finally` block guarantees the lock is released even if an unhandled runtime exception occurs inside the critical section.

11. Practical Programming Problems
Problem 1: Parallel Word Frequency Pipeline using Streams
Count word frequencies in a list of sentences using parallel streams and concurrent collectors.
```java
import java.util.List;
import java.util.Map;
import java.util.Arrays;
import java.util.stream.Collectors;

public class ParallelWordCounter {
    public static Map<String, Long> countWords(List<String> sentences) {
        return sentences.parallelStream()
            .flatMap(s -> Arrays.stream(s.toLowerCase().split("\\s+")))
            .collect(Collectors.groupingByConcurrent(w -> w, Collectors.counting()));
    }

    public static void main(String[] args) {
        List<String> texts = List.of(
            "Java streams are fast and expressive",
            "Java concurrency enables high throughput computing",
            "Functional streams make Java powerful"
        );
        Map<String, Long> freqs = countWords(texts);
        System.out.println("Word Frequencies: " + freqs);
        System.out.println("Frequency of 'java': " + freqs.get("java"));
    }
}
```
Complexity: Time $O(N / \text{cores})$ parallelized, Space $O(U)$ unique words.

13. Common Mistakes
- Modifying Source Collections in Streams: Mutating the underlying collection while streaming causes `NullPointerException` or data corruption.
- Deadlocks via Out-of-Order Locking: Thread 1 acquires Lock A then Lock B; Thread 2 acquires Lock B then Lock A. Always acquire multiple locks in a globally consistent order.
- Forgetting to Shut Down ExecutorService: Leaks thread pool threads, preventing the JVM process from exiting cleanly.

15. Debugging Techniques
- Thread Dumps: Generate thread dumps via `jstack <pid>` to diagnose deadlocks and thread contention states.
- Stream Peek: Use `.peek(x -> System.out.println("[DEBUG] " + x))` to inspect elements flowing through intermediate stream stages.

16. Edge Cases
- Parallel Stream Overhead: Parallel streams introduce thread scheduling and split/merge overhead; on small datasets ($N < 10,000$), sequential streams are almost always faster.
- Volatile with Non-Atomic Operations: `volatile int count; count++;` is NOT thread-safe because `++` consists of three separate operations (read, increment, write). Use `AtomicInteger`.

17. Best Practices
- Use `Optional` only as a method return type; avoid using it as a field or method parameter.
- Use `Atomic` classes (`AtomicInteger`, `AtomicReference`) for simple shared counters rather than heavy synchronization.
- Always call `executor.shutdown()` when thread pools are no longer needed.

18. Performance Considerations
- G1GC Tuning: Configure `-XX:MaxGCPauseMillis=200` to direct the G1 Garbage Collector to prioritize latency-sensitive response times.

19. Security Considerations
- Thread Starvation & DoS: Limit maximum thread pool size (`newFixedThreadPool`) to prevent unbounded thread creation from exhausting JVM heap memory.

20. Memory Considerations
- Metaspace Leaks: Repeatedly loading and discarding dynamic classes without proper ClassLoader garbage collection exhausts native Metaspace RAM.

21. Comparison with Related Concepts
- `Runnable` vs `Callable`: `Runnable` returns void and cannot throw checked exceptions; `Callable` returns a generic result and can throw exceptions.
- `synchronized` vs `ReentrantLock`: `synchronized` is a language-level implicit lock; `ReentrantLock` provides timed try-locks, interruptible lock acquisition, and fair locking options.

22. Frequently Asked Questions
Q: What does the `volatile` keyword do in Java?
A: `volatile` guarantees memory visibility across threads. It instructs the JVM to read and write the variable directly to main memory rather than caching it in a CPU register, establishing a happens-before relationship.

Q: What is the difference between intermediate and terminal stream operations?
A: Intermediate operations (e.g., `filter`, `map`) are lazy and return a new Stream without executing computation; Terminal operations (e.g., `collect`, `forEach`) execute the pipeline and consume the stream.

23. Interview Questions
Beginner:
Q: What is a Functional Interface in Java?
A: A Functional Interface is an interface that contains exactly one abstract method (annotated with `@FunctionalInterface`), making it eligible to be implemented by a lambda expression or method reference.

Intermediate:
Q: What is the Java Memory Model (JMM) happens-before guarantee?
A: The happens-before guarantee states that if operation A happens-before operation B, the memory writes performed by thread A are guaranteed to be visible to thread B when B executes. Actions like unlocking a mutex or writing to a `volatile` variable establish happens-before boundaries.

Advanced:
Q: How does the G1 (Garbage-First) Garbage Collector work and how does it differ from traditional CMS/Parallel collectors?
A: G1GC partitions the JVM heap into hundreds of equal-sized virtual memory regions. It tracks which regions contain the highest proportion of garbage ("garbage first") and prioritizes collecting those specific regions during user-configured target pause intervals (`MaxGCPauseMillis`), achieving predictable, low-latency garbage collection on massive heaps.
