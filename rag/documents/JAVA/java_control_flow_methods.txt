TITLE: Deep Java Control Flow, Enhanced Switch, Methods, Overloading, and Pass-by-Value Mechanics

1. Introduction
Control flow structures and method modularity in Java govern the algorithmic decision-making, iterative looping, and procedural organization of applications. Modern Java (Java 14, 17, and 21 LTS) enhances traditional branching (`if-else`, `switch`) with modern Switch Expressions, yield statements, arrow syntax (`->`), and pattern matching. Methods encapsulate behavior, define access contracts, and support method overloading (compile-time polymorphism) and variable-length argument lists (varargs). Understanding call stack mechanics, recursion, and Java's strict pass-by-value parameter evaluation is vital for writing clean, high-performance software.

4. Core Concepts
- Branching: Diverting instruction execution based on boolean condition evaluations.
- Switch Expression (Modern Java): A switch construct that can yield a value directly into a variable without break statements or fall-through bugs.
- Enhanced For-Each Loop: Syntactic abstraction for iterating over arrays and `Iterable` collections.
- Labeled Break/Continue: Allows breaking or continuing outer nested loops from within inner loops.
- Strict Pass-by-Value: Java copies the argument value into the parameter slot. For objects, the reference pointer address is copied.
- Method Overloading: Declaring multiple methods in the same class with identical names but differing parameter types or counts.

5. Detailed Theory
5.1 Modern Switch Expressions (Java 14+)
Traditional switch statements were prone to fall-through bugs if `break` was omitted. Modern Java introduces Switch Expressions:
```java
String result = switch (day) {
    case MONDAY, FRIDAY -> "Work Mode";
    case SATURDAY, SUNDAY -> "Weekend!";
    default -> {
        String custom = "Midweek: " + day;
        yield custom; // yields value from multi-line block
    }
};
```
- Arrow syntax (`->`) automatically prevents fall-through.
- Exhaustiveness: The compiler enforces that all possible enum values or inputs are handled.

5.2 Labeled Loops
In deeply nested loops, standard `break` terminates only the innermost loop. Java supports labeled statements to control outer loops:
```java
outerLoop:
for (int i = 0; i < 5; i++) {
    for (int j = 0; j < 5; j++) {
        if (i * j > 6) break outerLoop; // Breaks out of BOTH loops
    }
}
```

5.3 Method Overloading and Resolution Hierarchy
Methods can be overloaded if their parameter lists differ in:
- Number of parameters.
- Data types of parameters.
- Order of parameter types.
*Note: Overloading based purely on return type is a compile-time error.*
Resolution Priority: 1) Exact primitive match -> 2) Widening primitive conversion -> 3) Autoboxing -> 4) Varargs (`...`).

5.4 Pass-by-Value Mechanics with Object References
When an object reference is passed to a method:
- The method receives a copy of the reference address.
- Mutating the internal state through the reference (`obj.setName("New")`) modifies the caller's object in heap memory.
- Reassigning the parameter reference variable (`obj = new Person()`) modifies only the local method pointer, having ZERO effect on the caller's variable!

7. Basic Examples (Beginner Level)
```java
public class MethodBasics {
    // Overloaded calculation methods
    public static int calculateArea(int side) {
        return side * side; // Square
    }

    public static double calculateArea(double radius) {
        return Math.PI * radius * radius; // Circle
    }

    public static int calculateArea(int length, int width) {
        return length * width; // Rectangle
    }

    public static void main(String[] args) {
        int squareArea = calculateArea(5);
        double circleArea = calculateArea(3.0);
        int rectArea = calculateArea(4, 6);

        System.out.println("Square Area (5):    " + squareArea);

        System.out.println("Rectangle Area (4x6): " + rectArea);

        // Enhanced For Loop
        int[] scores = { 92, 85, 78, 99, 88 };
        int sum = 0;
        for (int s : scores) {
            sum += s;
        }
        System.out.println("Average Score: " + (sum / (double)scores.length));
    }
}
```
Expected Output:
```

Circle Area (r=3):  28.27
Rectangle Area (4x6): 24
Average Score: 88.4
```

8. Intermediate Examples (Modern Switch Expressions and Pass-by-Value Demonstration)
```java
public class ControlFlowDeepDive {
    // Helper class for pass-by-value demonstration
    static class DataNode {
        int value;
        DataNode(int v) { this.value = v; }
    }

    public static void modifyData(int primitiveVal, DataNode nodeRef) {
        primitiveVal += 100; // Modifies only local stack copy
        nodeRef.value += 100; // Modifies object on heap!

        nodeRef = new DataNode(999); // Reassigning reference locally
    }

    public static String evaluateQuarter(int month) {
        // Modern Java 14+ Switch Expression with Arrow Syntax
        return switch (month) {
            case 1, 2, 3 -> "Q1 - Winter/Early Spring";
            case 4, 5, 6 -> "Q2 - Spring";
            case 7, 8, 9 -> "Q3 - Summer";
            case 10, 11, 12 -> "Q4 - Autumn/Winter";
            default -> {
                String errorMsg = "Invalid Month: " + month;
                yield errorMsg; // yield value from multi-line block
            }
        };
    }

    public static void main(String[] args) {
        int x = 10;
        DataNode node = new DataNode(10);

        System.out.println("Before modifyData: x=" + x + ", node.value=" + node.value);
        modifyData(x, node);
        System.out.println("After  modifyData: x=" + x + ", node.value=" + node.value);

        System.out.println("\n--- Modern Switch Evaluation ---");
        System.out.println("Month 5:  " + evaluateQuarter(5));
        System.out.println("Month 11: " + evaluateQuarter(11));
        System.out.println("Month 15: " + evaluateQuarter(15));
    }
}
```
Expected Output:
```
Before modifyData: x=10, node.value=10
After  modifyData: x=10, node.value=110

--- Modern Switch Evaluation ---
Month 5:  Q2 - Spring
Month 11: Q4 - Autumn/Winter
Month 15: Invalid Month: 15
```

9. Advanced Examples (Varargs, Labeled Search Breaks, and Tail Recursion)
```java
public class AdvancedMethods {
    // Variable-length arguments (Varargs)
    public static int sumAll(int multiplier, int... numbers) {
        int total = 0;
        for (int n : numbers) {
            total += n;
        }
        return total * multiplier;
    }

    // 2D Matrix Search using Labeled Break
    public static boolean searchMatrix(int[][] matrix, int target) {
        boolean found = false;
        searchBlock:
        for (int r = 0; r < matrix.length; r++) {
            for (int c = 0; c < matrix[r].length; c++) {
                if (matrix[r][c] == target) {
                    System.out.printf("Found target %d at row %d, col %d\n", target, r, c);
                    found = true;
                    break searchBlock; // Jump out of nested loops cleanly
                }
            }
        }
        return found;
    }

    // Tail-recursive Factorial
    public static long factorialTail(int n, long accumulator) {
        if (n <= 1) return accumulator;
        return factorialTail(n - 1, n * accumulator);
    }

    public static void main(String[] args) {
        System.out.println("Varargs calculation: " + sumAll(2, 10, 20, 30, 40));

        int[][] grid = {
            { 1, 5, 9 },
            { 14, 20, 25 },
            { 30, 42, 50 }
        };
        searchMatrix(grid, 20);

        System.out.println("Factorial(6): " + factorialTail(6, 1));
    }
}
```
Expected Output:
```
Varargs calculation: 200
Found target 20 at row 1, col 1
Factorial(6): 720
```

10. Line-by-Line Code Explanation
- `public static int sumAll(int multiplier, int... numbers)`: Varargs syntax. The compiler converts `int... numbers` into an internal array `int[] numbers`. Varargs parameters MUST be placed as the final parameter in the method signature.
- `break searchBlock;`: Labeled break statement. Immediately terminates execution of the outer `searchBlock` loop, skipping remaining rows.

11. Practical Programming Problems
Problem 1: GCD using Euclidean Algorithm
Implement the greatest common divisor function using recursion and iteration.
```java
public class GCDCalculator {
    public static int computeGCD(int a, int b) {
        while (b != 0) {
            int temp = b;
            b = a % b;
            a = temp;
        }
        return a;
    }

    public static void main(String[] args) {
        System.out.println("GCD(48, 18) = " + computeGCD(48, 18));
        System.out.println("GCD(101, 10) = " + computeGCD(101, 10));
    }
}
```
Complexity: Time $O(\log(\min(a, b)))$, Space $O(1)$.

13. Common Mistakes
- Thinking Java is Pass-by-Reference: Reassigning an object parameter inside a method (`obj = new Object()`) does NOT change the caller's reference variable!
- Overloading by Return Type Only: `int get()` and `void get()` in the same class will NOT compile.
- Fall-Through in Traditional Switch: Forgetting `break` in classical `switch` causes unintentional execution of subsequent cases.

14. Common Errors and Error Messages
INCORRECT EXAMPLE:
```java
// Bug: Overloading based purely on return type
public class BadOverload {
    public int calculate() { return 1; }
    public double calculate() { return 1.0; } // COMPILE ERROR: method calculate() is already defined
}
```
CORRECT VERSION:
```java
public class GoodOverload {
    public int calculateInt() { return 1; }
    public double calculateDouble() { return 1.0; }
}
```

15. Debugging Techniques
- Method Call Stack Inspection: In IDEs, view the Call Stack window to trace active method execution frames.
- Static Analysis: Use SonarQube or SpotBugs to catch switch fall-through vulnerabilities.

16. Edge Cases
- Ambiguous Overloading with Varargs and Primitives: Overloading `void f(long a)` and `void f(Integer a)` called with `f(5)` chooses `long` (widening) over `Integer` (autoboxing).
- StackOverflowError in Deep Recursion: Infinite or deep recursion exceeding thread stack size (typically ~10,000 frames) throws `java.lang.StackOverflowError`.

17. Best Practices
- Prefer modern Switch Expressions (`->`) over legacy switch statements to eliminate fall-through bugs.
- Place varargs as the last parameter in method signatures.
- Keep methods focused on a single responsibility (ideally $\le 30$ lines).

18. Performance Considerations
- Method Inlining: The JIT compiler automatically inlines small, frequently invoked methods, eliminating call instruction and stack frame overhead.

19. Security Considerations
- Defensive Copying: When returning mutable object references from getter methods, return a clone or copy to prevent external mutation of private state.

20. Memory Considerations
- Stack Frames: Each method call allocates a stack frame containing local variables and operands. Frames are popped automatically upon method return.

21. Comparison with Related Concepts
- Classical Switch vs Switch Expression: Classical switch uses colons and requires `break`; Switch expression uses `->`, returns a value, and guarantees no fall-through.
- Method Overloading vs Overriding: Overloading is compile-time polymorphism in the same class; Overriding is runtime polymorphism in a derived subclass (`@Override`).

22. Frequently Asked Questions
Q: Can the `main` method be overloaded in Java?
A: Yes! You can declare `public static void main(int x)`, but the JVM will strictly invoke `public static void main(String[] args)` as the application entry point.

Q: Does Java support default argument values like Python or C++?
A: No. Java achieves default arguments by overloading methods with fewer parameters that call the primary method with default values.

23. Interview Questions
Beginner:
Q: What is the difference between `break` and `continue`?
A: `break` terminates the enclosing loop entirely; `continue` skips the remainder of the current iteration and advances to the next iteration.

Intermediate:
Q: Explain why Java is strictly pass-by-value, even when passing objects.
A: When an object is passed to a method, Java copies the reference memory address value into the parameter variable. The method can modify the object's contents through this pointer, but reassigning the parameter variable points only the local copy to a new address, leaving the caller's reference unchanged.

Advanced:
Q: How does the Java compiler resolve overloaded methods when widening, autoboxing, and varargs are involved?
A: The compiler follows a strict 3-phase resolution algorithm: 1) Phase 1: Matches without boxing or varargs (widening primitives only); 2) Phase 2: Matches with autoboxing/unboxing; 3) Phase 3: Matches with varargs. If multiple ambiguous matches exist at the same phase, compilation fails.
