TITLE: Mastering Advanced C++: Templates, SFINAE, Concepts, Exception Safety, and Concurrency

1. Introduction
Advanced modern C++ combines compile-time metaprogramming, generic templates, type constraints (C++20 Concepts), robust multi-tier exception safety guarantees, and native multi-threading primitives (`std::thread`, `std::mutex`, `std::atomic`). Generic programming allows writing algorithms and data structures that operate uniformly across any compatible type with zero runtime overhead. Understanding template specialization, SFINAE (Substitution Failure Is Not An Error), C++20 Concepts, RAII lock guards, condition variables, and memory models is essential for building mission-critical systems.

2. Learning Objectives
- Master function and class templates, template specialization (full and partial), and non-type template parameters.
- Understand compile-time type introspection using `type_traits` and SFINAE (`std::enable_if`).
- Master C++20 Concepts and Constraints (`requires` clauses) for readable compile-time diagnostics.
- Master exception safety guarantees: Basic, Strong, and No-throw (`noexcept`).
- Implement native multithreading using `std::thread`, `std::jthread` (C++20), `std::mutex`, `std::unique_lock`, and `std::atomic`.
- Coordinate inter-thread communication using `std::condition_variable` and `std::future`.

3. Prerequisites
- Mastery of C++ fundamentals, OOP, smart pointers, RAII, and STL containers.

4. Core Concepts
- Generic Metaprogramming: Writing code that generates code at compile time based on types and constants.
- Template Specialization: Providing custom optimized implementations of a generic template for specific types.
- SFINAE: If an invalid type or expression occurs during template argument substitution, the compiler simply discards that overload instead of emitting a compilation error.
- Concepts (C++20): Named compile-time predicates that constrain template parameters, replacing complex SFINAE boilerplate.
- Exception Safety Guarantees: Formal contracts ensuring data structures maintain valid invariants when exceptions are thrown.
- Data Race: Two concurrent threads accessing the same memory location where at least one access is a write, without synchronization (Undefined Behavior).

5. Detailed Theory
5.1 Template Metaprogramming & Specialization
- Function Template: `template <typename T> T find_max(T a, T b);`
- Class Template: `template <typename T, size_t N> class FixedStack;`
- Full Specialization: Custom implementation for a concrete type (`template <> class FixedStack<bool, 64> { ... };`).
- Partial Specialization: Specializing on a subset of template parameters (e.g., `template <typename T> class FixedStack<T*, 100> { ... };`).

5.2 C++20 Concepts vs SFINAE
Before C++20, constraining templates required `std::enable_if_t`:
```cpp
template <typename T, typename = std::enable_if_t<std::is_integral_v<T>>>
T gcd(T a, T b);
```
In C++20, Concepts provide clean, declarative constraints:
```cpp
template <std::integral T>
T gcd(T a, T b);
```

5.3 The Four Exception Safety Levels
1. No Exception Safety: Memory leaks or corrupted invariants occur if an exception is thrown.
2. Basic Guarantee: If an exception is thrown, no resources are leaked and objects remain in a valid (though possibly unspecified) state.
3. Strong Guarantee (Commit-or-Rollback): If an operation fails, the program state is rolled back to exactly what it was before the operation began.
4. No-throw Guarantee (`noexcept`): The operation is guaranteed to succeed and will never throw an exception. Mandatory for move constructors and destructors.

5.4 Concurrency Primitives (`<thread>`, `<mutex>`, `<atomic>`)
- `std::thread`: Represents an independent execution thread. Must be `.join()`ed or `.detach()`ed before destruction.
- `std::jthread` (C++20): Automatically joins on destruction and supports cooperative cancellation tokens.
- `std::mutex`: Mutual exclusion lock. Always use RAII wrappers (`std::lock_guard` or `std::unique_lock`) to prevent deadlocks.
- `std::atomic<T>`: Lock-free atomic operations implemented via hardware CPU cache-coherency instructions.

6. Syntax
- Class Template: `template <typename T> class Queue { ... };`
- Concept: `template <typename T> concept Numeric = std::is_arithmetic_v<T>;`
- Thread Lock: `std::lock_guard<std::mutex> lock(mtx_);`
- Atomic: `std::atomic<int> counter{0}; counter.fetch_add(1);`

7. Basic Examples (Beginner Level)
```cpp
#include <iostream>
#include <string>

// Function Template
template <typename T>
T get_max(T a, T b) {
    return (a > b) ? a : b;
}

// Class Template
template <typename T>
class Box {
private:
    T value_;
public:
    explicit Box(T val) : value_(val) {}
    T get_value() const { return value_; }

int main() {
    std::cout << "Max int:    " << get_max(10, 25) << '\n';
    std::cout << "Max double: " << get_max(3.14, 2.71) << '\n';

    Box<int> int_box(100);

    std::cout << "Int Box: " << int_box.get_value() << '\n';
    std::cout << "Str Box: " << str_box.get_value() << '\n';

    return 0;
}
```
Expected Output:

```
Max double: 3.14

```

8. Intermediate Examples (C++20 Concepts and Exception-Safe RAII Locking)
```cpp
#include <iostream>
#include <concepts>
#include <thread>
#include <mutex>
#include <vector>

// C++20 Concept defining numeric printable types
template <typename T>
concept PrintableNumeric = std::integral<T> || std::floating_point<T>;

template <PrintableNumeric T>
T add_numbers(T a, T b) {
    return a + b;
}

// Thread-Safe Shared Counter
class ThreadSafeCounter {
private:
    int count_{0};
    mutable std::mutex mutex_;

public:
    void increment() {
        std::lock_guard<std::mutex> lock(mutex_); // RAII Lock
        count_++;
    }

    int get() const {
        std::lock_guard<std::mutex> lock(mutex_);
        return count_;
    }
};

int main() {
    std::cout << "Concept Add: " << add_numbers(15, 27) << '\n';
    std::cout << "Concept Add: " << add_numbers(3.5, 4.2) << '\n';
    // add_numbers("hello", "world"); // COMPILE ERROR: does not satisfy PrintableNumeric!

    ThreadSafeCounter counter;
    std::vector<std::thread> threads;

    for (int i = 0; i < 5; i++) {
        threads.emplace_back([&counter]() {
            for (int j = 0; j < 1000; j++) {
                counter.increment();
            }
        });
    }

    for (auto& t : threads) {
        t.join();
    }

    std::cout << "Final Thread-Safe Counter (Expected 5000): " << counter.get() << '\n';
    return 0;
}
```
Expected Output:
```
Concept Add: 42
Concept Add: 7.7
Final Thread-Safe Counter (Expected 5000): 5000
```

9. Advanced Examples (Producer-Consumer Thread Queue with Condition Variables)
```cpp
#include <iostream>
#include <queue>
#include <thread>
#include <mutex>
#include <condition_variable>
#include <chrono>

template <typename T>
class SafeQueue {
private:
    std::queue<T> queue_;
    mutable std::mutex mtx_;
    std::condition_variable cv_;
    bool finished_{false};

public:
    void push(T item) {
        {
            std::lock_guard<std::mutex> lock(mtx_);
            queue_.push(std::move(item));
        }
        cv_.notify_one(); // Wake up one waiting consumer thread
    }

    bool pop(T& out_item) {
        std::unique_lock<std::mutex> lock(mtx_);
        // Wait until queue has items or producer finishes
        cv_.wait(lock, [this]() {
            return !queue_.empty() || finished_;
        });

        if (queue_.empty() && finished_) {
            return false;
        }

        out_item = std::move(queue_.front());
        queue_.pop();
        return true;
    }

    void finish() {
        {
            std::lock_guard<std::mutex> lock(mtx_);
            finished_ = true;
        }
        cv_.notify_all(); // Wake up all waiting consumers
    }
};

int main() {
    SafeQueue<int> message_queue;

    // Producer Thread
    std::thread producer([&message_queue]() {
        for (int i = 1; i <= 5; ++i) {
            std::this_thread::sleep_for(std::chrono::milliseconds(10));
            std::cout << "[PRODUCER] Sent item: " << i * 100 << '\n';
            message_queue.push(i * 100);
        }
        message_queue.finish();
    });

    // Consumer Thread
    std::thread consumer([&message_queue]() {
        int item;
        while (message_queue.pop(item)) {
            std::cout << "  [CONSUMER] Processed item: " << item << '\n';
        }
        std::cout << "  [CONSUMER] Work complete. Exiting.\n";
    });

    producer.join();
    consumer.join();

    return 0;
}
```
Expected Output:
```
[PRODUCER] Sent item: 100
  [CONSUMER] Processed item: 100
[PRODUCER] Sent item: 200
  [CONSUMER] Processed item: 200
[PRODUCER] Sent item: 300
  [CONSUMER] Processed item: 300
[PRODUCER] Sent item: 400
  [CONSUMER] Processed item: 400
[PRODUCER] Sent item: 500
  [CONSUMER] Processed item: 500
  [CONSUMER] Work complete. Exiting.
```

10. Line-by-Line Code Explanation
- `std::unique_lock<std::mutex> lock(mtx_);`: Unlike `std::lock_guard`, `std::unique_lock` can be explicitly locked and unlocked, a mandatory requirement for condition variables.
- `cv_.wait(lock, [this]() { return !queue_.empty() || finished_; });`: Atomically unlocks the mutex and puts the thread to sleep. When notified, it re-acquires the lock and re-evaluates the predicate to prevent spurious wakeups.

11. Practical Programming Problems
Problem 1: Lock-Free Atomic SpinLock Implementation
Implement a lightweight lock using `std::atomic_flag`.
```cpp
#include <iostream>
#include <atomic>
#include <thread>
#include <vector>

class SpinLock {
private:
    std::atomic_flag flag_ = ATOMIC_FLAG_INIT;

public:
    void lock() {
        while (flag_.test_and_set(std::memory_order_acquire)) {
            // Spin / busy-wait until lock is released
        }
    }

    void unlock() {
        flag_.clear(std::memory_order_release);
    }
};

int main() {
    SpinLock spin;
    int shared_val = 0;

    std::vector<std::thread> threads;
    for (int i = 0; i < 4; i++) {
        threads.emplace_back([&spin, &shared_val]() {
            for (int j = 0; j < 10000; j++) {
                spin.lock();
                shared_val++;
                spin.unlock();
            }
        });
    }

    for (auto& t : threads) t.join();
    std::cout << "SpinLock protected value (Expected 40000): " << shared_val << '\n';
    return 0;
}
```
Complexity: Time $O(N)$ operations, Space $O(1)$.

12. Real-World Applications
- Game Engines: High-throughput job systems scheduling parallel rendering and physics tasks across worker threads.
- Database Engines: Lock-free ring buffers and concurrent B-Trees for million-QPS transaction logging.
- Generic Libraries (Boost, STL): Template metaprogramming generating optimized code paths tailored to data types.

13. Common Mistakes
- Deadlock via Inconsistent Lock Ordering: Thread 1 locks Mutex A then Mutex B; Thread 2 locks Mutex B then Mutex A. Solution: Use `std::lock(mtx1, mtx2)` or `std::scoped_lock` (C++17).
- Unhandled Thread Destruction: Destroying a `std::thread` before calling `.join()` or `.detach()` triggers `std::terminate()`.
- Spurious Wakeups: Forgetting the predicate in `cv.wait(lock)` causes threads to proceed when no data is actually available.

14. Common Errors and Error Messages
INCORRECT EXAMPLE:
```cpp
// Bug: Data race on raw integer
int counter = 0;
// Thread 1: counter++; Thread 2: counter++; -> DATA RACE / UNDEFINED BEHAVIOR
```
CORRECT VERSION:
```cpp
std::atomic<int> counter{0};
counter++; // Thread-safe atomic increment
```

15. Debugging Techniques
- ThreadSanitizer (TSan): Compile with `-fsanitize=thread -g` to detect data races at runtime.
- Static Assertions: Use `static_assert(sizeof(T) == 8, "Type must be 64-bit");` for compile-time validation.

16. Edge Cases
- Exception in Thread Function: An uncaught exception in a worker thread calls `std::terminate()`, killing the entire process. Wrap thread bodies in `try-catch`.
- Spurious Wakeup: Condition variables may wake up without an explicit `notify()`. Always use a while loop or predicate lambda.

17. Best Practices
- Use C++20 Concepts instead of complex SFINAE `std::enable_if` templates.
- Use `std::scoped_lock` (C++17) when acquiring multiple mutexes simultaneously.
- Mark non-throwing move constructors and destructors as `noexcept`.

18. Performance Considerations
- Template Inlining: Generic templates are compiled directly into the call site with zero virtual table indirection.
- False Sharing: Avoid placing independent `std::atomic` variables accessed by different threads on the same 64-byte CPU cache line (`alignas(64)`).

19. Security Considerations
- Data Races: Data races lead to corrupted pointers and undefined behavior. Synchronize all concurrent shared memory accesses.

20. Memory Considerations
- Code Bloat from Templates: Instantiating class templates with dozens of different types generates separate machine code for each type in the Text segment.

21. Comparison with Related Concepts
- `std::lock_guard` vs `std::unique_lock`: `lock_guard` is lightweight and non-movable; `unique_lock` supports explicit unlocking, deferred locking, and condition variables.
- SFINAE vs Concepts: SFINAE relies on obscure substitution failure tricks; Concepts provide first-class compiler-enforced type constraints with clear error messages.

22. Frequently Asked Questions
Q: What is a data race in C++?
A: A data race occurs when two or more threads access the same memory location concurrently without synchronization, and at least one of the accesses is a write. In C++, data races result in Undefined Behavior.

Q: Why should move constructors be marked `noexcept`?
A: STL containers (like `std::vector`) check `std::is_nothrow_move_constructible`. If a type's move constructor may throw, `std::vector` falls back to copying during reallocation to guarantee the Strong Exception Safety guarantee.

23. Interview Questions
Beginner:
Q: What is a template in C++?
A: A template is a blueprint for generating type-independent functions or classes at compile time.

Intermediate:
Q: What is the Strong Exception Safety guarantee?
A: It guarantees that if an operation throws an exception, the state of the program is left unchanged, exactly as it was before the operation began (commit-or-rollback semantics).

Advanced:
Q: What are C++20 Concepts and how do they improve template metaprogramming?
A: Concepts are named compile-time boolean predicates that constrain template type parameters using the `requires` clause. They replace complex SFINAE boilerplate, produce human-readable compiler diagnostic messages, and enable overloading based on constraint specificity.
