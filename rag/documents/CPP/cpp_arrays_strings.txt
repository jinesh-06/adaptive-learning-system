TITLE: Deep Modern C++ Arrays, std::vector, std::string, std::string_view, and SSO

1. Introduction
Text manipulation and sequential buffer storage in C++ have evolved far beyond unsafe C-style null-terminated arrays. Modern C++ provides a comprehensive suite of safe, high-performance container abstractions: `std::array` for fixed-size compile-time stack buffers, `std::vector` for dynamic heap arrays, `std::string` for mutable text with automatic capacity management, and `std::string_view` (C++17) for zero-copy non-owning string slicing. Understanding Small String Optimization (SSO), bounds-checked indexing, and string stream parsing is fundamental for building high-performance modern C++ applications.

2. Learning Objectives
- Differentiate `std::array`, `std::vector`, and raw C-style arrays.
- Master `std::string` member methods, capacity management (`reserve`, `shrink_to_fit`), and Small String Optimization (SSO).
- Implement zero-allocation string parsing using `std::string_view` (C++17).
- Master formatted string manipulation and type conversions using `std::stringstream`.
- Understand bounds-checked indexing (`at()`) vs direct subscript access (`[]`).

3. Prerequisites
- Proficiency in C++ fundamentals, control flow, functions, and references.

4. Core Concepts
- `std::array<T, N>`: A thin, zero-overhead wrapper over fixed-size stack arrays that provides standard STL iterator interfaces and knows its size.
- `std::vector<T>`: The default dynamic contiguous array in C++, providing amortized $O(1)$ insertions at the back.
- Small String Optimization (SSO): An internal optimization where short strings (typically $\le 15$ or $22$ characters) are stored directly inside the `std::string` object without allocating heap memory.
- `std::string_view`: A lightweight, non-owning view (pointer + length) over a contiguous sequence of characters, enabling $O(1)$ zero-copy substring slicing.

5. Detailed Theory
5.1 `std::array` vs Raw Arrays
A raw C array `int arr[10]` decays to a pointer when passed to functions, losing size metadata.
`std::array<int, 10>`:
- Allocates elements contiguously on the stack.
- Retains compile-time size: `arr.size() == 10`.
- Supports range-based for loops, STL algorithms (`std::sort`), and bounds checking via `arr.at(index)`.
- Has zero runtime memory or performance overhead compared to a raw array.

5.2 `std::string` and Small String Optimization (SSO)
A standard `std::string` object typically occupies 24 or 32 bytes on 64-bit systems:
- Long String: Stores pointer to heap buffer, size, and capacity. Allocates on heap via `new char[]`.
- Short String (SSO): Uses the internal struct bytes as the storage buffer directly. Strings shorter than 16/23 bytes require zero heap allocations, yielding extreme performance benefits.
- Capacity & Reallocation: When appending characters past `capacity()`, `std::string` reallocates a larger heap buffer (typically $1.5\times$ or $2\times$), copies existing data, and frees old memory. Use `str.reserve(n)` to preallocate capacity and eliminate reallocations.

5.3 `std::string_view` (C++17 Zero-Copy Views)
Passing a `const std::string&` requires having a materialized `std::string` object. Calling `str.substr()` creates a brand-new heap-allocated string copy ($O(N)$ time).
`std::string_view`:
- Structure: `{ const char* data; size_t length; }` (16 bytes total).
- Passed by value cheaply.
- `sv.substr(start, len)` runs in $O(1)$ time by adjusting the pointer and length without allocating any memory.
- *Caution: Does not guarantee null termination (`'\0'`). Never pass `sv.data()` directly to legacy C APIs expecting null-terminated strings without checking.*

6. Syntax
- `std::array`: `std::array<int, 5> fixed_arr = {1, 2, 3, 4, 5};`
- `std::string`: `std::string text = "Hello World";`
- `std::string_view`: `void parse(std::string_view sv);`
- `std::stringstream`: `std::stringstream ss; ss << val;`

7. Basic Examples (Beginner Level)
```cpp
#include <iostream>
#include <array>
#include <string>

int main() {
    // std::array (Stack-allocated, fixed size)
    std::array<double, 4> temperatures = { 98.6, 99.1, 98.4, 100.2 };
    std::cout << "Temperatures (Size: " << temperatures.size() << "): ";
    for (double t : temperatures) {
        std::cout << t << "F ";
    }
    std::cout << '\n';

    // std::string manipulation
    std::string phrase = "Modern C++";
    phrase += " Programming";
    phrase.insert(0, "Deep ");
    std::cout << "Constructed string: " << phrase << '\n';
    std::cout << "Length: " << phrase.length() << ", Capacity: " << phrase.capacity() << '\n';

    return 0;
}
```
Expected Output:
```
Temperatures (Size: 4): 98.6F 99.1F 98.4F 100.2F 
Constructed string: Deep Modern C++ Programming
Length: 29, Capacity: 30
```

8. Intermediate Examples (String Stream Parsing and Zero-Copy string_view)
```cpp
#include <iostream>
#include <string>
#include <string_view>
#include <sstream>
#include <vector>

// High-performance parser taking non-owning string_view
void tokenize_string_view(std::string_view sv, char delimiter) {
    std::cout << "Tokenizing view: \"" << sv << "\"\n";
    size_t start = 0;
    size_t end = sv.find(delimiter);

    while (end != std::string_view::npos) {
        std::string_view token = sv.substr(start, end - start);
        std::cout << "  Token: [" << token << "]\n";
        start = end + 1;
        end = sv.find(delimiter, start);
    }
    // Last token
    std::cout << "  Token: [" << sv.substr(start) << "]\n";
}

int main() {
    // Formatted parsing using std::stringstream
    std::string csv_row = "Alice,101,3.95,ComputerScience";
    std::stringstream ss(csv_row);
    std::string name, major;
    int id;
    double gpa;
    char comma;

    std::getline(ss, name, ',');
    ss >> id >> comma >> gpa >> comma;
    std::getline(ss, major);

    std::cout << "Parsed Record -> Name: " << name 
              << ", ID: " << id 
              << ", GPA: " << gpa 
              << ", Major: " << major << '\n';

    std::cout << "\n--- Zero-Copy string_view Tokenization ---\n";
    const char *raw_c_str = "Apple:Banana:Cherry:Dragonfruit";
    tokenize_string_view(raw_c_str, ':');

    return 0;
}
```
Expected Output:
```
Parsed Record -> Name: Alice, ID: 101, GPA: 3.95, Major: ComputerScience

--- Zero-Copy string_view Tokenization ---
Tokenizing view: "Apple:Banana:Cherry:Dragonfruit"
  Token: [Apple]
  Token: [Banana]
  Token: [Cherry]
  Token: [Dragonfruit]
```

9. Advanced Examples (SSO Verification and Custom Bounds-Checked Array Wrapper)
```cpp
#include <iostream>
#include <string>
#include <cstdlib>

// Custom global new operator to track heap allocations
void* operator new(size_t size) {
    std::cout << "  [HEAP ALLOC] Allocated " << size << " bytes on heap.\n";
    return std::malloc(size);
}

void operator delete(void* ptr) noexcept {
    std::free(ptr);
}

int main() {
    std::cout << "Creating short string (SSO candidate):\n";
    {
        std::string short_str = "Small string"; // Typically <= 15 chars -> No heap allocation!
        std::cout << "Short string: \"" << short_str 
                  << "\", length: " << short_str.length() << '\n';
    }

    std::cout << "\nCreating long string (Exceeding SSO capacity):\n";
    {
        std::string long_str = "This is a significantly longer string designed to exceed SSO buffer limits!";
        std::cout << "Long string length: " << long_str.length() 
                  << ", capacity: " << long_str.capacity() << '\n';
    }

    return 0;
}
```

10. Line-by-Line Code Explanation
- `operator new(size_t size)`: Overrides standard heap allocation to log every runtime allocation.
- `std::string short_str = "Small string";`: Stored entirely within the stack footprint of the `std::string` object due to Small String Optimization (SSO). Zero heap allocation messages are printed.
- `std::string long_str = "...";`: Exceeds the internal SSO buffer capacity, triggering a dynamic heap allocation via `operator new`.

11. Practical Programming Problems
Problem 1: Valid Palindrome Checker with string_view
Write an efficient, allocation-free function that checks if a string is a palindrome ignoring alphanumeric case and whitespace.
```cpp
#include <iostream>
#include <string_view>
#include <cctype>

bool is_palindrome(std::string_view sv) {
    if (sv.empty()) return true;
    int left = 0;
    int right = static_cast<int>(sv.length()) - 1;

    while (left < right) {
        while (left < right && !std::isalnum(sv[left])) left++;
        while (left < right && !std::isalnum(sv[right])) right--;

        if (std::tolower(sv[left]) != std::tolower(sv[right])) {
            return false;
        }
        left++;
        right--;
    }
    return true;
}

int main() {
    std::string_view phrase = "A man, a plan, a canal: Panama";
    std::cout << "\"" << phrase << "\" is palindrome: " 
              << std::boolalpha << is_palindrome(phrase) << '\n';
    return 0;
}
```
Complexity: Time $O(N)$, Space $O(1)$.

13. Common Mistakes
- Dangling `std::string_view`: Creating a `std::string_view` from a temporary `std::string` (`std::string_view sv = std::string("test") + "ing";`) leaves the view pointing to destroyed stack/heap memory.
- Subscript Indexing Out of Bounds: Using `vec[i]` on an invalid index triggers undefined behavior without throwing an exception. Use `vec.at(i)` when bounds checking is required.
- Modifying string capacity in tight loops without `reserve()`: Causes multiple reallocation and copy passes.

14. Common Errors and Error Messages
INCORRECT EXAMPLE:
```cpp
// Bug: Dangling string_view from temporary object
std::string_view get_view() {
    std::string temp = "temporary text";
    return temp; // DANGLING VIEW: temp is destroyed upon function return!
}
```
CORRECT VERSION:
```cpp
std::string get_string() {
    std::string temp = "safe text";
    return temp; // Returns full value by move/copy
}
```

15. Debugging Techniques
- AddressSanitizer: Compile with `-fsanitize=address -g` to instantly detect dangling `string_view` accesses.
- `_GLIBCXX_DEBUG`: Compile with `-D_GLIBCXX_DEBUG` in GCC to enable runtime assertions on `operator[]` bounds across all STL containers.

16. Edge Cases
- Missing Null Terminator in `string_view`: `sv.data()` does NOT guarantee a trailing `'\0'`. Passing it to `strlen()` or `printf("%s")` causes out-of-bounds reads.
- Empty Substrings: Slicing an empty range `sv.substr(0, 0)` returns an empty view with `size() == 0`.

17. Best Practices
- Pass read-only text parameters by `std::string_view` instead of `const std::string&` to accept string literals, `char[]`, and `std::string` without conversions.
- Call `str.reserve(N)` before appending data in a loop.
- Use `std::array` instead of raw C-style arrays for fixed-size stack buffers.

18. Performance Considerations
- Zero-Copy Slicing: `std::string_view::substr` performs pointer adjustment ($O(1)$) compared to `std::string::substr` ($O(N)$ allocation and copy).
- SSO Threshold: Keep short strings below 15/22 characters to avoid heap allocation overhead completely.

19. Security Considerations
- Buffer Overflows: `std::string` and `std::vector` manage their own bounds and cannot be smashed like raw C buffers.

20. Memory Considerations
- Memory Overhead: `std::string` consumes 24-32 bytes of stack memory regardless of string length. `std::vector` consumes 24 bytes (3 pointers: begin, end, capacity).

21. Comparison with Related Concepts
- `std::string` vs `std::string_view`: `std::string` owns and manages its memory buffer; `std::string_view` is a non-owning observer window.
- `std::array` vs `std::vector`: `std::array` is fixed-size on stack; `std::vector` is dynamically resizable on heap.

22. Frequently Asked Questions
Q: Why does `std::vector::at()` exist if `operator[]` is faster?
A: `at(index)` performs bounds checking and throws `std::out_of_range` on violation; `operator[]` skips bounds checks for raw execution speed.

Q: Is `std::string_view` null-terminated?
A: Not necessarily. A `string_view` created from a substring does not have a null character at its end.

23. Interview Questions
Beginner:
Q: What is the difference between `std::array` and a C-style array?
A: `std::array` is a type-safe object that knows its size (`size()`), does not automatically decay to a pointer when passed to functions, and integrates with modern STL iterators while retaining zero runtime overhead over a C array.

Intermediate:
Q: Explain Small String Optimization (SSO) in `std::string`.
A: SSO is an optimization where small strings (under 16 to 24 bytes) are stored directly inside the internal buffer of the `std::string` object itself. This avoids calling `malloc`/`new` for short strings, improving cache locality and performance.

Advanced:
Q: What are the dangers of `std::string_view` lifetimes and how can they be avoided?
A: A `std::string_view` is a non-owning reference. If the underlying `std::string` or character buffer is destroyed, reallocated, or modified, the `string_view` becomes a dangling pointer. Never bind a `string_view` to temporary rvalues or return one referencing local function stack variables.
