TITLE: Deep Modern C++ Standard Template Library (STL): Containers, Iterators, and Algorithms

1. Introduction
The Standard Template Library (STL) is the crown jewel of C++, providing a rich, mathematically principled collection of generic data structures, algorithms, iterators, and function objects. Designed by Alexander Stepanov, the STL cleanly decouples data storage (Containers) from algorithmic operations (Algorithms) via an abstract iterator interface. Understanding sequence containers (`std::vector`, `std::deque`, `std::list`), associative containers (`std::set`, `std::map`), unordered hash containers (`std::unordered_map`), iterator categories, and standard algorithms (`std::sort`, `std::lower_bound`, `std::transform`) is mandatory for high-performance software engineering and competitive programming.

2. Learning Objectives
- Master the STL container taxonomy: sequence, associative, unordered, and container adapters.
- Understand internal container mechanics, memory layouts, time complexities, and iterator invalidation rules.
- Master iterator categories: input, output, forward, bidirectional, and random access iterators.
- Utilize standard algorithms: sorting, searching, partition, transformation, and numeric reductions (`std::accumulate`).
- Implement custom sorting comparators and custom hash functions for user-defined structs in `std::unordered_map`.
- Apply competitive programming patterns: fast priority queues, binary searches, and frequency maps.

3. Prerequisites
- Proficiency in C++ fundamentals, OOP, templates basics, and operator overloading.

4. Core Concepts
- Container: A generic object that stores a collection of elements in memory.
- Iterator: A generalized pointer abstraction providing traversal over container elements.
- Algorithm: A function template performing computational operations (sorting, searching) over iterator ranges `[first, last)`.
- Functor / Lambda: Callable entities passed to STL algorithms to customize behavior.
- Iterator Invalidation: The invalidation of iterator pointers when container reallocations or structural mutations occur.

5. Detailed Theory
5.1 STL Container Taxonomy and Complexities
1. Sequence Containers:
   - `std::vector<T>`: Contiguous heap array. $O(1)$ random access, amortized $O(1)$ push_back, $O(N)$ middle insert/delete. Default choice.
   - `std::deque<T>`: Double-ended queue stored as chunks of fixed-size arrays. $O(1)$ push_front and push_back, $O(1)$ random access.
   - `std::list<T>`: Doubly-linked list. $O(1)$ insertion/deletion anywhere given an iterator, $O(N)$ non-random access, poor cache locality.
   - `std::forward_list<T>`: Singly-linked list with zero memory overhead per node beyond a single pointer.
2. Associative Containers (Self-Balancing Red-Black Trees):
   - `std::set<K>`, `std::map<K, V>`: Stored in sorted order. $O(\log N)$ search, insert, and delete. Requires `operator<`.
3. Unordered Containers (Hash Tables):
   - `std::unordered_set<K>`, `std::unordered_map<K, V>`: Array of buckets with chaining. Average $O(1)$ search, insert, delete; worst-case $O(N)$ on hash collisions. Requires `std::hash` and `operator==`.
4. Container Adapters:
   - `std::stack` (LIFO), `std::queue` (FIFO), `std::priority_queue` (Max Heap, $O(\log N)$ push/pop, $O(1)$ top).

5.2 Iterator Categories
- Input / Output: Single-pass, read or write only (`std::istream_iterator`).
- Forward: Multi-pass, forward traversal (`std::forward_list`).
- Bidirectional: Forward and backward traversal (`++`, `--`) (`std::list`, `std::set`, `std::map`).
- Random Access: $O(1)$ pointer arithmetic (`+`, `-`, `[]`) (`std::vector`, `std::deque`, `std::array`).

5.3 Iterator Invalidation Rules
- `std::vector`: `push_back()` invalidates ALL iterators and references if reallocation occurs. Deleting an element invalidates all iterators at or after the deleted element.
- `std::list` / `std::set` / `std::map`: Node-based. Insertions NEVER invalidate iterators; Deletions invalidate ONLY the iterator pointing to the erased node.

6. Syntax
- Vector: `std::vector<int> v = {1, 2, 3};`
- Map: `std::map<std::string, int> scores; scores["Alice"] = 95;`
- Unordered Map: `std::unordered_map<int, std::string> lookup;`
- Algorithm Sort: `std::sort(v.begin(), v.end(), std::greater<int>());`

7. Basic Examples (Beginner Level)
```cpp
#include <iostream>
#include <vector>
#include <map>
#include <algorithm>

int main() {
    // Vector operations
    std::vector<int> numbers = { 40, 10, 30, 50, 20 };
    numbers.push_back(60);

    // Standard Algorithm Sort
    std::sort(numbers.begin(), numbers.end());

    std::cout << "Sorted vector: ";
    for (int n : numbers) std::cout << n << ' ';
    std::cout << '\n';

    // Associative Map (Key-Value pairs in sorted order)
    std::map<std::string, int> age_map;
    age_map["Alice"] = 28;
    age_map["Bob"] = 34;
    age_map["Charlie"] = 22;

    std::cout << "Ages (alphabetical order):\n";
    for (const auto& [name, age] : age_map) {
        std::cout << "  " << name << " -> " << age << " years\n";
    }

    return 0;
}
```
Expected Output:
```
Sorted vector: 10 20 30 40 50 60 
Ages (alphabetical order):
  Alice -> 28 years
  Bob -> 34 years
  Charlie -> 22 years
```

8. Intermediate Examples (Binary Search, Priority Queue, and Transform)
```cpp
#include <iostream>
#include <vector>
#include <queue>
#include <algorithm>
#include <numeric>

int main() {
    // Priority Queue (Max-Heap by default)
    std::priority_queue<int> max_heap;
    max_heap.push(15);
    max_heap.push(45);
    max_heap.push(30);
    max_heap.push(5);

    std::cout << "Extracting from Max-Heap: ";
    while (!max_heap.empty()) {
        std::cout << max_heap.top() << ' ';
        max_heap.pop();
    }
    std::cout << '\n';

    // Binary Search Algorithms (lower_bound, upper_bound)
    std::vector<int> sorted_data = { 10, 20, 20, 20, 30, 40, 50 };
    int target = 20;

    auto low = std::lower_bound(sorted_data.begin(), sorted_data.end(), target);
    auto up  = std::upper_bound(sorted_data.begin(), sorted_data.end(), target);

    std::cout << "Target " << target << " occurs " 
              << (up - low) << " times, starting at index " 
              << (low - sorted_data.begin()) << '\n';

    // Transform algorithm
    std::vector<int> squared(sorted_data.size());
    std::transform(sorted_data.begin(), sorted_data.end(), squared.begin(), [](int x) {
        return x * x;
    });

    std::cout << "Squared elements: ";
    for (int val : squared) std::cout << val << ' ';
    std::cout << '\n';

    return 0;
}
```
Expected Output:
```
Extracting from Max-Heap: 45 30 15 5 
Target 20 occurs 3 times, starting at index 1
Squared elements: 100 400 400 400 900 1600 2500 
```

9. Advanced Examples (Custom Struct Hashing in std::unordered_map and Custom Comparator Priority Queue)
```cpp
#include <iostream>
#include <unordered_map>
#include <queue>
#include <string>

// Custom domain struct
struct Point2D {
    int x;
    int y;

    bool operator==(const Point2D& other) const {
        return x == other.x && y == other.y;
    }
};

// Custom Hash Specialization
struct Point2DHash {
    size_t operator()(const Point2D& p) const {
        // Combine hashes using bitwise XOR and prime multiplier
        return std::hash<int>()(p.x) ^ (std::hash<int>()(p.y) << 1);
    }
};

// Custom Min-Heap Job struct
struct Task {
    std::string name;
    int priority; // Lower integer = Higher Priority
};

struct TaskComparator {
    bool operator()(const Task& a, const Task& b) const {
        return a.priority > b.priority; // Min-Heap
    }
};

int main() {
    // Unordered Map with Custom Struct Key
    std::unordered_map<Point2D, std::string, Point2DHash> location_names;
    location_names[{0, 0}] = "Origin";
    location_names[{10, 20}] = "Tower Alpha";
    location_names[{5, -5}] = "Depot Beta";

    Point2D query = {10, 20};
    std::cout << "Querying location (10, 20): " << location_names[query] << '\n';

    // Min-Heap Priority Queue
    std::priority_queue<Task, std::vector<Task>, TaskComparator> task_queue;
    task_queue.push({"Garbage Collection", 5});
    task_queue.push({"Process Security Alert", 1});
    task_queue.push({"Render Frame", 3});

    std::cout << "\nProcessing High-Priority Tasks:\n";
    while (!task_queue.empty()) {
        Task top_task = task_queue.top();
        std::cout << "  [Priority " << top_task.priority << "] " << top_task.name << '\n';
        task_queue.pop();
    }

    return 0;
}
```
Expected Output:
```
Querying location (10, 20): Tower Alpha

Processing High-Priority Tasks:
  [Priority 1] Process Security Alert
  [Priority 3] Render Frame
  [Priority 5] Garbage Collection
```

10. Line-by-Line Code Explanation
- `struct Point2DHash`: Defines a custom hash functor implementing `operator()(const Point2D&)`. `std::unordered_map` requires this to compute hash bucket indices.
- `std::priority_queue<Task, std::vector<Task>, TaskComparator>`: Constructs a Min-Heap using a custom comparator. By returning `a.priority > b.priority`, the smallest priority number stays at the top of the heap.

11. Practical Programming Problems
Problem 1: Top K Frequent Elements
Given an integer array, find the $K$ most frequent elements using `std::unordered_map` and `std::priority_queue`.
```cpp
#include <iostream>
#include <vector>
#include <unordered_map>
#include <queue>

std::vector<int> top_k_frequent(const std::vector<int>& nums, int k) {
    std::unordered_map<int, int> counts;
    for (int n : nums) counts[n]++;

    // Min-heap storing pair: {frequency, number}
    using ElementPair = std::pair<int, int>;
    std::priority_queue<ElementPair, std::vector<ElementPair>, std::greater<ElementPair>> min_heap;

    for (const auto& [num, freq] : counts) {
        min_heap.push({freq, num});
        if (min_heap.size() > static_cast<size_t>(k)) {
            min_heap.pop();
        }
    }

    std::vector<int> result;
    while (!min_heap.empty()) {
        result.push_back(min_heap.top().second);
        min_heap.pop();
    }
    return result;
}

int main() {
    std::vector<int> nums = { 1, 1, 1, 2, 2, 3, 4, 4, 4, 4 };
    auto top2 = top_k_frequent(nums, 2);

    std::cout << "Top 2 most frequent numbers: ";
    for (int val : top2) std::cout << val << ' ';
    std::cout << '\n';
    return 0;
}
```
Complexity: Time $O(N \log K)$, Space $O(N)$.

13. Common Mistakes
- Accidental Insertion with `map[key]`: Accessing `map[key]` when `key` does not exist creates a new entry with a default-constructed value! Use `map.find(key)` or `map.contains(key)` (C++20) for read-only checks.
- Erasing Elements in Loops Incorrectly: In loops, `vec.erase(it)` invalidates `it`. Correct pattern: `it = vec.erase(it);` or `std::erase_if(vec, predicate)` (C++20).
- Using `std::endl` inside Algorithm Loops: Destroys performance by repeatedly flushing buffers.

14. Common Errors and Error Messages
INCORRECT EXAMPLE:
```cpp
// Bug: Iterator invalidation during erase
for (auto it = vec.begin(); it != vec.end(); ++it) {
    if (*it == target) {
        vec.erase(it); // INVALIDATES 'it'! Next ++it causes SEGFAULT!
    }
}
```
CORRECT VERSION:
```cpp
// Modern C++20 idiom
std::erase(vec, target); // Safe, optimal erase-remove idiom
```

15. Debugging Techniques
- GCC Debug Mode: Compile with `-D_GLIBCXX_DEBUG` to catch iterator invalidations and out-of-bounds container accesses at runtime.
- Valgrind: Detects memory leaks in custom container allocations.

16. Edge Cases
- Custom Map Key Missing `operator<`: If `a < b` and `b < a` both return false, `std::map` treats `a` and `b` as equivalent keys. Comparators must establish a Strict Weak Ordering.
- Hash Collisions: Adversarial input causing hash collisions degrades `std::unordered_map` from $O(1)$ to $O(N)$.

17. Best Practices
- Default to `std::vector` for sequential data due to superior CPU L1/L2 cache locality.
- Use `emplace_back()` instead of `push_back()` to construct objects in-place and avoid copy/move overhead.
- Use `std::unordered_map` when lookup speed is paramount; use `std::map` when keys must be ordered.

18. Performance Considerations
- Cache Locality: `std::vector` stores elements contiguously in RAM; node-based containers (`std::list`, `std::map`) scatter nodes across the heap, causing CPU cache misses.

19. Security Considerations
- Hash Flooding Denial of Service: Untrusted web input in `std::unordered_map` can trigger intentional hash collisions; use custom randomized hash salts for public web endpoints.

20. Memory Considerations
- Capacity Overhead: `std::vector` capacity grows geometrically ($1.5\times$ or $2\times$), consuming slightly more memory than `size()`. Use `shrink_to_fit()` when memory is tight.

21. Comparison with Related Concepts
- `std::map` vs `std::unordered_map`: `std::map` is ordered, backed by Red-Black trees ($O(\log N)$); `std::unordered_map` is unordered, backed by hash tables (average $O(1)$).
- `std::vector` vs `std::deque`: `std::vector` is single contiguous buffer; `std::deque` is a collection of fixed-size array blocks allowing $O(1)$ front/back expansion without full reallocation.

22. Frequently Asked Questions
Q: What is the Erase-Remove idiom in C++?
A: Prior to C++20, removing elements matching a predicate from a vector required `vec.erase(std::remove(vec.begin(), vec.end(), val), vec.end());`. C++20 simplifies this to `std::erase(vec, val)`.

Q: What is the difference between `push_back()` and `emplace_back()`?
A: `push_back()` accepts an already-constructed object and copies or moves it; `emplace_back()` forwards arguments directly to the element's constructor to construct it in-place in the vector's storage.

23. Interview Questions
Beginner:
Q: What are the differences between `std::vector` and `std::list`?
A: `std::vector` stores elements contiguously in memory, supporting $O(1)$ random access and cache efficiency, but $O(N)$ middle insertions. `std::list` is a doubly-linked list with $O(1)$ insertions given an iterator, but $O(N)$ sequential traversal and poor cache locality.

Intermediate:
Q: What is iterator invalidation and when does it occur in `std::vector`?
A: Iterator invalidation occurs when an operation modifies the internal structure or memory of a container, making existing iterators point to invalid or deallocated memory. In `std::vector`, adding elements past its `capacity()` reallocates the heap buffer, invalidating ALL iterators.

Advanced:
Q: What requirements must a custom comparator satisfy for `std::map` and `std::sort`?
A: It must establish a Strict Weak Ordering: 1) Irreflexivity: `comp(a, a)` is false; 2) Asymmetry: if `comp(a, b)` is true, `comp(b, a)` is false; 3) Transitivity: if `comp(a, b)` and `comp(b, c)` are true, `comp(a, c)` is true; 4) Transitivity of equivalence: if `!comp(a, b) && !comp(b, a)` and `!comp(b, c) && !comp(c, b)`, then `!comp(a, c) && !comp(c, a)`.
