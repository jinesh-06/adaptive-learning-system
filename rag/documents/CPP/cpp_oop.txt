TITLE: Deep C++ Object-Oriented Programming, Encapsulation, RAII, and Operator Overloading

1. Introduction
Object-Oriented Programming (OOP) in C++ provides a robust paradigm for domain modeling, data encapsulation, state abstraction, and deterministic resource lifecycle management. Unlike many garbage-collected object-oriented languages, C++ unifies object lifetimes with deterministic scoping through the foundational paradigm of Resource Acquisition Is Initialization (RAII). Understanding class mechanics, access control (`private`, `public`, `protected`), constructors (default, parameterized, copy, move), destructors, the `this` pointer, static members, friend functions, and operator overloading is essential for writing idiomatic, leak-free C++ code.

2. Learning Objectives
- Master class declaration, encapsulation, and access specifier visibility.
- Understand the complete object lifecycle: default constructors, member initializer lists, copy constructors, and destructors.
- Master the RAII (Resource Acquisition Is Initialization) idiom for leak-free resource management.
- Understand the `this` pointer, method chaining, `const` member functions, and mutable fields.
- Master static class members, static methods, friend functions, and friend classes.
- Implement intuitive, safe operator overloading (`operator+`, `operator==`, `operator<<`, `operator=`).

3. Prerequisites
- Proficiency in C++ fundamentals, control flow, functions, and references.

4. Core Concepts
- Encapsulation: Bundling data fields and their manipulating methods into a single class while restricting direct external access to internal state.
- Class Invariants: Conditions that must always hold true for a valid object state, enforced by constructors and methods.
- RAII: Tying resource lifecycle (heap memory, file handles, socket descriptors, mutex locks) to object lifetime, ensuring automatic release in the destructor upon scope exit.
- Member Initializer List: Initializing class members directly before the constructor body executes, avoiding redundant default construction and assignment.
- Const-Correctness: Marking methods that do not modify object state as `const` (`void print() const;`), allowing them to be invoked on `const` object instances.

5. Detailed Theory
5.1 Class Anatomy and Access Specifiers
- `private` (Default for `class`): Accessible only by member functions and declared `friend` entities.
- `public`: Accessible from any external code.
- `protected`: Accessible by member functions, friends, and derived subclasses.
*Note: In C++, a `struct` is identical to a `class`, except its default access specifier and inheritance mode are `public`.*

5.2 Object Lifecycle and the Rule of Five
Modern C++ defines special member functions generated by the compiler:
1. Default Constructor: `Class();`
2. Destructor: `~Class();`
3. Copy Constructor: `Class(const Class& other);`
4. Copy Assignment Operator: `Class& operator=(const Class& other);`
5. Move Constructor (C++11): `Class(Class&& other) noexcept;`
6. Move Assignment Operator (C++11): `Class& operator=(Class&& other) noexcept;`
The Rule of Five states that if a class manages raw resources and customizes any of these functions, it should explicitly declare or customize all five.

5.3 Member Initializer Lists
```cpp
class Account {
private:
    std::string owner_;
    const int id_;
    double balance_;
public:
    // Member Initializer List
    Account(std::string owner, int id, double bal)
        : owner_(std::move(owner)), id_(id), balance_(bal) {
        // Constructor body runs AFTER members are fully initialized
    }
};
```
Members MUST be initialized via initializer lists if they are `const`, reference types (`T&`), or classes without default constructors.

5.4 Operator Overloading Mechanics
Operators allow custom classes to behave like native primitives:
- Member Overload: Binary operators where the left-hand operand is an instance of the class (`obj1 + obj2` -> `obj1.operator+(obj2)`).
- Non-Member / Friend Overload: Essential when the left-hand operand is not your class (e.g., `std::cout << obj` -> `std::ostream& operator<<(std::ostream& os, const MyClass& obj)`).

7. Basic Examples (Beginner Level)
```cpp
#include <iostream>
#include <string>

class Rectangle {
private:
    double width_{1.0};
    double height_{1.0};

public:
    // Default Constructor
    Rectangle() = default;

    // Parameterized Constructor with Initializer List
    Rectangle(double width, double height) 
        : width_(width > 0 ? width : 1.0), height_(height > 0 ? height : 1.0) {}

    // Const Member Functions
    double get_area() const { return width_ * height_; }
    double get_perimeter() const { return 2.0 * (width_ + height_); }

    void set_dimensions(double w, double h) {
        if (w > 0) width_ = w;
        if (h > 0) height_ = h;
    }
};

int main() {
    Rectangle default_rect;
    Rectangle custom_rect(5.0, 3.0);

    std::cout << "Default Rect Area: " << default_rect.get_area() << '\n';
    std::cout << "Custom Rect Area:  " << custom_rect.get_area() << '\n';
    std::cout << "Custom Rect Perimeter: " << custom_rect.get_perimeter() << '\n';

    return 0;
}
```
Expected Output:
```
Default Rect Area: 1
Custom Rect Area:  15
Custom Rect Perimeter: 16
```

8. Intermediate Examples (RAII File Handle Wrapper and Operator Overloading)
```cpp
#include <iostream>
#include <fstream>
#include <string>

// RAII Class managing a file stream automatically
class ScopedFileWriter {
private:
    std::ofstream file_;
    std::string filename_;

public:
    explicit ScopedFileWriter(const std::string& filename) 
        : file_(filename), filename_(filename) {
        if (file_.is_open()) {
            std::cout << "[RAII] Opened file: " << filename_ << '\n';
        }
    }

    // Destructor: Automatically closes file when leaving scope
    ~ScopedFileWriter() {
        if (file_.is_open()) {
            file_.close();
            std::cout << "[RAII] Closed and flushed file: " << filename_ << '\n';
        }
    }

    void write_line(const std::string& line) {
        if (file_.is_open()) {
            file_ << line << '\n';
        }
    }
};

// Custom Complex Number with Operator Overloading
class Complex {
private:
    double real_{0.0};
    double imag_{0.0};

public:
    Complex(double r, double i) : real_(r), imag_(i) {}

    // Overload + operator
    Complex operator+(const Complex& other) const {
        return Complex(real_ + other.real_, imag_ + other.imag_);
    }

    // Overload == operator
    bool operator==(const Complex& other) const {
        return (real_ == other.real_) && (imag_ == other.imag_);
    }

    // Friend stream insertion operator
    friend std::ostream& operator<<(std::ostream& os, const Complex& c) {
        os << c.real_ << " + " << c.imag_ << "i";
        return os;
    }
};

int main() {
    {
        ScopedFileWriter writer("raii_test.txt");
        writer.write_line("Line 1: RAII Resource Management");
        writer.write_line("Line 2: Automatic deterministic destruction");
        std::cout << "Inside scope block.\n";
    } // writer destructor runs automatically HERE!

    std::cout << "Outside scope block.\n\n";

    Complex c1(3.0, 4.0);
    Complex c2(1.5, 2.5);
    Complex sum = c1 + c2;

    std::cout << "c1 = " << c1 << '\n';
    std::cout << "c2 = " << c2 << '\n';
    std::cout << "c1 + c2 = " << sum << '\n';

    return 0;
}
```
Expected Output:
```
[RAII] Opened file: raii_test.txt
Inside scope block.
[RAII] Closed and flushed file: raii_test.txt
Outside scope block.

c1 = 3 + 4i
c2 = 1.5 + 2.5i
c1 + c2 = 4.5 + 6.5i
```

9. Advanced Examples (Deep Copy vs Move Semantics and Custom Dynamic Array)
```cpp
#include <iostream>
#include <utility>
#include <algorithm>

class DynamicBuffer {
private:
    int* data_{nullptr};
    size_t size_{0};

public:
    // Parameterized Constructor
    explicit DynamicBuffer(size_t size) 
        : data_(new int[size]()), size_(size) {
        std::cout << "[ALLOC] Created buffer of size " << size_ << '\n';
    }

    // Destructor
    ~DynamicBuffer() {
        delete[] data_;
        std::cout << "[FREE] Destroyed buffer of size " << size_ << '\n';
    }

    // 1. Copy Constructor (Deep Copy)
    DynamicBuffer(const DynamicBuffer& other) 
        : data_(new int[other.size_]), size_(other.size_) {
        std::copy(other.data_, other.data_ + other.size_, data_);
        std::cout << "[COPY] Deep copied buffer of size " << size_ << '\n';
    }

    // 2. Move Constructor (Resource Theft)
    DynamicBuffer(DynamicBuffer&& other) noexcept 
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr; // Nullify source to prevent double free
        other.size_ = 0;
        std::cout << "[MOVE] Moved buffer ownership.\n";
    }

    // 3. Copy-and-Swap Assignment Operator
    DynamicBuffer& operator=(DynamicBuffer other) {
        swap(*this, other);
        std::cout << "[ASSIGN] Swapped buffer.\n";
        return *this;
    }

    friend void swap(DynamicBuffer& first, DynamicBuffer& second) noexcept {
        using std::swap;
        swap(first.data_, second.data_);
        swap(first.size_, second.size_);
    }

    size_t size() const { return size_; }
};

int main() {
    DynamicBuffer b1(5);
    DynamicBuffer b2 = b1; // Invokes Copy Constructor (Deep Copy)
    DynamicBuffer b3 = std::move(b1); // Invokes Move Constructor (Zero Allocation!)

    std::cout << "b3 size: " << b3.size() << ", b1 size after move: " << b1.size() << '\n';
    return 0;
}
```
Expected Output:
```
[ALLOC] Created buffer of size 5
[COPY] Deep copied buffer of size 5
[MOVE] Moved buffer ownership.
b3 size: 5, b1 size after move: 0
[FREE] Destroyed buffer of size 5
[FREE] Destroyed buffer of size 5
[FREE] Destroyed buffer of size 0
```

10. Line-by-Line Code Explanation
- `DynamicBuffer(const DynamicBuffer& other)`: Deep copy. Allocates brand-new heap memory and copies elements, ensuring `b1` and `b2` do not share pointers.
- `DynamicBuffer(DynamicBuffer&& other) noexcept`: Move constructor. Steals `other.data_` pointer and sets `other.data_ = nullptr`. Runs in $O(1)$ time with zero heap allocations.
- `DynamicBuffer& operator=(DynamicBuffer other)`: Copy-and-swap idiom. Automatically handles both copy-assignment and move-assignment through a single unified method.

11. Practical Programming Problems
Problem 1: Thread-Safe Singleton Pattern using Static Local Variables (Meyers' Singleton)
Implement a thread-safe singleton configuration manager in C++11.
```cpp
#include <iostream>
#include <string>

class ConfigManager {
private:
    ConfigManager() { std::cout << "ConfigManager initialized.\n"; }
    std::string app_name_{"Learning Engine"};

public:
    // Delete copy and move constructors
    ConfigManager(const ConfigManager&) = delete;
    ConfigManager& operator=(const ConfigManager&) = delete;

    // Thread-safe in C++11+
    static ConfigManager& get_instance() {
        static ConfigManager instance;
        return instance;
    }

    const std::string& get_app_name() const { return app_name_; }
};

int main() {
    ConfigManager& config1 = ConfigManager::get_instance();
    ConfigManager& config2 = ConfigManager::get_instance();
    std::cout << "App Name: " << config1.get_app_name() << '\n';
    std::cout << "Same instance address: " << std::boolalpha << (&config1 == &config2) << '\n';
    return 0;
}
```
Complexity: Time $O(1)$, Space $O(1)$.

12. Real-World Applications
- Smart Pointers (`std::unique_ptr`, `std::shared_ptr`): RAII wrappers managing dynamic heap memory.
- Mutex Locks (`std::lock_guard`, `std::unique_lock`): RAII locks acquiring mutexes on construction and unlocking on destruction.
- Database Connection Pools: Encapsulating socket state, statement caching, and transaction rollbacks.

13. Common Mistakes
- Shallow Copying Pointers: Allowing the compiler-generated copy constructor to copy raw pointers leads to a double-free crash when both destructors run.
- Forgetting `const` on Member Functions: Omitting `const` prevents methods from being called on `const` object references.
- Missing `noexcept` on Move Constructors: If a move constructor is not marked `noexcept`, `std::vector::push_back` will fall back to expensive copy operations during reallocation to provide strong exception safety.

14. Common Errors and Error Messages
INCORRECT EXAMPLE:
```cpp
// Bug: Shallow copy leading to double-free
class Buffer {
    int *data;
public:
    Buffer() : data(new int[10]) {}
    ~Buffer() { delete[] data; }
    // Missing custom copy constructor!
};
```
CORRECT VERSION:
```cpp
class Buffer {
    std::vector<int> data; // Rule of Zero: let std::vector manage memory automatically!
public:
    Buffer() : data(10) {}
};
```

15. Debugging Techniques
- AddressSanitizer: Identifies double-free and use-after-move errors.
- `= delete` Diagnostics: Clearly shows compile-time errors when accidentally copying non-copyable classes.

16. Edge Cases
- Self-Assignment (`a = a;`): Custom assignment operators must protect against freeing their own memory before copying (`if (this == &other) return *this;`).
- Order of Member Initialization: Class members are always initialized in the order they are declared in the class definition, NOT the order listed in the member initializer list.

17. Best Practices
- Follow the Rule of Zero: Prefer using modern RAII containers (`std::vector`, `std::string`, `std::unique_ptr`) so you don't have to write custom destructors or copy/move constructors.
- Follow the Rule of Five: If you write a custom destructor to manage a raw resource, implement all five special member functions.
- Mark single-argument constructors as `explicit` to prevent unintended implicit type conversions.

18. Performance Considerations
- Move Semantics: Eliminates deep copies of heavy heap containers when returning from functions or passing temporary objects.
- Inlined Getters: Short getter functions defined inside the class body are automatically inlined with zero call overhead.

19. Security Considerations
- Uninitialized Class Members: Always use in-class member initializers (`int count_{0};`) to prevent reading indeterminate stack garbage.

20. Memory Considerations
- Class Memory Layout: Non-static member variables are laid out sequentially in memory subject to padding and alignment rules; Member functions reside in the Text segment and add zero bytes to instance size.

21. Comparison with Related Concepts
- `class` vs `struct`: In C++, `class` defaults to `private` access; `struct` defaults to `public` access.
- Copy vs Move: Copy duplicates memory ($O(N)$); Move transfers pointer ownership ($O(1)$).

22. Frequently Asked Questions
Q: What does the `explicit` keyword do on a constructor?
A: It prevents the compiler from using that constructor for implicit type conversions and copy-initialization (`MyClass obj = 42;`).

Q: What is the `this` pointer?
A: `this` is a hidden implicit constant pointer passed to non-static member functions, pointing to the specific object instance on which the method was invoked.

23. Interview Questions
Beginner:
Q: What is encapsulation and how is it achieved in C++?
A: Encapsulation is the bundling of data and methods inside a class while hiding internal state using access specifiers (`private`, `protected`), exposing only safe public interfaces.

Intermediate:
Q: Explain the Rule of Five in modern C++.
A: If a class defines a custom destructor, copy constructor, or copy assignment operator, it should explicitly define or delete all five: Destructor, Copy Constructor, Copy Assignment, Move Constructor, and Move Assignment.

Advanced:
Q: Explain the Copy-and-Swap idiom and why it provides strong exception safety.
A: The Copy-and-Swap idiom implements assignment by taking the parameter by value (creating a copy) and swapping its internals with `*this` using a non-throwing `swap`. If copying fails, the exception occurs before modifying `*this`. Once swapped, the temporary's destructor cleans up the old resource cleanly.
