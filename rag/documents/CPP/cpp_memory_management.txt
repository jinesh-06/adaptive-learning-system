TITLE: Deep Modern C++ Memory Management: Smart Pointers, RAII, Move Semantics, and Ownership

1. Introduction
Memory and resource management in modern C++ represents a profound paradigm shift away from manual, error-prone `new`/`delete` allocations towards deterministic, exception-safe ownership semantics. Modern C++ manages resource lifecycles through Resource Acquisition Is Initialization (RAII), smart pointers (`std::unique_ptr`, `std::shared_ptr`, `std::weak_ptr`), move semantics, rvalue references (`T&&`), and perfect forwarding (`std::forward`). Understanding how to model exclusive vs shared ownership, resolve circular reference leaks, eliminate redundant memory copies via move constructors, and interface safely with legacy pointers is the hallmark of modern C++ expertise.

2. Learning Objectives
- Master modern dynamic allocation: `new`, `delete`, `new[]`, `delete[]`, and why raw `new`/`delete` is discouraged in modern C++.
- Understand explicit ownership semantics using `std::unique_ptr` and `std::make_unique`.
- Master reference-counted shared ownership using `std::shared_ptr` and `std::make_shared`.
- Break circular reference memory leaks using non-owning `std::weak_ptr`.
- Master move semantics, rvalue references (`&&`), `std::move`, and perfect forwarding.
- Implement custom deleters for non-memory resources (OS file handles, C library pointers).

3. Prerequisites
- Proficiency in C++ pointers, classes, destructors, and the Rule of Five.

4. Core Concepts
- Exclusive Ownership: Exactly one smart pointer owns the resource (`std::unique_ptr`). Cannot be copied, only moved.
- Shared Ownership: Multiple smart pointers share ownership of a heap resource (`std::shared_ptr`). The resource is freed when the last owning pointer is destroyed.
- Weak Reference: A non-owning observer pointer to a `std::shared_ptr` managed object (`std::weak_ptr`) that does not increment the reference count.
- Rvalue Reference (`T&&`): A reference bound to a temporary object eligible for resource theft.
- Control Block: An internal heap structure allocated alongside `std::shared_ptr` containing strong ref count, weak ref count, and allocator/deleter state.

5. Detailed Theory
5.1 Raw Memory Primitives: `new` and `delete`
- `Type *p = new Type(args);`: Allocates `sizeof(Type)` bytes on the heap via `operator new`, then invokes the constructor.
- `delete p;`: Invokes the destructor, then frees memory via `operator delete`.
- `Type *arr = new Type[N];`: Allocates buffer with array size cookie, invokes default constructors $N$ times.
- `delete[] arr;`: Invokes destructors for all $N$ elements, then frees array memory.
*Rule: Never mix `new[]` with `delete`, or `new` with `delete[]`.*

5.2 `std::unique_ptr<T>` (Exclusive Ownership)
- Zero memory overhead: `sizeof(std::unique_ptr<T>) == sizeof(T*)`.
- Non-copyable (`CopyConstructor = delete`), Move-only.
- Construction: Always use `std::make_unique<T>(args...)` (C++14) for exception safety.
- Custom Deleter: Supports custom callable cleanups (`std::unique_ptr<FILE, decltype(&fclose)> fp(fopen(...), fclose);`).

5.3 `std::shared_ptr<T>` and Control Blocks
- Size: 16 bytes (2 pointers: pointer to raw object + pointer to shared control block).
- Reference Counting: Copying increments strong count; Destruction decrements strong count. When strong count reaches 0, the managed object is destroyed.
- `std::make_shared<T>`: Performs a single contiguous heap allocation combining both the object and the control block, improving cache locality and reducing allocation overhead.

5.4 `std::weak_ptr<T>` and Circular References
If Object A holds `std::shared_ptr<B>` and Object B holds `std::shared_ptr<A>`, their strong reference counts will never drop to 0, causing a permanent memory leak.
Solution: Replace one link with `std::weak_ptr`.
- `weak_ptr` does not keep the object alive.
- To use the object, promote it safely to `shared_ptr`:
  `if (auto shared = weak.lock()) { shared->do_something(); }`

5.5 Move Semantics and `std::move`
- Lvalues: Objects with persistent memory addresses (identifiable by name).
- Rvalues: Temporary objects, expressions, or literals without persistent identity.
- `std::move(x)`: An unconditional cast converting an lvalue `x` into an rvalue `x&&`, signalling that `x`'s resources can be transferred/stolen.

6. Syntax
- Unique Pointer: `auto p = std::make_unique<Widget>(10);`
- Shared Pointer: `auto sp = std::make_shared<Widget>(20);`
- Weak Pointer: `std::weak_ptr<Widget> wp = sp;`
- Custom Deleter: `std::unique_ptr<FILE, void(*)(FILE*)> f(fopen("a.txt","r"), [](FILE* fp){ fclose(fp); });`

7. Basic Examples (Beginner Level)
```cpp
#include <iostream>
#include <memory>
#include <string>

class Resource {
public:
    std::string name_;
    explicit Resource(std::string name) : name_(std::move(name)) {
        std::cout << "[ACQUIRE] Resource '" << name_ << "' created.\n";
    }
    ~Resource() {
        std::cout << "[RELEASE] Resource '" << name_ << "' destroyed.\n";
    }
    void use() const {
        std::cout << "Using resource: " << name_ << '\n';
    }
};

int main() {
    std::cout << "--- Entering unique_ptr scope ---\n";
    {
        // Exclusive ownership
        std::unique_ptr<Resource> u_ptr = std::make_unique<Resource>("UniqueWorker");
        u_ptr->use();

        // std::unique_ptr<Resource> copy_ptr = u_ptr; // COMPILE ERROR: cannot copy unique_ptr!
        std::unique_ptr<Resource> moved_ptr = std::move(u_ptr); // Transfer ownership
        if (!u_ptr) {
            std::cout << "u_ptr is now null after std::move.\n";
        }
        moved_ptr->use();
    } // moved_ptr automatically calls ~Resource() HERE!

    std::cout << "--- Exited unique_ptr scope ---\n";
    return 0;
}
```
Expected Output:
```
--- Entering unique_ptr scope ---
[ACQUIRE] Resource 'UniqueWorker' created.
Using resource: UniqueWorker
u_ptr is now null after std::move.
Using resource: UniqueWorker
[RELEASE] Resource 'UniqueWorker' destroyed.
--- Exited unique_ptr scope ---
```

8. Intermediate Examples (Shared Pointers, Reference Counting, and Weak Pointers)
```cpp
#include <iostream>
#include <memory>

class Node {
public:
    int id_;
    std::shared_ptr<Node> next_;
    std::weak_ptr<Node> prev_; // Use weak_ptr to prevent circular reference leak!

    explicit Node(int id) : id_(id) {
        std::cout << "Node " << id_ << " created.\n";
    }
    ~Node() {
        std::cout << "Node " << id_ << " destroyed.\n";
    }
};

int main() {
    std::cout << "--- Shared Ownership Demo ---\n";
    std::shared_ptr<Node> node1 = std::make_shared<Node>(1);
    {
        std::shared_ptr<Node> node2 = std::make_shared<Node>(2);

        node1->next_ = node2;
        node2->prev_ = node1; // weak_ptr binding

        std::cout << "node1 use_count: " << node1.use_count() << '\n';
        std::cout << "node2 use_count: " << node2.use_count() << '\n';

        // Access node1 from node2 via weak_ptr lock
        if (auto locked_node1 = node2->prev_.lock()) {
            std::cout << "Successfully accessed node1 from node2. ID: " 
                      << locked_node1->id_ << '\n';
        }
    } // node2 destroyed cleanly without circular leak!

    std::cout << "After inner scope, node1 use_count: " << node1.use_count() << '\n';
    return 0;
}
```
Expected Output:
```
--- Shared Ownership Demo ---
Node 1 created.
Node 2 created.
node1 use_count: 1
node2 use_count: 2
Successfully accessed node1 from node2. ID: 1
Node 2 destroyed.
After inner scope, node1 use_count: 1
Node 1 destroyed.
```

9. Advanced Examples (Custom Deleters for C Handles and Perfect Forwarding)
```cpp
#include <iostream>
#include <memory>
#include <utility>

// Custom C-Style File Deleter
struct CFileDeleter {
    void operator()(FILE* fp) const {
        if (fp) {
            std::fclose(fp);
            std::cout << "[RAII] fclose called on FILE* handle.\n";
        }
    }
};

using UniqueFile = std::unique_ptr<FILE, CFileDeleter>;

UniqueFile open_safe_file(const char* path, const char* mode) {
    FILE* fp = std::fopen(path, mode);
    return UniqueFile(fp);
}

// Perfect Forwarding Factory Template
template <typename T, typename... Args>
std::unique_ptr<T> make_custom_unique(Args&&... args) {
    // std::forward preserves lvalue/rvalue value category
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}

struct SensorData {
    int sensor_id;
    double calibration_factor;
    SensorData(int id, double cal) : sensor_id(id), calibration_factor(cal) {
        std::cout << "SensorData initialized (" << sensor_id << ", " << calibration_factor << ")\n";
    }
};

int main() {
    {
        UniqueFile my_file = open_safe_file("smart_file_test.txt", "w");
        if (my_file) {
            std::fputs("Testing safe custom smart pointer deleter.\n", my_file.get());
        }
    } // CFileDeleter automatically executes fclose()!

    auto sensor = make_custom_unique<SensorData>(101, 1.045);
    std::cout << "Sensor ID: " << sensor->sensor_id << '\n';

    return 0;
}
```
Expected Output:
```
[RAII] fclose called on FILE* handle.
SensorData initialized (101, 1.045)
Sensor ID: 101
```

10. Line-by-Line Code Explanation
- `using UniqueFile = std::unique_ptr<FILE, CFileDeleter>;`: Defines a smart pointer type holding a C standard `FILE*` handle, executing `CFileDeleter::operator()` automatically upon scope exit.
- `std::forward<Args>(args)...`: Universal reference forwarding. Preserves exact lvalue/rvalue qualifiers of arguments when passing them to the constructor.

11. Practical Programming Problems
Problem 1: Thread-Safe Object Cache using weak_ptr
Implement an object cache where instances are shared if currently in use, and recreated on-demand if expired.
```cpp
#include <iostream>
#include <memory>
#include <unordered_map>
#include <string>

class HeavyAsset {
public:
    std::string name_;
    explicit HeavyAsset(std::string name) : name_(std::move(name)) {
        std::cout << "[ASSET] Loaded heavy asset: " << name_ << '\n';
    }
    ~HeavyAsset() {
        std::cout << "[ASSET] Unloaded heavy asset: " << name_ << '\n';
    }
};

class AssetManager {
private:
    std::unordered_map<std::string, std::weak_ptr<HeavyAsset>> cache_;

public:
    std::shared_ptr<HeavyAsset> get_asset(const std::string& name) {
        auto it = cache_.find(name);
        if (it != cache_.end()) {
            if (auto shared = it->second.lock()) {
                std::cout << "Cache Hit for '" << name << "'!\n";
                return shared;
            }
        }

        std::cout << "Cache Miss for '" << name << "'. Loading...\n";
        auto new_asset = std::make_shared<HeavyAsset>(name);
        cache_[name] = new_asset;
        return new_asset;
    }
};

int main() {
    AssetManager manager;
    {
        auto asset1 = manager.get_asset("texture_hero.png");
        auto asset2 = manager.get_asset("texture_hero.png"); // Cache hit
    } // Asset destroyed here!

    // Next request is a cache miss because asset was deallocated
    auto asset3 = manager.get_asset("texture_hero.png");
    return 0;
}
```
Complexity: Time $O(1)$ average lookup, Space $O(N)$ cached entries.

13. Common Mistakes
- Creating Multiple `std::shared_ptr` from the Same Raw Pointer:
  `int *raw = new int(5); std::shared_ptr<int> sp1(raw); std::shared_ptr<int> sp2(raw);`
  Creates TWO separate control blocks! Both try to `delete raw`, resulting in a fatal double-free crash.
- Calling `.get()` and Deleting Raw Pointer: Calling `delete ptr.get()` causes double deletion when the smart pointer exits scope.
- Using `std::shared_ptr` when `std::unique_ptr` Suffices: `shared_ptr` incurs control block allocation and atomic reference count synchronization overhead.

14. Common Errors and Error Messages
INCORRECT EXAMPLE:
```cpp
// Bug: Circular shared_ptr reference causing permanent memory leak
struct A; struct B;
struct A { std::shared_ptr<B> b; ~A() { std::cout << "~A\n"; } };
struct B { std::shared_ptr<A> a; ~B() { std::cout << "~B\n"; } };
// Neither destructor ever runs!
```
CORRECT VERSION:
```cpp
struct B { std::weak_ptr<A> a; ~B() { std::cout << "~B\n"; } }; // Break cycle with weak_ptr
```

15. Debugging Techniques
- AddressSanitizer: Identifies memory leaks and heap-use-after-free conditions.
- Track `use_count()`: Inspect `sp.use_count()` to debug unexpected pointer retention.

16. Edge Cases
- Custom Array Deleters: `std::unique_ptr<int[]>` automatically uses `delete[]`; `std::shared_ptr<int[]>` in C++17+ also supports arrays natively.
- Passing `unique_ptr` by Value vs Reference: Passing by value transfers ownership (requires `std::move`); Passing by `const std::unique_ptr<T>&` observes without ownership change.

17. Best Practices
- Prefer `std::unique_ptr` by default; upgrade to `std::shared_ptr` only when shared lifetime is genuinely required.
- Always construct smart pointers using `std::make_unique` and `std::make_shared`.
- Never use raw `new` and `delete` in modern application code.

18. Performance Considerations
- `std::make_shared` Optimization: Allocates the managed object and control block in a single heap chunk, cutting memory allocations in half and optimizing CPU cache lines.

19. Security Considerations
- Memory Safety: Smart pointers eliminate 95%+ of memory leak, double free, and dangling pointer vulnerabilities when used consistently.

20. Memory Considerations
- `std::unique_ptr` Overhead: 0 bytes overhead over raw pointer.
- `std::shared_ptr` Overhead: 16 bytes stack + control block heap allocation.

21. Comparison with Related Concepts
- `std::unique_ptr` vs `std::shared_ptr`: `unique_ptr` is single-owner, zero-overhead, non-copyable; `shared_ptr` is multi-owner, ref-counted, copyable.
- `std::weak_ptr` vs Raw Pointer: `weak_ptr` safely tracks object lifetime and detects if the target has been deleted via `.expired()` or `.lock()`; raw pointers cannot detect deallocation.

22. Frequently Asked Questions
Q: Why should `std::make_unique` be preferred over `std::unique_ptr<T>(new T())`?
A: `std::make_unique` guarantees exception safety by preventing resource leaks if an exception is thrown during parameter evaluation before the pointer takes ownership.

Q: Is `std::shared_ptr` thread-safe?
A: The reference count manipulation is thread-safe (uses atomic CPU instructions), but accessing the underlying object itself requires synchronization (e.g., `std::mutex`).

23. Interview Questions
Beginner:
Q: What is a smart pointer in C++?
A: A smart pointer is an RAII template class wrapping a raw pointer that automatically manages the allocation and deallocation of the underlying memory, freeing resources when the smart pointer object goes out of scope.

Intermediate:
Q: What is the purpose of `std::weak_ptr` and how is it used?
A: `std::weak_ptr` provides a non-owning reference to an object managed by `std::shared_ptr`. It is primarily used to break circular reference memory leaks and implement caches. To access the object, it is converted to a `shared_ptr` via `.lock()`.

Advanced:
Q: Explain how move semantics (`rvalue references`) and `std::forward` enable perfect forwarding.
A: An rvalue reference (`T&&`) binds to temporary objects. In a template function taking `Args&&... args` (a forwarding/universal reference), `args` can represent both lvalues and rvalues. `std::forward<Args>(arg)` casts `arg` back to an rvalue only if the original argument was an rvalue, preserving exact value categories during forwarding.
