TITLE: C++ Inheritance and Dynamic Polymorphism: Vtables, Abstract Classes, and Virtual Destructors

1. Introduction
Inheritance and polymorphism are the defining principles of Object-Oriented Programming that enable code reuse, extensible architectures, and runtime dynamic dispatch. Inheritance allows a derived (child) class to inherit properties and behaviors from a base (parent) class. Polymorphism ("many forms") enables a single interface to control general categories of actions, with specific behaviors determined either at compile time (static polymorphism via templates/overloading) or runtime (dynamic polymorphism via virtual functions). Understanding virtual method tables (vtables), virtual pointers (vptrs), pure virtual functions, abstract classes, virtual destructors, and multiple inheritance diamond resolution is critical for building extensible frameworks in C++.

2. Learning Objectives
By studying this module, learners will:
- Master base and derived class hierarchies and access specifier inheritance modes (`public`, `protected`, `private`).
- Differentiate between single, multiple, multilevel, hierarchical, and hybrid inheritance models.
- Implement runtime polymorphism using `virtual` member functions and the `override` specifier.
- Understand the internal mechanics of Virtual Method Tables (`vtable`) and Virtual Table Pointers (`vptr`).
- Design abstract classes and interface contracts using Pure Virtual Functions (`= 0`).
- Resolve the "Diamond Problem" using virtual base classes (`virtual public Base`).
- Implement virtual destructors to prevent partial object deletion and memory leaks.
- Apply runtime type identification (`dynamic_cast`) safely.

3. Core Concepts
- Base vs Derived Class: Base defines common attributes and interfaces; Derived specializes or extends functionality.
- Virtual Functions (`virtual`): Functions whose execution target is resolved dynamically at runtime based on the actual type of the underlying object.
- Vtable / Vptr: An array of function pointers generated by the compiler per polymorphic class; each object contains a hidden `vptr` pointing to its class `vtable`.
- Pure Virtual Function (`virtual void func() = 0`): A function with no implementation in the base class, making the class Abstract.
- Abstract Class: A class with at least one pure virtual function; cannot be directly instantiated.
- Virtual Destructor: Guarantees that when deleting a derived object via a base pointer, the derived destructor executes first before the base destructor.

4. Detailed Explanation
4.1 Inheritance Access Modes
- `public` inheritance: Models an "is-a" relationship (public members of base stay public, protected stay protected).
- `protected` inheritance: Public and protected members of base become protected in derived.
- `private` inheritance: Public and protected members of base become private in derived (models implementation inheritance).

4.2 Dynamic Dispatch Mechanics (Vtable & Vptr)
When a class declares a virtual function:
1. Compiler creates a static table of function pointers (`vtable`) for that class.
2. Compiler inserts an implicit pointer (`vptr`) into every instance of the class (usually at byte offset 0).
3. When invoking `base_ptr->draw()`, the CPU looks up `vptr -> vtable[index]` and dispatches to the derived implementation at runtime ($O(1)$ overhead).

4.3 Pure Virtual Functions and Interfaces
`class Shape { public: virtual double area() const = 0; virtual ~Shape() {} };`
Any derived class (e.g., `Circle`, `Rectangle`) MUST override `area()` to be instantiable.

4.4 The Diamond Problem
Occurs when class `D` inherits from both `B` and `C`, which both inherit from `A`. Without `virtual` inheritance, `D` receives two duplicate copies of `A`.
Resolution: `class B : virtual public A { ... };` and `class C : virtual public A { ... };`.

5. Syntax
5.1 Polymorphic Hierarchy
class Base {
public:
    virtual void show() const { std::cout << "Base\n"; }
    virtual ~Base() = default; // Critical for polymorphic base classes
};

class Derived : public Base {
public:
    void show() const override { std::cout << "Derived\n"; }
};

6. Basic Examples
Example 6.1: Basic Inheritance and Method Overriding
#include <iostream>
#include <string>

class Vehicle {
protected:
    std::string brand;
    int year;

public:
    Vehicle(const std::string &b, int y) : brand(b), year(y) {}

    virtual void display_info() const {
        std::cout << year << " " << brand << " (Generic Vehicle)
";
    }

    virtual ~Vehicle() = default;
};

class Car : public Vehicle {
private:
    int num_doors;

public:
    Car(const std::string &b, int y, int doors)
        : Vehicle(b, y), num_doors(doors) {}

    void display_info() const override {
        std::cout << year << " " << brand << " Car with " << num_doors << " doors.
";
    }
};

int main() {
    Vehicle v("GenericMotors", 2020);
    Car c("Tesla", 2026, 4);

    v.display_info();
    c.display_info();
    return 0;
}

7. Intermediate Examples
Example 7.1: Abstract Class, Pure Virtual Functions, and Dynamic Dispatch
#include <iostream>
#include <vector>
#include <memory>

class Shape {
public:
    virtual double area() const = 0; // Pure virtual function
    virtual void render() const = 0;
    virtual ~Shape() = default;
};

class Circle : public Shape {
private:
    double radius;
public:
    Circle(double r) : radius(r) {}
    double area() const override { return 3.14159 * radius * radius; }
    void render() const override { std::cout << "Rendering Circle (r=" << radius << ") | Area: " << area() << "
"; }
};

class Rectangle : public Shape {
private:
    double width, height;
public:
    Rectangle(double w, double h) : width(w), height(h) {}
    double area() const override { return width * height; }
    void render() const override { std::cout << "Rendering Rectangle (" << width << "x" << height << ") | Area: " << area() << "
"; }
};

int main() {
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Circle>(5.0));
    shapes.push_back(std::make_unique<Rectangle>(4.0, 6.0));

    for (const auto &shape : shapes) {
        shape->render(); // Polymorphic dynamic dispatch
    }
    return 0;
}

8. Advanced Examples
Example 8.1: Virtual Destructors and Memory Leak Prevention
#include <iostream>

class BaseWithoutVirtualDestructor {
public:
    BaseWithoutVirtualDestructor() { std::cout << "Base Created
"; }
    ~BaseWithoutVirtualDestructor() { std::cout << "Base Destroyed (Derived destructor NOT called!)
"; }
};

class DerivedResource : public BaseWithoutVirtualDestructor {
private:
    int *large_buffer;
public:
    DerivedResource() {
        large_buffer = new int[1000];
        std::cout << "Derived Resource Allocated
";
    }
    ~DerivedResource() {
        delete[] large_buffer;
        std::cout << "Derived Resource Successfully Freed
";
    }
};

class SafeBase {
public:
    virtual ~SafeBase() { std::cout << "SafeBase Destructor
"; }
};

class SafeDerived : public SafeBase {
private:
    int *safe_buffer;
public:
    SafeDerived() : safe_buffer(new int[500]) { std::cout << "SafeDerived Allocated
"; }
    ~SafeDerived() override {
        delete[] safe_buffer;
        std::cout << "SafeDerived Buffer Freed
";
    }
};

int main() {
    std::cout << "--- Testing Safe Virtual Destructor ---
";
    SafeBase *safe_ptr = new SafeDerived();
    delete safe_ptr; // Correctly calls SafeDerived destructor first, then SafeBase destructor
    return 0;
}

9. Code Explanation
In Example 7.1:
- `Shape` defines an abstract interface. The `std::vector<std::unique_ptr<Shape>>` holds heterogeneous polymorphic objects uniformly.
- When `shape->render()` executes, CPU inspects the object's `vptr` and jumps to `Circle::render` or `Rectangle::render` automatically.
In Example 8.1:
- Deleting a derived instance via a `Base*` without a virtual destructor causes undefined behavior where only the base destructor runs, leaking `DerivedResource::large_buffer`. Declaring `virtual ~SafeBase()` guarantees complete polymorphic destruction.

10. Practical Use Cases
- Game engine rendering pipelines (`GameObject -> Enemy, Player, Obstacle`).
- Cross-platform database driver interfaces (`DBConnection -> PostgresConnection, MySQLConnection`).
- GUI event handling systems and widget hierarchies.

11. Common Mistakes
1. Forgetting `virtual` on base class destructor when working with polymorphism (causes severe memory leaks).
2. Forgetting `override` keyword, accidentally defining a new method instead of overriding due to slight signature mismatch.
3. Object Slicing: Assigning a derived object to a base object by value (`Base b = derived_obj;`), stripping away derived member attributes and dynamic dispatch.
4. Calling virtual functions inside constructors or destructors (dynamic dispatch does not resolve to derived class because derived part is uninitialized or already destroyed).

12. Edge Cases
- Multiple inheritance name collisions when two base classes contain methods with identical names.
- Downcasting with `dynamic_cast`: Returns `nullptr` if pointer cast fails, throws `std::bad_cast` if reference cast fails.

13. Best Practices
- Always mark base class destructors as `virtual` (or `protected non-virtual` if base is not intended to be deleted polymorphically).
- Always use the `override` specifier on derived overridden methods to catch signature typos at compile time.
- Prefer composition over inheritance when polymorphism is not explicitly required.

14. Performance Considerations
- Virtual function calls introduce an indirect pointer dereference through the `vtable`, which prevents inline expansion and may incur slight CPU branch prediction penalties.

15. Comparison with Related Concepts
- Dynamic Polymorphism (virtual functions) vs Static Polymorphism (Templates/CRTP): Dynamic resolves at runtime with runtime memory/vtable overhead; Static resolves at compile time with zero runtime cost and full inlining.

16. Debugging Tips
- Inspect object size: Classes with virtual functions are typically 8 bytes larger due to the `vptr`.
- Use GDB `set print object on` to display the actual runtime derived type of polymorphic base pointers.

17. Interview Questions and Concept Checks
1. Why is a virtual destructor mandatory in a polymorphic base class?
   - To ensure that when an object of a derived class is deleted through a base class pointer, the derived class's destructor is executed first, releasing all derived resources.
2. What is Object Slicing in C++?
   - When a derived class object is assigned to a base class object by value, the derived-specific members are sliced away, leaving only the base portion.
3. What is the difference between a Virtual Function and a Pure Virtual Function?
   - A virtual function has a default base implementation; a pure virtual function has no implementation (`= 0`) in the base class, making the class abstract.

18. Summary
Inheritance and dynamic polymorphism enable modular, extensible software architecture in C++. Mastery of virtual functions, vtables, abstract contracts, and virtual destructors ensures robust object lifecycle management and clean object-oriented designs.
